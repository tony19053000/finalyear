Get started

Set up hive yourself

One computer runs the controller (coordinator and web dashboard). Every laptop that shares runs the agent. You send a program; hive decides where it runs.

Nothing runs on a laptop unless its owner allows it.

1Set up the controllerUbuntu 24.04, then create a fabric 2Add laptopsWindows or Ubuntu, then join 3Choose what to shareThe owner decides 4Run a programDashboard or terminal
Version. This guide matches version 0.17.5. File names below use 0.17.5; if you downloaded another version, put that number in its place.

What you need

  • Controller: a laptop or PC with Ubuntu 24.04 (64-bit). It should stay on while the fabric is used.
  • Agents: Windows 10 (22H2) or 11 (64-bit), or Ubuntu 22.04 / 24.04 (64-bit). Docker and an NVIDIA GPU are optional: without them a laptop still shares its processor.
  • All laptops on the same network (home or team Wi-Fi, or Ethernet). hive does not work across the internet.

Words used here

Fabric
Your group of laptops: one controller and its agents.
Node
One laptop in the fabric, as the dashboard shows it.
Join code
A one-time code (mf1-...) that lets one laptop join. The fabric admin makes it.
Job
One program you send to the fabric, with its files.
Console
The small page each laptop serves to itself (from its app menu entry) for joining and for the owner settings. Only that laptop can open it.
Dashboard
The controller's web page: nodes, jobs, invites, users.

Install

Install on a Windows laptop

You need: a Windows 10 (version 22H2) or Windows 11 laptop with a 64-bit Intel or AMD processor, an administrator's password (yours, if you are an administrator), and a join code from whoever runs the fabric's controller. You do not need Python, a terminal or WSL.

  1. Download hive-Setup-0.17.5.exe (from the team's release page or the person running the fabric). Download page
  2. Run it. Windows may say "Windows protected your PC": the installer is not signed yet. Click More info, check that the app name is hive-Setup-..., then Run anyway. Windows then asks whether the app may make changes: click Yes (or type an administrator's password).
  3. Follow the pages. Accept the licence and keep the suggested folder (C:\Program Files\hive). The page What this computer will share explains what happens: it runs in the background, starts with Windows, keeps running when you sign out, and runs nobody's jobs until you allow it.
  4. Wait for "hive setup finished". The installer starts the agent and checks that it really runs (up to a minute). The last page says either "hive is installed and running" or exactly what is wrong and what to do. Leave Open hive ticked and click Finish.
  5. Join. A browser page opens. It is served by the laptop itself and cannot be reached from the network. Paste the mf1-... code (or scan the QR code on the dashboard with the webcam), then choose what the laptop shares and look at the checks. The rest is the same as Join a laptop.

To open the page again later: Start menu → hive.

Docker and the GPU

  • Docker Desktop lets jobs run in containers. Giving the agent Docker access is the same as giving it full administrator rights on the laptop, so it is off until you turn it on: Start menu → hive - give Docker access (Windows asks for an administrator's OK; the agent restarts by itself). Docker Desktop only runs while someone is signed in; turn on Start Docker Desktop when you sign in in its settings.
  • NVIDIA GPU: install the NVIDIA driver (nvidia.com/drivers or Windows Update) and restart. The page's GPU check says whether the agent sees it. Sharing the GPU is off until you turn it on in the owner settings.

Another user of this laptop

Only the person who installed it (and administrators) may open its page. Anyone else who opens hive from the Start menu is asked whether to request access; an administrator approves it in the Windows prompt. An administrator can also do it directly, in an elevated PowerShell (remove takes it back):

PS> hive-agent console-access add --user <their Windows user name>

The network says "Public"

On a network Windows calls Public (cafés, hotels) other laptops cannot fetch files from this one; jobs still run. On your home or team network, set it to Private: Settings → Network & internet → (your Wi-Fi or Ethernet) → Network profile type → Private. The agent never opens a port on Public networks.

A laptop that already ran the agent for development

If this laptop ran the agent from a source checkout (the HiveAgent scheduled task), the installer stops and disables that task and moves its identity to the new service, so the laptop stays the same node in the dashboard. If it finds more than one identity, it installs but does not start, and the last page names the folders and the command to choose one.

Install on Ubuntu

There are two packages. Install the one(s) this computer needs. One computer may have both: the controller laptop can share its own CPU too.

PackageWhat it isUbuntu
hive-agent_0.17.5_amd64.debshares this computer's CPU/GPU with a fabric22.04 or 24.04
hive-controller_0.17.5_amd64.debruns the fabric itself (one per fabric)24.04 only

You do not need Python, Docker, PostgreSQL or a source checkout: each package brings everything it needs. You need an administrator account (one that can use sudo). Get the files from the release page (or from whoever runs the fabric).

Check a download (optional): in the download folder this must say OK:

$ sha256sum -c SHA256SUMS --ignore-missing

The agent (every laptop that shares)

$ sudo apt install ./hive-agent_0.17.5_amd64.deb

apt needs the ./ (it means "this file", not a package from the internet). The last lines say whether the service hive-agent is running and that the laptop has not joined a fabric yet. It now runs in the background: it starts with the computer, keeps running when you log out, and runs nobody's jobs until you allow it.

Next: open the agent's page from the app menu (or run hive-console-open) and join. The person who ran sudo apt install may open that page. To let another user open it (they log out and in once):

$ sudo usermod -aG hive-admin <user>

Docker (optional): Docker access equals administrator rights, so it is off until you choose it: app menu → hive → Give Docker access. See What your laptop shares.

The controller (one per fabric)

Ubuntu 24.04 only (22.04 is refused: apt says Depends: libc6 (>= 2.36)).

$ sudo apt install ./hive-controller_0.17.5_amd64.deb

It writes its settings to /etc/hive/controller.toml (listening on this computer's network address), starts its own database and the controller, and ends by telling you to run sudo hive-controller setup url and open the link in a browser on this computer. Continue with Create a fabric.

On a computer with only the controller package, the compute command is /opt/hive/controller/current/bin/compute (the agent package puts compute on the PATH).

Is it running?

systemctl status hive-agent          # or hive-controller
hive-agent doctor                    # version, joined or not, last upgrade, Docker/GPU/disk checks
sudo hive-controller doctor          # the controller's own checks
journalctl -u hive-agent -n 50       # the agent's recent log

Other Linux distributions

Only Ubuntu 22.04/24.04 .deb packages are built and tested. On another distribution you can unpack the bundle archive (hive-0.17.5-linux-x86_64.tar.xz) and run it by hand as described in the operations runbook (docs/OPERATIONS.md in the source); that path is not tested.

Set up

Create a fabric

You need the controller package installed on an Ubuntu 24.04 computer (above). This is done once per fabric.

1. Open the setup link, on the controller computer

$ sudo hive-controller setup url

It prints a link like http://127.0.0.1:47110/setup#token=.... Open it in a browser on that same computer. The link works once, and only from that computer (the admin password must not cross the network before the fabric's encryption exists).

Working from another computer? Forward the port first, then open the same link there:

$ ssh -L 47110:127.0.0.1:47110 <user>@<controller>

2. Create the first admin

The page shows the checks first (database, disk, the network address laptops will use). Then, under The first admin: an Admin user name (3 characters or more) and a Password (12 characters or more, not too simple), Repeat the password, and Create the fabric.

If the page warns that laptops would join at 127.0.0.1: no network address was found when the package was installed. Put this computer's LAN address in the three *bind lines of /etc/hive/controller.toml, run sudo systemctl restart hive-controller, and open a new setup link.

3. Your fabric is ready

  • Join code, shown only now: the first mf1-... code (and its QR code) for your first laptop. It works once, for a limited time.
  • Dashboard: https://<this computer's address>:47110/
  • CA fingerprint: the fabric's own certificate. Browsers do not know it yet, so they warn the first time. hive-controller ca trust-helper prints how to make your browser trust it (and the fingerprint to compare).

The controller restarts itself with encryption on; the setup link never works again.

4. Sign in and add laptops

Open the dashboard and sign in with the admin name and password. To add a laptop: Settings > Invites > New invite gives a new join code (text and QR). On the laptop, follow Join a laptop. More users: Settings > Users (an admin can add them).

From a terminal on any computer (the compute command):

compute login --controller https://<controller address>:47110 --fingerprint <CA fingerprint> -u <admin>
compute fabric invite          # a new join code
compute nodes                  # the laptops that joined; CONN "yes" = connected now

Keep your fabric safe

  • The controller's database is backed up automatically before every upgrade. Take your own copy any time with sudo hive-controller db backup (keep the file private: it is the whole fabric).
  • apt remove hive-controller keeps the fabric; only apt purge deletes it (Uninstall).

Join a laptop

Install first (Windows or Ubuntu), and get a join code from whoever runs the fabric's controller.

  1. Get a join code. The fabric admin opens the dashboard, goes to Settings > Invites > New invite, and either reads you the code (it starts with mf1-) or leaves the QR code on screen. A code works once, and only for a limited time (15 minutes by default).
  2. Open hive on the laptop. Find hive in the app menu (Windows: the Start menu). A browser page opens. It is served by the laptop itself and cannot be reached from the network.
  3. Join. Click Start, paste the code (or click Scan QR code with the camera and hold the dashboard's QR code up to the webcam), then Join. If something is wrong the page says what and what to do, for example "This code has expired - ask for a new code" (all messages: Troubleshooting).
  4. Choose what the laptop shares. The safe choices are already set: no jobs run, the GPU is not shared, a job may use at most half the processor. Read each line, change what you want, optionally give the laptop a name, and click Save and continue. See What your laptop shares.
  5. Look at the checks. They show what the laptop can offer (Docker, NVIDIA GPU, CUDA, disk space, firewall). Nothing here blocks joining; a missing item only means fewer kinds of jobs run here.
  6. Done. The laptop appears in the fabric's dashboard within a few seconds, under the name you gave it. The page's Home says Connected to the fabric.
A join code works once. If two laptops use the same code at the same moment, only one joins; the other gets "This code was already used" and needs a new code. The same happens if the join reached the controller but the answer was lost on the way back: ask the admin for a new code.

To open the page again later, use the same app-menu entry. To leave the fabric: Leave in the page's menu.

What your laptop shares

You, the laptop's owner, decide what other people's work may do on it, not the fabric's admin. Open hive from the app menu and go to Settings. Changes apply within seconds, no restart needed.

Run jobs off means: your laptop is part of the fabric and says what it could run, but nobody's job is downloaded, prepared or run on it. The agent only looks: it checks whether Docker and a graphics card are there, without starting anything in Docker and without changing system settings. The first time you turn Run jobs on, it finishes setting up (this can start one short check in Docker and set up its CPU limit) and reconnects to the fabric by itself within seconds. After that, turning Run jobs off and on takes effect at once.

Docker. Jobs run safest in Docker containers. Docker access is the same as full admin rights on the laptop, so the agent never takes it by itself: right-click hive in the app menu and choose Give Docker access (asks for your password), or on Ubuntu run:

$ sudo usermod -aG docker hive && sudo systemctl restart hive-agent

Use

Run a workload

A job is a folder (your "project") with your program and a small file, compute.yaml, that says how to run it. You send the folder; hive picks where it runs (your laptop, another laptop, or several at once) and brings the results back.

Before you start: at least one laptop has joined and its owner turned on Run jobs from the fabric on this laptop. Without Docker on that laptop, its owner must also allow jobs without a container.

1. A first job

Make a folder hello with two files. compute.yaml says: run python hello.py, and bring back the results/ folder.

hello/compute.yaml

name: hello
entrypoint: [python, hello.py]
outputs: [results/]

hello/hello.py

import os
import platform

os.makedirs("results", exist_ok=True)
with open("results/where.txt", "w") as f:
    f.write(f"hello from {platform.node()}\n")
print("hello from the fabric")

2. Send it from the dashboard

Open the dashboard, go to Jobs → Submit job, choose the Project folder hello (or a .zip of it) and click Upload and submit. The job page opens: its state (queued → running → succeeded), where it ran, and its log. When it has finished, download the outputs from the job page.

3. Or send it from a terminal

Once per computer, log in (the controller's address and fingerprint are on the dashboard):

$ compute login --controller https://<controller address>:47110 --fingerprint <CA fingerprint> -u <your name>

Then:

$ compute run ./hello -f

compute run prints the job's id (job_...), uploads only files the controller does not have yet, and with -f follows the log until the job ends. Then fetch the results:

compute get <JOB_ID>            # unpacks into ./outputs/<JOB_ID>/
compute jobs                    # your recent jobs
compute explain <JOB_ID>        # why it was placed where it was

--node <NODE_ID> sends the job to one particular laptop; --local runs it on your own laptop.

4. Split one big job across laptops

When a job is a list of independent pieces (files to convert, numbers to try, rows to process) hive can split it: each laptop runs your program on some of the pieces, and the results are joined in order. Add a split: section and two placeholders: {items_file} (a JSON list of this piece's items) and {out} (the folder to write this piece's result to).

squares/compute.yaml

name: squares
entrypoint: [python, square.py, "{items_file}", "{out}"]
split:
  over: {range: {stop: 20}}
  chunk: {items: 5}
  combine: concat

squares/square.py

import json
import sys
from pathlib import Path

items = json.loads(Path(sys.argv[1]).read_text())
out = Path(sys.argv[2])
out.mkdir(parents=True, exist_ok=True)
lines = "".join(f"{n} {n * n}\n" for n in items)
(out / "squares.txt").write_text(lines)
$ compute run ./squares -f

The numbers 0–19 are cut into 4 pieces of 5; laptops pull pieces until all are done; combine: concat glues the four squares.txt files together in order, so compute get <JOB_ID> gives one squares.txt with 20 lines. compute watch <JOB_ID> shows which laptop did which piece. If splitting would be slower than one laptop (small jobs, a slow network), hive runs it on one laptop and compute explain says why.

Other ways to name the pieces: over: {glob: "images/*.jpg"} (files of the project), over: {lines: data.csv, header: true} (rows of a file). Other ways to join them: merge-csv, merge-json, or your own script.

More in compute.yaml

env:
  requirements: requirements.txt   # Python packages, installed once per laptop and reused
resources:
  gpu: required                    # required | preferred | none
  ram_gb: 8
limits:
  timeout: 30m

A job that needs a GPU runs only on a laptop whose owner shares the GPU.

Use hive from your own Python

Your program can send jobs and use their results the same way you do in a terminal: through the compute command, whose --json output is meant for programs. Every compute command works this way, and exit codes are stable (0 = success; see compute --help).

Not here yet: the Python library for using another laptop's GPU from inside your running program (remote_gpu(), Remote GPU / Combined GPU) comes with a later version.
CommandGives
compute run <folder>the job id on the first line (add -f to wait for the end; the exit code is then the job's outcome)
compute jobs <job id> --jsonthe job: state, where it ran, its attempts and outputs
compute jobs --jsonyour recent jobs
compute get <job id> --dest <folder>the job's output files, checked and unpacked
compute logs <job id>its log (stdout and stderr)
compute cancel <job id>stops it
compute nodes --jsonthe laptops and what they offer
Example: send a job, wait, read its result (sum_on_fabric.py)

Copy this into sum_on_fabric.py and run python sum_on_fabric.py. It makes a tiny project, sends it, waits for it to finish, downloads the output and prints total = 5050.

"""Send a job to hive from Python and use its result."""

import json
import subprocess
import sys
import tempfile
from pathlib import Path


def compute(*args: str) -> str:
    """Run one `compute` command; stop with its message if it fails."""
    done = subprocess.run(["compute", *args], capture_output=True, text=True)
    if done.returncode != 0:
        sys.exit(f"compute {args[0]} failed ({done.returncode}): {done.stderr.strip()}")
    return done.stdout


# 1. a project: the program and its compute.yaml
project = Path(tempfile.mkdtemp()) / "sum"
project.mkdir()
(project / "compute.yaml").write_text(
    "name: sum\nentrypoint: [python, job.py]\noutputs: [result.json]\n"
)
(project / "job.py").write_text(
    "import json\n"
    "json.dump({'total': sum(range(1, 101))}, open('result.json', 'w'))\n"
)

# 2. send it; -f waits until the job has ended (the first line is its id)
job_id = compute("run", str(project), "-f").splitlines()[0].strip()

# 3. what happened, as JSON
job = json.loads(compute("jobs", job_id, "--json"))
print("job", job_id, "is", job["state"])

# 4. its output files
compute("get", job_id, "--dest", str(project / "out"))
result = json.loads((project / "out" / "result.json").read_text())
print("total =", result["total"])

The controller's REST API (https://<controller>:47110/v1/..., OpenAPI at /v1/openapi.json) is what compute itself uses; scripting it directly works too, with a token from compute login.

Maintain

Upgrade & uninstall

Which versions work together

A controller accepts agents of its own version line and the one before (controller 0.17.x accepts agents 0.17.x and 0.16.x). An older agent, or one newer than the controller, is refused with version_unsupported and stops. So: upgrade the controller first, then the laptops.

Upgrade

Install the new version over the old one, the same way you installed it. Settings, the laptop's identity (it stays the same node), the owner settings and the controller's database are kept.

  • Ubuntu: sudo apt install ./hive-agent_<new>_amd64.deb (or hive-controller_...).
  • Windows: run the new hive-Setup-<new>.exe.

The running version is kept aside, the controller backs up its database, and the new version must be healthy within about a minute. Healthy: the old copy is removed.

If the new version does not start

hive switches back to the version that ran before, by itself, and says so (UPGRADE FAILED / ROLLED BACK; on Windows: "The new version did not start; the previous version runs again."). For the controller, the database is first restored from the backup taken before the upgrade. The laptop keeps working. Fix the cause the message names, then install again (Ubuntu: sudo apt install --reinstall ./<new>.deb).

If an upgrade was cut off (power loss, a killed installer): on Ubuntu, install the new package again, sudo dpkg -i ./hive-agent_<new>_amd64.deb (then sudo apt --fix-broken install if apt asks), or sudo dpkg --configure -a if it was cut off after the switch. On Windows, run the installer again.

Uninstall

By default an uninstall keeps your data (the laptop's identity, so it comes back as the same node; the controller's fabric and database). Remove everything only if you mean it.

Keep the data (default)Remove everything
Ubuntu agentsudo apt remove hive-agentsudo apt purge hive-agent
Ubuntu controllersudo apt remove hive-controllersudo apt purge hive-controller (deletes the fabric!)
WindowsSettings → Apps → hive Agent → Uninstall → also remove all data? Nothe same, answer Yes

Check that nothing is left with lab/verify_uninstall.py (from a source checkout or the release page); it ends with CLEAN: nothing left behind or lists every leftover:

sudo python3 lab/verify_uninstall.py --os linux                  # after apt remove
sudo python3 lab/verify_uninstall.py --os linux --data-removed   # after apt purge
python lab\verify_uninstall.py --os windows                      # Windows, administrator prompt

Troubleshooting

Each entry starts with what you see. Where hive shows a code (on the laptop's page, in hive-agent doctor, on the installer's last page, or in a command's output), search this page for it.

First step for almost anything: hive-agent doctor on the laptop (Ubuntu: any terminal; Windows: an administrator PowerShell) and, on the controller, sudo hive-controller doctor. They change nothing and say what is wrong.

Installing

"Windows protected your PC" (SmartScreen)
The installer is not signed yet. Click More info, check the name hive-Setup-..., click Run anyway.
apt refuses the controller: Depends: libc6 (>= 2.36)
The controller needs Ubuntu 24.04. The agent package works on 22.04 too.
Installer's last page: "installed but NOT running yet" needs_attention
It stopped on purpose: usually it found two older identities on this computer (two users ran it before) and will not guess which one is this laptop. The page names both folders and the command to pick one.
Installer's last page: "installed but NOT running" failed
The service did not start and could not be brought back. Restart the computer and run the installer again; if it repeats, send C:\ProgramData\hive\logs\setup-result.json to the team.

Upgrading

"UPGRADE FAILED ... ROLLED BACK" rolled_back
The new version was not healthy, so it went back to the version that ran before. Nothing is lost. Fix what the message names, then install again (Ubuntu: sudo apt install --reinstall ./<file>.deb).
"an upgrade ... was interrupted" interrupted
Finish the upgrade the way the message says: Ubuntu: sudo dpkg -i ./<new>.deb (then sudo apt --fix-broken install if apt asks), or sudo dpkg --configure -a when it was cut off after the switch; Windows: run the installer again.
Controller: "the database was restored from the backup taken before it" upgrade_rolled_back
The new controller did not start after updating its database, so the database was put back and the previous version started again on it. Laptops reconnect by themselves.
Controller: db status says ROLLBACK FAILED rollback_failed
sudo hive-controller db status names the backup; restore it with sudo hive-controller db restore <backup> --yes, then sudo systemctl start hive-controller.

Joining a fabric

"This code has expired." / "This code was already used to join a laptop." expired used
A join code works once and only for a while (15 minutes by default). Ask the admin for a new one (dashboard: Settings > Invites > New invite).
"The fabric admin cancelled this code." / "The controller does not know this code." revoked_code bad_code
Ask for a new code. bad_code also means a code that was cut short when copying: codes start with mf1-.
"This laptop was removed from the fabric by its admin." node_revoked
Leave the fabric on this laptop (Leave in the page's menu), then join again with a new code.
"This laptop has already joined a fabric." already_joined
To join a different fabric, leave the current one first.
"Cannot reach the controller ..." unreachable
The controller computer is off, on another network, or its address changed. Check it is on and on the same Wi-Fi; pick it from the list of controllers the page found. A firewall on the controller must allow TCP 47100, 47101 and 47110 (the controller package opens them itself when ufw is on).
"Something answered ..., but it is not a hive controller's join port." not_a_controller
The address is wrong. Pick the controller from the list, or ask for a new code.
"The controller ... is not the fabric this code belongs to" ca_mismatch
You picked a different controller than the one that made the code. Nothing secret was sent. Pick the right one.
"The controller is busy ..." busy
Wait a minute and try again.
"Joined, but this laptop could not save its certificate." storage
Usually a full disk. Free some space, then join again with a new code.
"The controller refused to let this laptop join." refused
Ask the fabric admin to look at the controller's log (journalctl -u hive-controller).

The agent stopped on this laptop

"version_unsupported: agent ... is too old for controller ..." version_unsupported
Too old: install the newer version on this laptop. "newer than controller": the fabric admin upgrades the controller first. Then press Restart on the page.
"this node was revoked" revoked
The admin removed this laptop. To come back: Leave the fabric, then join with a new code.
"another hive-agent with node_id ... connected" conflict
Two agents use the same identity, typically an old developer copy (hive-agent run in a terminal, or the old Windows scheduled task) next to the installed service. Stop the other one, then press Restart.
A setting is named as wrong config config_reload
It refuses a configuration value it cannot use and names it (and the file). Fix it, then press Restart.
"leaving failed: ..." identity
See the Logs page; run hive-agent doctor.
"the fabric connection ended" or another error ended error
Press Restart. If it stops again, the Logs page (or journalctl -u hive-agent) has the reason.

Docker, GPU and network

"docker: no access" / jobs do not run in containers
Ubuntu: app menu → hive → Give Docker access. Windows: Start menu → hive - give Docker access. Docker Desktop on Windows only runs while someone is signed in.
The GPU check says the driver does not answer
Install or repair the NVIDIA driver and restart the laptop. Sharing the GPU stays off until you turn it on in the owner settings.
Windows: "the network is Public"
On your own network: Settings → Network & internet → (your network) → Network profile type → Private.
Joined, but the laptop never connects: the log repeats agent.discovery.none / controller_not_found

The laptop finds its controller by mDNS (multicast on UDP port 5353), which some Wi-Fi adapters, routers or firewalls drop. Check from the laptop that the session port answers: Test-NetConnection <controller-ip> -Port 47100 (Windows) or nc -vz <controller-ip> 47100 (Ubuntu).

Workaround: tell the laptop where the controller is. In the configuration file (Windows: C:\ProgramData\hive\config\config.toml, edited in an administrator editor; Ubuntu: /etc/hive/config.toml with sudo; create it if it does not exist) put this in the [agent] section, then press Restart:

[agent]
controller_address = "192.168.31.13:47100"   # the controller's LAN IP : session port (default 47100)

Use port 47100 (the session port), not 47101 (the join port). With an address set the laptop no longer uses mDNS, so give the controller a fixed address (a DHCP reservation in the router).

The dashboard's Live CPU looks wrong while a job runs
Run hive-agent doctor cpu --seconds 30 on the laptop while the job runs (Windows: an administrator PowerShell). It prints the CPU cap a job gets on this laptop, then one line per second. It changes nothing.
"needs an elevated prompt" / "only administrators may change" (Windows)
hive-agent commands that change the service need an administrator PowerShell (right-click → Run as administrator). For everyday things use the page from the Start menu.
"cannot listen on 127.0.0.1:47130 for the local console ..."
Another program (often a second agent) uses the console's port. Stop the other agent.
A job fails with "... refused this laptop's certificate - wrong fabric or expired certificate?"
Run hive-agent identity show: if the fabric is not the one this controller runs, or the certificate has expired, Leave the fabric and join again with a new code. If it looks right, retry the job and check journalctl -u hive-controller.

The controller's database

sudo hive-controller doctor and journalctl -u hive-controller -n 80 show these codes.

CodeWhat it meansWhat to do
port_in_useanother program uses the database port (47150)stop it, or set [controller.db] port in /etc/hive/controller.toml
binaries_missing, binaries_unusablethe bundled PostgreSQL is missing or cannot run (wrong Ubuntu)reinstall the package; the controller needs Ubuntu 24.04
version_mismatchthe database was made by another PostgreSQL major versionrestore a backup made by this version, or ask the team
data_dir_invalid, path_invalid/var/lib/hive/db is not a database folder, or a path PostgreSQL cannot usedo not edit that folder by hand; restore from a backup
lockedanother controller already uses this databasestop the other one
initdb_failed, start_failed, start_timeoutthe database could not be created or did not start (in time)journalctl -u hive-controller -n 80 names the log file; often a full disk
stop_failed, orphan_stop_failedan old database process would not stoprestart the computer
not_runninga db command needs the database, which is not runningsudo systemctl start hive-controller
in_usedb restore while the controller runssudo systemctl stop hive-controller first
dump_failed, restore_faileda backup or a restore did not work (nothing was changed)check the free disk space, then try again

Still stuck? Collect hive-agent doctor (and sudo hive-controller doctor), the last 80 log lines, and the installer's output, and send them to the team. More answers on the support page.
