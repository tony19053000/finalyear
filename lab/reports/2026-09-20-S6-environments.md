**Laptop 1 (Linux) only**; the Windows laptops (Docker Desktop, WSL2 backend) are a 🧑 step.

## Expected vs actual

Expected: `docker: usable`, `gpu-in-container: yes` (confirmed by hand earlier the same day with
the same CUDA base image), container start well under 1 s, warm venv install well under 1 s.
Actual: matched — docker usable, GPU visible in the container (5/5), container start 0.22 s,
warm venv create+install 0.10 s, venv process start 0.11 s. Not obtained: the PyTorch-CUDA
container case (disk), so `torch-cuda-in-container` is TBD on this laptop.

## Conclusion
On Laptop 1 (Linux, Docker Engine + NVIDIA Container Toolkit) Docker is usable with the full
ADR-0004 sandbox shape (no flag refused) and a container sees the GPU, so the ADR-0004
recommendation for this laptop is `docker`. A warm container start costs about 0.22 s and a
warm-cache `uv` environment about 0.10 s to build plus 0.11 s to start the process — both far
inside the 3 s V0.5 target; a cold environment costs 3.6 s (uv, ~100 MB download) or 9.7 s
(small image pull). Q4 (Docker Desktop GPU on Windows) is **not** answered by this file: it needs
the 🧑 Windows runs. The PyTorch-CUDA container number is still missing on this laptop.
