# V0.15 lab — the ML planner on real laptops (roadmap 0.15.11, criteria 1–4, D379)

This checklist judges V0.15's success criteria on the **4 lab laptops**. The same chain runs on one machine in
`tests/cluster/test_v015_ml_e2e.py` (campaign → dataset → train → plan with ML → evaluate → retrain); there the
numbers are noise and only prove the code path. **The criteria are judged on this lab's data only (D344).**
Words used: **L1** = the controller laptop (**Linux**, also runs an agent), **L2–L4** = the Windows laptops (agents
native or in WSL2, as set up in V0.4–V0.14). `<L1>`…`<L4>` = each laptop's node id from `compute nodes`.

**Shell.** Every command runs on **L1** in a **Linux bash shell** with the usual CLI setup
(`MESHFORGE_CLI__CONTROLLER_URL`, `compute login` as the **admin** — training, evaluation and the dataset are
admin commands). Not PowerShell / cmd. Dashboard steps use a browser on any laptop, signed in as the admin.

| Criterion (brief §5, roadmap V0.15) | Part | Pass when |
|---|---|---|
| **C1** on held-out families, `cost_model:ml` mean regret **lower** than calibrated analytical v2 | D | `ml_criterion_1: PASS` (paired bootstrap 95 % CI of the difference entirely below 0). `not_separable` / `too_few_groups` = **NOT MET**, `FAIL` = **FAIL** |
| **C2** on **every** benchmark family, ML mean regret ≤ calibrated + **5 percentage points** | D | `ml_criterion_2: PASS` (every family with ≥ 3 common groups passes) |
| **C3** retraining automated (scheduled + CLI) and reproducible: same dataset digest → byte-identical set version; a gate rejection recorded with its reason | C | C1–C4 below all as expected |
| **C4** decision latency p99 **< 100 ms with ML on**, 4 live laptops | E | `criterion 3: PASS` of the report on part E's campaign, whose decisions name a model set |
| **0.15.10** classifier vs cost regression (report only) | F | the section is printed (numbers, or `too_few_groups` with counts) |
| **0.15.TD1** node failure classifier (D380) | B, G | `node_failures` pasted: ≥ 50 → TD1 becomes a G7 task; < 50 → TD1 closed *deferred-by-evidence* |

Every step ends with **PASTE BACK:** — copy it into `lab/reports/<date>-V0.15-ml-planner.md` (from
`lab/reports/TEMPLATE.md`). Write **PASS / FAIL / NOT MET** next to each criterion with the line that decides it.
A step that could not be run is written down as such — never as a pass. Attach files (`.md` reports, the dataset
sidecar) to `lab/reports/raw/`.

**Evaluations run in the background (D378).** `compute planner eval` prints `evaluation report N started;
waiting up to S s` and polls until the report is `done` or `failed`. If it gives up (`did not finish within S s`,
exit 1) the evaluation **keeps running** on the controller: wait, then `compute planner reports` and fetch it
with the dashboard (Planner → the report). Never start a second evaluation while one runs (409
`eval_already_running`).

## A. Overnight unattended campaign (all Mode 1 + Mode 3 families, ≥ 2 000 runs)

- [ ] **A1 — create and start.** On L1 write `v015.yaml` (every CPU / memory family as Mode 1, every split
  family as Mode 3; GPU / ML families are out of V0.15's scope; 16 parameter points each; points outside a
  family's 5 s – 3 min window are dropped and counted, never silently):

  ```yaml
  version: 1
  name: lab-v015-ml
  seed: 1511
  families:
    - family: cpu.primes
      params: {limit: {min: 100000000, max: 250000000, int: true, steps: 16}}
    - family: cpu.zlib
      params: {size_mb: {min: 64, max: 184, int: true, steps: 16}, level: 6}
    - family: cpu.sort
      params: {n: {min: 5000000, max: 20000000, int: true, steps: 16}}
    - family: cpu.matmul
      params: {n: {min: 1024, max: 2944, int: true, steps: 16}}
    - family: cpu.integrate
      params: {points_m: {min: 40, max: 190, int: true, steps: 16}}
    - family: memory.groupby
      params: {rows_m: {min: 2, max: 17, int: true, steps: 16}}
    - family: split.image_classify
      params: {images: {min: 1000, max: 8500, int: true, steps: 16}}
    - family: split.csv_aggregate
      params: {rows: 20000, cols: 16, rounds: {min: 800, max: 2300, int: true, steps: 16}}
    - family: split.hash_files
      params: {files: 64, size_kb: 1024, rounds: {min: 96, max: 256, int: true, steps: 16}}
    - family: split.montecarlo_range
      params: {items: 3000, samples: {min: 100000, max: 1600000, int: true, steps: 16}}
  strategies: [local, mode1, mode3]
  nodes: all
  origin: <L1>
  repetitions: 4
  on_invalid: drop
  session_label: wifi
  budget: {max_runs: 2600, max_hours: 24}
  ```

  ```bash
  compute bench plan v015.yaml               # runs, groups, dropped points, estimated hours
  compute bench create v015.yaml             # prints camp_... = <CAMP_N>
  ```

  reference laptop, one run after another; with 4 laptops working in parallel it takes roughly a quarter to a
  third of that (6–8 h) - an overnight run. `max_hours: 24` is also the wall-clock stop (open runs are then
  `skipped`). If `plan` shows fewer than 2 000 runs (more points dropped on your build) raise `steps`; write down
  any change.

## D. Criteria 1 and 2 — evaluation on held-out families

Each evaluated family gets its own fold model trained **without** it (never registered), and its records are
re-planned with calibration + that model; the comparison is against calibrated analytical on the same groups.
Never use `--allow-leak` here (it stamps every verdict `leaked`).

- [ ] **D1 — all families at once.**

  ```bash
  compute planner eval --campaign <CAMP_N> --md lab-v015-eval.md --timeout 7200
  ```

  (Add `--campaign <CAMP_A>` / `<CAMP_E>` from 0.14.8 if 0.2 listed them.) Expected on stderr `evaluation report
  <R> started; waiting up to 7200 s`, then the report: `criterion 1/2/3` lines as in V0.14, then
  `ml_criterion_1: PASS|FAIL|not_separable|too_few_groups - …`, `ml_criterion_2: … - …` with one line per family
  (`  <family>: ML x % vs calibrated y % over n groups - PASS|FAIL|too_few_groups`), and `ML in the chosen plans:
  used rate …`. If the folds ran out of time, families show `eval_budget_exhausted` in the report's `folds`:
  raise `[controller.planner] ml_eval_timeout_s` (restart) and run D1 again.
  **C1** = the `ml_criterion_1` line; **C2** = the `ml_criterion_2` line (`too_few_groups` = NOT MET).
  **PASTE BACK:** every printed line; attach `lab-v015-eval.md`.
- [ ] **D2 — MAPE per term, fallback rates, fold models.**
