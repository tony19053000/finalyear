## C. Benchmark conditions (V0.9 G4, D217)

Run these after G4 is merged, with the fabric up (controller on **L1**, agents online). Replace `<NODE>` with
the node id `compute nodes` shows for the laptop named in the step.

- [ ] **C1 — netem on a real Linux agent (sudoers rule + one real shaped run).** The shaping node must be a
  Linux agent that is **not** the controller laptop (its traffic to the controller must leave through a real
  interface, not loopback) - an agent in **WSL2 Ubuntu on L2** is fine.
  1. On that node, follow `lab/netem/README.md` (sudoers rule + `[agent.conditions] netem = true`,
     `netem_interface = "<iface>"`), restart the agent, then check:

     ```bash
     sudo -n /usr/sbin/tc qdisc show dev <iface>      # must print a qdisc line, no password prompt
     ```
  2. On L1, write `netem.yaml`:

     ```yaml
     name: lab-netem
     seed: 1
     families: [{family: cpu.primes}]
     conditions: [none, "netem:delay=50ms"]
     strategies: [local]
     nodes: [<NODE>]
     origin: <NODE>
     repetitions: 3
     session_label: wifi
     budget: {max_runs: 10}
     ```

     ```bash
     compute bench plan netem.yaml          # 6 runs, no "does not offer netem" error
     compute bench create netem.yaml        # prints camp_...
     compute bench submit <camp_id> -n 6 --wait
     compute bench runs <camp_id>
     compute telemetry export --campaign <camp_id> -o netem.parquet
     uv run python -c "import pyarrow.parquet as pq; [print(r) for r in pq.read_table('netem.parquet').select(['repetition','failure_class','total_ms']).to_pylist()]"
     ```
  3. On the shaping node, after the runs: `sudo -n /usr/sbin/tc qdisc show dev <iface>` must show **no**
     `netem` line (reverted).

  Expected: 6 runs `done`, every `failure_class` `ok`; the agent log has `agent.conditions.applied` lines for
  the netem runs with `rtt_after_ms` about 50 ms above `rtt_before_ms`; no netem qdisc is left.
  **PASTE BACK:** the output of `compute bench runs`, the python one-liner's output, the
  `agent.conditions.applied` / `agent.conditions.finished` log lines of one netem run, and the final
  `tc qdisc show` line.

- [ ] **C2 — cpu_load on a native Windows agent.** On L1, write `cpuload.yaml` as above but with
  `conditions: [none, "cpu_load:2"]` and `nodes` / `origin` = **L2's native Windows agent** (not WSL);
  create, `submit -n 6 --wait`, `runs`. While a `cpu_load:2` run is running, on L2 in PowerShell:

  ```powershell
  Get-CimInstance Win32_Process -Filter "Name like 'python%'" | Where-Object CommandLine -like '*conditions.burn*' | Select-Object ProcessId, CommandLine
  Get-Process -Id <each ProcessId> | Select-Object Id, PriorityClass
  ```

  and the first command again after the campaign ended (it must list nothing).
  Expected: 6 runs `done`; during a `cpu_load:2` run two burner processes with `PriorityClass` **Idle**;
  none after. **PASTE BACK:** `compute bench runs` output, the PowerShell outputs, and the agent log line
  `agent.conditions.applied` of one cpu_load run (it shows `load_cores`).

- [ ] **C3 — gpu_load on a CUDA laptop (only if one has an NVIDIA GPU + torch).** As C2 with

  utilisation around 50 %. Expected: 6 runs `done`. **PASTE BACK:** `compute bench runs` output, one
