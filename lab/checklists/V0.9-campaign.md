# V0.9 lab — benchmark campaigns on real laptops

This checklist collects the V0.9 steps only real machines can show. G7 adds the campaign run itself
(roadmap 0.9.10); this file starts with the pre-campaign checks that earlier groups need.
Words used: **L1** = the controller laptop (Linux), **L2–L4** = the Windows laptops.

Every step ends with **PASTE BACK:** — what to copy into `lab/reports/<date>-V0.9-campaign.md`.

## C. Benchmark conditions (V0.9 G4, D217)

Run these after G4 is merged, with the fabric up (controller on **L1**, agents online). Replace `<NODE>` with
the node id `compute nodes` shows for the laptop named in the step.

- [ ] **C1 — netem on a real Linux agent (sudoers rule + one real shaped run).** The shaping node must be a
  Linux agent that is **not** the controller laptop (its traffic to the controller must leave through a real
  interface, not loopback) - an agent in **WSL2 Ubuntu on L2** is fine.
  1. On that node, follow `lab/netem/README.md` (sudoers rule + `[agent.conditions] netem = true`,
     `netem_interface = "<iface>"`), restart the agent, then check:

     ```bash
     sudo -n /usr/sbin/tc qdisc show dev <iface>      # must print a qdisc line, no password prompt
     ```
  2. On L1, write `netem.yaml`:

     ```yaml
     name: lab-netem
     seed: 1
     families: [{family: cpu.primes}]
     conditions: [none, "netem:delay=50ms"]
     strategies: [local]
     nodes: [<NODE>]
     origin: <NODE>
     repetitions: 3
     session_label: wifi
     budget: {max_runs: 10}
     ```

     ```bash
     compute bench plan netem.yaml          # 6 runs, no "does not offer netem" error
     compute bench create netem.yaml        # prints camp_...
     compute bench submit <camp_id> -n 6 --wait
     compute bench runs <camp_id>
     compute telemetry export --campaign <camp_id> -o netem.parquet
     uv run python -c "import pyarrow.parquet as pq; [print(r) for r in pq.read_table('netem.parquet').select(['repetition','failure_class','total_ms']).to_pylist()]"
     ```
  3. On the shaping node, after the runs: `sudo -n /usr/sbin/tc qdisc show dev <iface>` must show **no**
     `netem` line (reverted).

  Expected: 6 runs `done`, every `failure_class` `ok`; the agent log has `agent.conditions.applied` lines for
  the netem runs with `rtt_after_ms` about 50 ms above `rtt_before_ms`; no netem qdisc is left.
  **PASTE BACK:** the output of `compute bench runs`, the python one-liner's output, the
  `agent.conditions.applied` / `agent.conditions.finished` log lines of one netem run, and the final
  `tc qdisc show` line.
  4. **Crash recovery (D244).** Start one more `netem:delay=50ms` run; while it is running (`tc qdisc show
     dev <iface>` shows the `netem` line), `kill -9` the agent process. Restart the agent the normal way.
     **PASTE BACK:** `sudo -n /usr/sbin/tc qdisc show dev <iface>` after the restart (must show the default
     qdisc, no `netem`) and any `agent.conditions.*` log lines from the restart (a `sweep_*failed` line means it did NOT recover).

## G5 lane B - unattended runner + owner guard (0.9.7, D219/D246)

- [ ] **R1 - owner pause on a real laptop mid-campaign.** On L1 (controller + agent) and L2 (agent),
  create a campaign of `cpu.primes` + `cpu.zlib`, `strategies: [local, mode1]`, origin L1, 5 repetitions
  (20 runs), then:

  ```
  compute bench create r1.yaml          # prints camp_...
  compute bench start <camp_id> --per-node 1 --cooldown 2
  compute bench status <camp_id>         # repeat; done % grows
  ```

  When `status` shows about 6 runs done, on **L2** run `meshforge-agent bench pause`, wait 60 s, run
  `compute bench runs <camp_id> --state submitted` on L1 twice 30 s apart, then on L2
  `meshforge-agent bench resume`. Let the campaign finish.
  Expected: within ~5 s of the pause L2's running benchmark (if any) stops (`agent.execution.owner_preempted`
  in L2's agent log, the load generators gone); no new benchmark job starts on L2 until the resume; the
  campaign ends `done` / `complete` with every run `done`; `status` shows `stopped by the owner guard` >= 0
  and an infrastructure failure rate that does not count them.
  **PASTE BACK:** the final `compute bench status <camp_id>` output, the two `runs --state submitted`
  outputs, and L2's `agent.execution.owner_preempted` / `agent.bench.guard` log lines.

- [ ] **R2 - owner activity on Windows (idle time).** On a native Windows agent with
  `[agent.bench] idle_threshold_s = 60`, start a campaign with runs on that laptop, then **use the laptop**
  (move the mouse, type) for a minute, then leave it alone for 2 minutes.
  Expected: the agent logs `agent.bench.owner_activity owner_active=true reason=idle idle_source=windows`
  shortly after you start using it (a running benchmark is stopped, `owner_preempted`), and
  `owner_active=false` about `clear_after_s` (60 s) after you stop; benchmarks resume.
  **PASTE BACK:** those two log lines and `compute bench status <camp_id>` at the end.

- [ ] **R3 - Linux idle source.** On the native Linux laptop with a desktop session, run
  `loginctl show-session $(loginctl list-sessions --no-legend | awk 'NR==1{print $1}') -p Type -p IdleHint -p IdleSinceHintMonotonic`
  once while using it and once after 6 minutes idle. Then start the agent and read its first
  `agent.bench.owner_activity` / `agent.bench.idle_source_unknown` line.
  Expected: `Type=x11` or `wayland`, `IdleHint=yes` after the idle period; the agent reports
  `idle_source=logind` (or logs `idle_source_unknown` if the desktop never sets the hint - then say which
  desktop it is). **PASTE BACK:** both `loginctl` outputs and the agent log line.
