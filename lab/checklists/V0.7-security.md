# V0.7 security lab run (🧑 roadmap 0.7.12)

The real-machine half of V0.7: what CI cannot show - pairing four real laptops by code, revoking a
busy laptop and timing it, real packet captures on every plane, a Windows agent end to end, and
the Windows / Docker Desktop items the agent groups could not run. The G3 and G4 checklists
(`V0.7-G3-mtls-revocation.md`, `V0.7-G4-users-rotation.md`) are folded in here; run **this** file.

**Laptops (4):** **L1** controller (Linux, also runs `compute`), **L2** Linux agent, **L3** Windows
agent with Docker Desktop, **L4** a fourth agent (Linux or Windows). Same Wi-Fi/LAN. `<L1-IP>` = L1's
LAN address. Tools: `tcpdump` on L1 and L2 (`sudo apt install tcpdump tshark`), Wireshark on L3.
About 2 hours. Every **PASTE** line goes into the reply, in order, with the section letter.
The agents' and controller's own logs never show a code, token or secret value: if you see one
anywhere, **PASTE** where (file + line) - that is a defect.

## 0. Setup and clocks
1. Pull the same commit on every laptop (`git log -1 --oneline` - **PASTE** it once) and `uv sync`.
2. Clocks (peer tokens live 60 s, peers allow 30 s of skew): turn time sync on (Linux
   `timedatectl set-ntp true`; Windows "Set time automatically" / `w32tm /resync`), then print
   `date -u +%s` (PowerShell `[DateTimeOffset]::UtcNow.ToUnixTimeSeconds()`) on all four within a few
   seconds. **PASTE** the four numbers. Expected: all within 30 s of L1.
3. Firewalls: L1 opens TCP 47100, 47101, 47110; every agent laptop opens 47120 (OPERATIONS §0d).
4. L1: `meshforge-controller fabric create` (skip if a CA exists - then `meshforge-controller fabric show`),
   start the controller, `meshforge-controller user create alice` and `... user create admin --admin`
   (give each a password), `compute login --controller https://<L1-IP>:47110 --fingerprint <full
   fingerprint from fabric show>` as alice. **PASTE** `meshforge-controller fabric show` (fingerprint
   and expiry only).

## P. Pair four laptops by code (criterion 2, D135/D136)
1. On L1, one code per agent laptop: `meshforge-controller fabric invite` three times (codes for L2,
   L3, L4). Do not paste codes anywhere except the hidden prompt.
2. On L2 and L4: `meshforge-agent join` (paste the code at the prompt), then `meshforge-agent identity show`.
   **PASTE** each `identity show` (expected `enrolled: True`, the fabric id, `cert_not_after` ~30 days out).
3. **Windows (L3):** in PowerShell `meshforge-agent join`, paste the code, `meshforge-agent identity show`.
   **PASTE** it. Then `icacls "$env:LOCALAPPDATA\MeshForge\identity\node.key"` and the same for `node.crt`
   (adjust if `data_dir` is set). **PASTE**. Expected: only your account (and SYSTEM), no `Users`/`Everyone`.
4. Start every agent (`meshforge-agent serve`, or the systemd unit / scheduled task). On L1 `compute nodes`.
   **PASTE** the table. Expected: L2, L3, L4 `online`.

## C. Code reuse, expiry, revocation (criterion 2)
1. **Reuse:** on L4 `meshforge-agent join --force` with the code L4 already used. **PASTE** the error.
   Expected: refused `token_used` ("ask for a new code"); `compute nodes` unchanged.
2. **Expiry:** on L1 `meshforge-controller fabric invite --ttl 1m`, wait 70 s, then on L4
   `meshforge-agent join --force` with it. **PASTE**. Expected: refused `token_expired`.
3. **Revoked invite:** `meshforge-controller fabric invite`, then `meshforge-controller fabric invites`
   (**PASTE** the list - never shows a code), `meshforge-controller fabric invites --revoke <inv_id>`, then
   join with that code on L4. **PASTE**. Expected: refused `token_revoked`.
4. **Wrong controller:** on L4 edit one character in the CA-pin part of a fresh code (or use a code from
   another fabric). **PASTE**. Expected: refused `pin_mismatch` before anything secret is sent; on L1
   `meshforge-controller fabric invites` shows that invite still unused.

## R. Revoke a busy laptop and time it (criterion 1)
1. As alice on L1: `compute run <a project whose main.py sleeps 300 s> --node <L4 id>`; wait for `running`.
2. On L4 watch the agent's terminal / log. On L1: `date +%s.%N; compute node revoke <L4 id>` (as admin).
3. **PASTE**: the L1 timestamp, the time on L4 when the agent printed `node_revoked` (its log line has a
   timestamp), and `compute jobs <job id>`. Expected: under ~2 s (one heartbeat); the attempt `lost`
   (detail `node_revoked`) and the job retried on L2 or L3.
4. On L2: `meshforge-agent` log shows the revocation update; a fetch from L4's peer server is refused
   (`peer_cert_revoked` if one was attempted). Optional **PASTE**.
5. Bring L4 back: `meshforge-agent join --force` with a new code - **PASTE**, expected refused
   `node_revoked`; then `meshforge-agent identity reset --yes` and `meshforge-agent join` with another new
   code - **PASTE** `identity show`: a NEW node id.

## X. Packet captures on every plane (criterion 3)
Markers (make them now, on L1): `export MK_ARGV=MF-LAB-ARGV-$RANDOM$RANDOM MK_FILE=MF-LAB-FILE-$RANDOM$RANDOM`;
a project folder whose `data.txt` contains `$MK_FILE`, whose `main.py` prints `sys.argv[1]` and
`open("data.txt").read()` and writes `result.txt`, and whose `compute.yaml` has
`entrypoint: ["python", "main.py", "<the value of $MK_ARGV>"]`, `outputs: [result.txt]` and
`secrets: [LAB_KEY]` (`compute run` takes the job's arguments from the manifest), and a secret: `printf 'MF-LAB-SECRET-%s' "$RANDOM$RANDOM" | tee /tmp/val | compute secret set LAB_KEY`
.
1. Start captures **before** any traffic:
   - L1: `sudo tcpdump -i <iface> -s0 -w l1.pcap 'tcp port 47100 or tcp port 47101 or tcp port 47110'`
   - L2: `sudo tcpdump -i <iface> -s0 -w l2.pcap 'tcp port 47120'` (agent-to-agent traffic never passes L1)
   - L3 (Windows): Wireshark, capture filter `tcp port 47120 or tcp port 47100 or tcp port 47110`, save as `l3.pcapng`.
2. Traffic, as alice on L1 (one plane each):
   a. **Enrol** (47101): `meshforge-controller fabric invite` and join it on a fresh data dir on L2
      (`meshforge-agent join --config <a copy of the config with another data_dir>`); keep the code in
      `$MK_CODE` on L1 (`export MK_CODE=...`) for the grep. **Dedicated enrolment capture (D167):** on
      L1, right before the join, also start `sudo tcpdump -i <iface> -s0 -w enroll.pcap 'tcp port 47101'`
      and stop it (Ctrl-C) once `meshforge-agent identity show` on L2 says `enrolled: true`. Then on L1,
      with the Python that runs MeshForge (`uv run python` in the checkout, or the installed venv's):
      ```bash
      python - "$MK_CODE" enroll.pcap <<'PY'
      import sys
      from meshforge.common import join_code
      code, data = sys.argv[1], open(sys.argv[2], "rb").read()
      token = join_code.decode(code).token
      for name, m in [("code", code.encode()), ("token_raw", token), ("token_hex", token.hex().encode()),
                      ("csr_armour", b"CERTIFICATE REQUEST"), ("cert_armour", b"BEGIN CERTIFICATE")]:
          print(name, data.count(m))
      PY
      tshark -r enroll.pcap -q -z conv,tcp | grep -c 47101            # connections seen
      tshark -r enroll.pcap -d tcp.port==47101,tls -Y 'tcp.len > 0 && (!tls || _ws.malformed)' | wc -l   # payload that is not well-formed TLS
      tshark -r enroll.pcap -d tcp.port==47101,tls -Y 'tls.handshake.type == 2' -T fields -e tls.handshake.extensions.supported_version | sort | uniq -c
      ```
      **PASTE** the output. Expected: the five counts `0`; at least `2` connections (the CA fetch and
      `Enroll`) - fewer means the capture missed the join, redo it; `0` payload packets that are not well-formed TLS; every
      ServerHello `0x0304` (TLS 1.3). CI runs the same check on loopback
      (`tests/cluster/test_v07_g7_criterion3_recorder.py`, the "enroll" link).
   b. **REST + blobs** (47110) and **control** (47100): `compute run <project> --node <L2 id> -f`,
      `compute logs <job>`, `compute get <job> --dest out/` (the output download).
   c. **Peer** (47120): the same with `--node <L3 id>` while L1's uplink is busy (or simply run it: L3
      fetches what L2 holds from L2's peer server when the controller is slower); then the sleep project
      from R on L3 and `compute cancel <job>` while it runs.
3. Stop the captures; copy `l2.pcap` and `l3.pcapng` to L1. For **each** file run (on L1):
   ```bash
   for f in l1.pcap l2.pcap l3.pcapng; do
     echo "== $f"
     for m in "$MK_ARGV" "$MK_FILE" "$(cat /tmp/val)" "$(base64 -w0 /tmp/val | tr -d =)" \
              "$(xxd -p -c 9999 /tmp/val)" "$MK_CODE" "Bearer " "eyJhdHQiOiJhdHRf" \
              "$(python3 -c 'import json,os;print(json.load(open(os.path.expanduser("~/.config/meshforge/compute/login.json")))["token"])')"; do
       printf '%s ' "$(grep -c -a -F -- "$m" "$f")"
     done; echo
     tshark -r "$f" -d tcp.port==47110,http -d tcp.port==47120,http -Y 'http || http2' 2>/dev/null | wc -l
     tshark -r "$f" -Y 'tls.handshake.type == 2' -T fields -e tcp.srcport -e tls.handshake.extensions.supported_version 2>/dev/null | sort | uniq -c
   done
   ```
   (`eyJhdHQiOiJhdHRf` is the fixed start of every peer token; `Bearer ` the start of every
   `Authorization` header: API tokens, fetch tokens, upload grants, peer tokens. Adjust the
   `login.json` path if `[cli] credentials_dir` is set.)
   **PASTE** the whole output. Expected: every count `0` on all three files; the `http || http2` line
   count `0`; the ServerHello versions `0x0304` (TLS 1.3) on 47101/47110/47120, and on 47100 TLS 1.3 or
   1.2 (grpcio negotiates; D137).
4. Positive control (shows the capture works): in Wireshark on `l1.pcap`, Statistics > Protocol
   Hierarchy. **PASTE** a screenshot: TLS on every stream, nothing else above TCP. Also
   `tshark -r l2.pcap -Y 'tls.handshake.extensions_server_name' -T fields -e tls.handshake.extensions_server_name | sort -u`
   - **PASTE**: the peer server names `node-<id>.node.meshforge` are visible by design (THREAT_MODEL PB-I2).
5. The job really ran with the markers: **PASTE** `compute logs <the L3 job>` - expected `$MK_ARGV`,
   `$MK_FILE` and `[secret:LAB_KEY]` where the secret was printed.
