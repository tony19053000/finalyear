# V0.7 G3 lab check - mTLS on a real LAN, revocation on real laptops (tester)

Needs: controller laptop **L1** (Linux), >= 2 agent laptops (**at least one Windows**, L2/L3),
all on the same Wi-Fi/LAN, G3 code pulled everywhere. Roughly 45 minutes. Paste back the
lines marked **PASTE**. `<L1-IP>` is L1's LAN address.

## 0. Clocks first (peer tokens live 60 s, peers allow 30 s of skew)
1. On every laptop turn time sync on (Linux `timedatectl set-ntp true`; Windows "Set time
   automatically" or `w32tm /resync`), then print `date -u +%s` (Windows PowerShell:
   `[DateTimeOffset]::UtcNow.ToUnixTimeSeconds()`) on all laptops within a few seconds of each
   other. **PASTE** the numbers. Expected: every laptop within **30 s** of L1. A laptop further off
   refuses peer fetches (`agent.peer.refused reason=expired` / `too_long` in its log) and jobs fall
   back to the controller - fix its clock before section B.

## A. Join (every agent laptop re-joins once - old enrolments stop working)
1. L1: `meshforge-controller fabric create` (skip if a CA exists), then start the controller.
   Open 47100, 47101, 47110 on L1's firewall (47120 on every agent laptop).
2. L1: `meshforge-controller fabric invite` once per laptop. On each agent laptop:
   `meshforge-agent join` (paste the code), then `meshforge-agent serve`.
3. L1: `compute nodes`. **PASTE** the table. Expected: every laptop `online`.

## B. No plaintext on the wire (criterion 3, real capture)
1. On L1 start a capture: `sudo tcpdump -i <iface> -s0 -w g3.pcap 'port 47100 or port 47101 or port 47110 or port 47120'`
   (Windows laptop: Wireshark with the same filter).
2. Run a job with a marker in argv and a marker in a project file, placed on L2 then on L3
   (so L3 fetches from L2's peer server):
   `compute run <project> --node <L2 id> -- MARKER-ARGV-8f3a` then the same with `--node <L3 id>`.
3. Stop the capture. `strings g3.pcap | grep -c -e MARKER-ARGV-8f3a -e <file marker> -e <fabric token>`
   **PASTE** the number. Expected `0`. In Wireshark, "Statistics > Protocol Hierarchy" must show
   TLS only on those four ports (no HTTP, no HTTP/2 cleartext). **PASTE** a screenshot or the TLS version
   column: expected TLSv1.3 on 47110 and 47120.

## C. Revocation on a laptop that is busy (criterion 1, "within one heartbeat")
1. Start a long job on L2: `compute run <project with sleep 120> --node <L2 id>`.
2. On L1 note the time (`date +%s.%N`), then `compute node revoke <L2 id>`; on L2 watch the agent.
3. Expected on L2: the agent stops within about 1 s, printing `node_revoked` and the
   `meshforge-agent identity reset --yes` remedy. Expected on L1: `compute jobs <id>` shows the
   attempt `lost` (detail `node_revoked`) and the job retried on another node. **PASTE** the agent's
   last 10 lines, the time between revoke and the agent's stop, and `compute jobs <id>`.
4. Try to bring it back: `meshforge-agent join --force` with a fresh code. Expected: refused
   `node_revoked`. Then `meshforge-agent identity reset --yes` and `meshforge-agent join` with a new code:
   expected to come back as a NEW node id. **PASTE** both outputs.

## D. Windows specifics
1. On the Windows laptop run `meshforge-agent join` then `serve`; confirm in `compute nodes` it is online.
2. `icacls %LOCALAPPDATA%\meshforge\identity\node.key` (adjust to your data dir): expected only your
   user (and SYSTEM) with access. **PASTE** the output.
3. Repeat C on this laptop. Windows is the first real run of grpcio TLS, ACLs and the revocation
   stop path outside Linux CI: **PASTE** anything unexpected verbatim.
