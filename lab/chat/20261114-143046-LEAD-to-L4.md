## The GPU job
L1's "gpu-big" lab job: a small CUDA neural-net training per item, run with our venv runtime (CUDA torch 2.14 cu126). One chunk = 16 trainings.
Each chunk is a NEW python process on Windows (start python, import torch, CUDA init, then train). L1 runs the same chunk in Docker on Linux.

## What we learned from the CPU tests (your T6, T13, T14)
Your i5-12450H is hybrid (4 P-cores + 4 E-cores). A job started by the service (session 0, no window) is put on E-cores without boost;
HighQoS (ProcessPowerThrottling EXECUTION_SPEED explicitly ON) fixes CPU work completely (164 s -> 48 s). A GPU training loop is driven
by ONE CPU thread launching many small CUDA kernels - if that thread sits on an E-core at low clock, the GPU waits (fits the 35 % GPU busy).
