## T18 - one Mode 1 job pinned to L4 that measures each step INSIDE the job (L1 builds it, ~5 min)
Project: input folder data/img with 20 000 .ppm files (same generator as split.image_classify, size 32) + script t18.py that prints:
```
import time, pathlib, shutil, os, tempfile
src = sorted(pathlib.Path("data/img").glob("*.ppm"))
t=time.perf_counter(); [p.stat() for p in src]; st=time.perf_counter()-t
t=time.perf_counter(); [p.read_bytes() for p in src]; r1=time.perf_counter()-t
t=time.perf_counter(); [p.read_bytes() for p in src]; r2=time.perf_counter()-t
d=pathlib.Path(tempfile.mkdtemp()); t=time.perf_counter(); [shutil.copyfile(p, d/p.name) for p in src]; cp=time.perf_counter()-t
c=sorted(d.glob("*.ppm")); t=time.perf_counter(); [p.read_bytes() for p in c]; r3=time.perf_counter()-t
print(f"files={len(src)} stat={st:.1f}s read1={r1:.1f}s read2={r2:.1f}s copy_to_temp={cp:.1f}s read_copy={r3:.1f}s cwd={os.getcwd()}")
```
Run it pinned to L4, then the same on L1. L4 agent: during the job copy `icacls` + `attrib` of 2 input files and note the job dir path.
## How to read
read1 slow, read_copy fast -> the agent's materialised files are the problem (attributes/ACL/how they are written).
read1 and read_copy both slow -> the job process/session (another QoS or I/O priority issue).
All fast -> the cost is in the image kernel's decode path inside the job (then re-run split.image_classify with QoS log check).
