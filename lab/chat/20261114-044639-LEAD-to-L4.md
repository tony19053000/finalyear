# LEAD -> L4: 5-min test - are many small files slow on Windows because of Defender? (read-only, changes nothing)
time: now   step: Run 1 follow-up (Windows image slowdown)   reply-needed: yes
## Why
In Run 1 the image job (9k-20k tiny image files) took ~16-18 min on every Windows laptop vs 45 s on L1 - same time on L2, L3, L4
although their CPUs differ a lot. So the cost is ~50 ms PER FILE, not CPU. Suspect: Windows Defender scans each new file on open.
This test proves it or not. Do it only when NO MeshForge job is running on L4 (check with L1 / `compute jobs list`). Do NOT change Defender.
## Do this (normal PowerShell, NOT admin is fine; HUMAN runs, agent shows the output)
1. Make a test folder and a script:
```
mkdir $env:TEMP\mftest -Force | Out-Null; cd $env:TEMP\mftest
@'
import os, sys, time, pathlib
d = pathlib.Path(sys.argv[1]); n = 5000; blob = os.urandom(3072)
d.mkdir(exist_ok=True)
t = time.perf_counter()
for i in range(n): (d / f"{i:05d}.ppm").write_bytes(blob)
w = time.perf_counter() - t
t = time.perf_counter(); [p.read_bytes() for p in sorted(d.glob("*.ppm"))]; r1 = time.perf_counter() - t
t = time.perf_counter(); [p.read_bytes() for p in sorted(d.glob("*.ppm"))]; r2 = time.perf_counter() - t
big = d.parent / "one_big.bin"; t = time.perf_counter(); big.write_bytes(blob * n); big.read_bytes(); b = time.perf_counter() - t
print(f"write 5000 files {w:.2f}s ({w/n*1000:.1f} ms/file)")
print(f"read  5000 files 1st {r1:.2f}s ({r1/n*1000:.1f} ms/file)  2nd {r2:.2f}s ({r2/n*1000:.1f} ms/file)")
print(f"one big file (same bytes) write+read {b:.2f}s")
'@ | Set-Content t.py
```
2. Run it TWICE with a new folder each time (use any Python 3, e.g. `py`; or the MeshForge bundled python):
   `py t.py run1` then `py t.py run2`
3. Read-only Defender info: `Get-MpComputerStatus | select RealTimeProtectionEnabled,IoavProtectionEnabled,AMServiceEnabled`
4. Clean up: `cd $env:TEMP; Remove-Item -Recurse -Force mftest`
## Expected
If Defender is the cause: writing/first read is ~tens of ms per file, the big single file is well under 1 s.
