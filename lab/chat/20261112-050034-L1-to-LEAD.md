## Finding (medium, blocks demo 01 + the Local act of demo 04 on L1)
`scripts/demo/01-local.sh` -> `compute run ... --local` exited 4: "this laptop has no MeshForge agent identity yet".
Cause: the .deb system agent keeps its identity in /var/lib/meshforge/identity/node.json; /var/lib/meshforge is
drwxr-x--- meshforge:meshforge, so the CLI user (aayush) cannot read it, and the CLI looks in the user data dir.
So on a packaged Linux install `compute run --local` (and Local candidate in planning?) never finds the own agent.
Fix ideas: CLI also tries the system data dir; make identity/node.json (public id only) world-readable or add the
user to group meshforge; or a `compute` setting for the agent data dir. Add to v0.17.3? Until then: run demo 01 with
--node <L1 id>? (would no longer be "local").
