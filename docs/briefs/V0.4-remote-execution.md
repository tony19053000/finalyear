## 2. Design decisions (settled by the Lead before spawning)

Numbering continues from V0.3 (D1–D39). **Object before the lane that builds it starts** — after that, changing

### 2a. Session hardening (G1)

| # | Decision | Why |
|---|---|---|
| D40 | **Explicit `Goodbye` replaces the timing inference.** New agent payload `Goodbye goodbye = 21` `{Reason reason (UNSPECIFIED=0, SHUTDOWN=1); string detail (bounded, printable)}`. On a requested stop the agent sends `Goodbye` as its **last** message, then half-closes and waits for the status as today. The controller treats a `Goodbye` (right `session_id`, valid envelope) as the clean-close event: it ends the session `agent_closed` **on receipt** (→ OFFLINE now, §12.3) and returns `OK`. **Any end of the stream without a prior `Goodbye` is `stream_lost`** (→ SUSPECT + linger), however "normal" the iterator end looked. `Goodbye` is never buffered, replayed or acked (add it to `_UNACKED`). `HALF_CLOSE_CONFIRM_S`, the `half_close_confirm_s` parameter and the confirm sleep are **deleted**, not kept as a fallback. | The roadmap row said "keep the timing rule as a fallback for old agents". There are no deployed old agents, and an old agent's clean stop now degrades to *SUSPECT → OFFLINE at lease expiry* (≤ 6 s later) — the **safe** direction: OFFLINE late never duplicates work, OFFLINE early does (V0.6 retries on it). A fallback would keep a timing hack and the `grpcio<1.85` cap alive for agents that do not exist. Ending on receipt (not "Goodbye *and* iterator ended") is simpler and equally safe: the agent has declared it is leaving; a zombie's `Goodbye` carries a stale `session_id` and is already dropped by the existing stale-message rule. |
| D41 | **Admission has a deadline.** `admit()` (lock wait + registry round trips) runs under `asyncio.timeout(admission_timeout_s)` (controller session setting, default **5 s**, bounds 0.5–30, validated **< the OFFLINE edge**). On timeout: reject with a new retryable `REJECT_CODE_UNAVAILABLE = 5` (the agent backs off like any retryable reject — check `agent/session/policy.py` treats it so), log `session.admission_timeout`, and the existing `finally` releases the claim and settles any deferred end **with its event**, then wakes the lease timer. | D28's claim makes the lease timer skip a node while its Hello is admitted. Unbounded, a hung database would leave a dead node ONLINE forever. The deadline bounds that suppression to one known interval. |
| D42 | **Split `manager.py` before V0.4 adds handlers.** (1) `session/claims.py` — the D28 claim/deferred-end logic (`_pending_hellos`, `_deferred_ends`, `admission_pending`, `_release_claim`) as one small class (`EndArbiter` or better name) with its own unit tests. (2) `session/reports.py` — per-report handlers (`_on_resource_update`, `_on_hardware_scores`, `_hello_scores`, `_reject_scores`) plus their counters. (3) `_dispatch` becomes a **table** `payload name → handler`, so G4 registers `attempt_status`/`log_chunk` without editing the manager's control flow. **Target `manager.py` ≤ 850 lines.** The move is a **refactor-only commit first** (behaviour identical, the existing suites green with only import-path edits), and only then the D40/D41 behaviour change. | Roadmap 0.4.17 item 2 and the G6 reviewer's `claims.py` ask. Doing the pure move first makes the review of D40 a small diff instead of a 1300-line one. |
| D43 | **Overflow and rejection are visible.** `WriteChain` emits `registry.write_queue_overflow` **once per overflow episode per session** (episode ends when the queue drains below half capacity), with `dropped` / `capacity` / `pending`; the per-drop `registry.write_dropped` stays at debug. `session.closed` (the session-end summary) lists every per-session counter, **including `hardware_scores_rejected`** (0.4.17 item 5) and the new overflow count. A direct test covers the **shutdown deferred-end backstop** (`manager.py` `# pragma: no cover` around `shutdown()`), and the pragma is removed. | G6/G7 follow-ups. A silent drop of liveness history is exactly the class of bug G4 found three times. |
| D43b | **The `grpcio<1.85` cap is lifted by the Lead after G1 closes**, not by G1: a separate step that upgrades grpcio and runs `tests/component/controller/test_stream_end_liveness.py` + the cluster tier on it, while no other lane is running (`uv.lock` changes re-sync every running agent's environment — §4 trap). | Keeps G1 free of `pyproject.toml`/`uv.lock`, so G2/G3 can run beside it. |

### 2b. Trust boundary for remote execution (all groups) — **[ADR-0014](../adr/0014-interim-execution-trust.md) (Proposed)**

V0.4 is the first version where a request causes code to run on another laptop. CLAUDE.md §9: *never design for
unauthenticated arbitrary code execution*. V0.7 brings pairing + mTLS; until then:

| # | Decision | Why |
|---|---|---|
| D44 | **Mutating and job-scoped REST needs a fabric token.** The controller creates a 32-byte random token (`secrets.token_urlsafe(32)`) on first start in its data dir (`fabric.token`, 0600 / Windows ACL like ADR-0013, atomic create), prints it with `meshforge-controller token show`, and can rotate it (`token rotate`). Every `POST`/`PUT`/`DELETE`, every `/v1/jobs*` read (logs contain user output) and every `/v1/blobs*` call requires `Authorization: Bearer <token>`, compared with `hmac.compare_digest`; missing/wrong → the typed envelope `unauthorized` (401). **The node/session GETs of D14 stay open.** CLI: `[cli] token` / `MESHFORGE_CLI__TOKEN` / `--token-file`; never logged, never in a URL. | A shared secret is the smallest thing that is not "anyone on the Wi-Fi can run code on four laptops". It is honest about what it is (one fabric-wide secret, no per-user identity) and V0.7 replaces it without changing the call sites (same header). |
| D45 | **An agent executes nothing unless its owner opts in.** `[agent.execution] enabled = false` by default; only an enabled agent advertises the `exec` capability (plus `exec-docker` / `exec-subprocess` per D51), and the controller **never** sends `StartAttempt` to a node without `exec`. An agent receiving `StartAttempt` while disabled rejects it (`AttemptStatus FAILED(unauthorized)`), never runs it. `allow_unsandboxed = false` by default: without it, `exec-subprocess` is not advertised. Enabled + controller found by **mDNS** → a loud `agent.execution.unpinned_controller` warning at start (a rogue controller on the LAN could send work) and a line in `docs/OPERATIONS.md`. Per-attempt **fetch tokens** (D48) scope what an agent may download. | The agent trusts whichever controller it connects to until V0.7 mTLS. The owner of each laptop decides whether it runs other people's code — that is also a product requirement (owner settings, roadmap 0.6.2). |

### 2c. Job model and submission (G2)

| # | Decision | Why |
|---|---|---|
| D46 | **Manifest** `compute.yaml` → Pydantic v2 model in **`meshforge.common.manifest`** (CLI, controller and agent all read it; `common` is the only package all three may import). V0.4 fields: `name`; `entrypoint` (string → `shlex.split` POSIX rules, or an argv list; **never a shell**); `env.base` (`python-cpu` \| `cuda-pytorch`, mapped to **digest-pinned** images in agent settings), `env.python` (recorded; must match the base), `env.requirements` (path in the tree; installed per D51); `resources.gpu` (`required`\|`preferred`\|`none`), `resources.vram_gb`, `ram_gb`, `cpus`; `outputs` (relative paths/globs, no `..`, no absolute); `limits.timeout` (duration string, bounded), `limits.network` (`default`\|`none`). `extra="forbid"`: an unknown key is an `invalid_input` with its YAML path. `split:` and `inputs:` are **recognised and rejected** with "arrives in V0.10 / V0.5" (never silently ignored). No manifest → inferred: `main.py`, else `__main__.py`, else `invalid_input` listing what was looked for. `yaml.safe_load` only; file size cap. | ARCHITECTURE §6.1 is illustrative; this fixes the V0.4 subset. Rejecting `split:` is the "no confidently-wrong output" rule: a job that asked for splitting must not quietly run whole. |
| D47 | **Bundle** = deterministic PAX tar → zstd (level 3) → SHA-256 of the compressed bytes is the **bundle digest**. Deterministic: paths sorted, POSIX separators, uid/gid 0, empty uname/gname, mtime 0, modes normalised to 0644/0755 (exec bit kept), no xattrs. Ignore: built-ins (`.git/`, `__pycache__/`, `.venv/`, `node_modules/`, `*.pyc`) + `.gitignore` + `.computeignore` via **`pathspec`** (gitwildmatch). Symlinks: kept only if the target stays inside the tree, else `invalid_input`; hardlinks/devices/fifos refused. Caps (settings): total uncompressed size (default 1 GiB), file count (100 000). **Unpacking is hostile-input safe** (agent side): reject absolute paths, `..`, links escaping the root, over-cap sizes (zip-bomb bound on the *decompressed* stream). Lives in `meshforge.common.bundle` (CLI packs, agent unpacks, outputs reuse it in G5). | Same tree → same digest on Linux and Windows is what makes V0.5's "resubmit transfers 0 bytes" possible; the unpack side is where a malicious bundle would attack a laptop. |
| D48 | **Blob store (V0.4 simple path, shaped like V0.5's CAS).** Controller dir `blobs/sha256/<2>/<64>`; `PUT /v1/blobs/{sha256}` streams the body to a temp file, verifies the digest, renames (idempotent: existing → 200, mismatch → `integrity_error`, size cap); `HEAD` for "have"; `GET` streams. Agents fetch with a **per-attempt fetch token** (random, bound to that attempt's digests, expires at attempt end + grace) instead of the fabric token — an agent never holds the fabric secret. | ADR-0003's layout from day one, so V0.5 adds chunking/peers without migrating data. Scoped tokens are V0.5's plan too. |
| D49 | **Job and attempt persistence** (migration `0006`): `job` (id, name, state, manifest JSONB, bundle_digest, placement JSONB, idempotency_key UNIQUE NULL, request_hash, created/updated, terminal failure_type/detail), `attempt` (id, job_id, node_id, fencing_token, state, failure_type, detail, exit_code, output_digest, start_snapshot JSONB, timestamps), `attempt_phase` (attempt_id, phase, started_at, duration_ms; PK (attempt_id, phase)). **All transitions through one pure module** `controller/jobs/transitions.py` (`next_job_state`, `next_attempt_state`, table-driven from §12.1/§12.2, every non-arrow raises) and **one writer** that updates with compare-and-set (`UPDATE … WHERE id = :id AND state = :expected`), so two racing transitions can never both win. `fencing_token` = per-job attempt epoch starting at 1. Python `JobState` / `AttemptState` enums in `common` with a proto parity test. | §12 is the contract V0.6's retries and V0.10's chunks build on; CAS updates are what make "0 duplicated executions" provable later. |
| D50 | **`POST /v1/jobs`** `{manifest, bundle_digest, placement: {node_id} \| {local: true}}` + optional `Idempotency-Key` header (bounded printable). Same key + same canonical request hash → `200` with the existing job (no second execution, criterion 4); same key + different body → `409 conflict`. Bundle not in the store → `409` listing the missing digest. Placement validated at submit: node unknown → `404 not_found`; not ONLINE, or lacking `exec` / a runtime that fits `resources.gpu` → `409` with a typed reason (`no_feasible_plan`) — **no job row** for a rejected request. `--local` = the submitting laptop's own agent: the CLI reads `node_id` from that agent's `node.json` (read-only, via a small `common` helper that knows `platform_dirs()`; the CLI never imports `agent`); no local agent → a clear CLI error. V0.4 records `PLANNING` as an immediate pass-through (placement is manual) so phase timings are complete from day one. Accepted job → `201` `{job_id, state}`. | One submission path for Local and Mode 1 (CLAUDE.md: Local is always a baseline, and one planner). Validating before creating keeps the jobs table free of rows that never had a chance. |

### 2d. Runtimes (G3) — the interface is fixed here so G3 can run in parallel

| # | Decision | Why |
|---|---|---|
| D51 | **`Runtime` protocol** in `meshforge.agent.execution.runtime`: `name`; `async probe() -> RuntimeAvailability` (available?, reason, gpu_capable, version); `async run(spec: RunSpec, on_output: Callable[[Stream, bytes], Awaitable[None]]) -> RunResult`. `RunSpec` (frozen): attempt_id, argv, workdir (host path), env (explicit allowlist + manifest env; **never** the agent's own environment), image (docker), setup_argv (requirements install or None), limits {cpus, memory_bytes, pids, timeout_s}, gpu_indices (NVML indices), network (bool), grace_s (default 3). `RunResult`: exit_code, signal, timed_out, cancelled, oom_killed, failure_type \| None, phase durations {env_s, run_s} from the **monotonic** clock. **Cancellation = cancelling the `run()` task**: graceful stop, then kill after `grace_s`, returning within `grace_s + 2 s` (criterion 3, ≤ 5 s). Timeout is enforced **inside** `run()` (criterion 3: within 2 s of the limit) and is `deadline_exceeded`; OOM → `oom`; non-zero exit → `user_error`; runtime/infrastructure fault → `internal_error`/`env_error` with detail. **Docker runtime** (`docker` SDK, blocking calls via `asyncio.to_thread`): only the workdir mounted (at `/work`), non-root user (numeric uid; test asserts uid ≠ 0 inside), `cap_drop=ALL`, `no-new-privileges`, `pids_limit`, `mem_limit` (+ `memswap_limit` = same), `nano_cpus`, `network_mode none` when `network=false`, labels `meshforge.attempt_id`/`meshforge.agent`, removed after collection, **orphans with our label swept at agent start**; GPU via `device_requests` with the exact NVML indices. Requirements: a separate **setup container** installs into `/work/.meshforge/deps` (`pip install --target`, network on) and the run container gets `PYTHONPATH`; its duration is the `env` phase (V0.5 caches it by env hash). **Subprocess runtime** (fallback, advertised only with `allow_unsandboxed`): same interface, `cwd=workdir`, allowlisted env, new process group / Windows job object via the shared `agent/process.py` tree-kill, lowered priority; documented as **unsandboxed**. | ADR-0004. Fixing the interface in the brief is what lets G3 build and test both runtimes before G4's executor exists. Separating setup from run keeps the run container network-free when the manifest says `none`, and the deps dir is the seam V0.5 caches. |

### 2e. Execution protocol, logs, outputs (G4/G5 — briefed after G1–G3 land, decided now)

| # | Decision | Why |
|---|---|---|
| D52 | `StartAttempt` gains an `ExecutionSpec` (bundle digest, fetch base URL + fetch token, canonical manifest JSON, runtime choice, limits, gpu indices, output globs, timeout). `AttemptStatus` gains `exit_code`, phase durations, `output_digest`, failure. Both ride the existing session: commands carry `session_id` + `message_id` (agent dedupes, D2), `AttemptStatus` goes through `send_report` (buffered, replayed, acked), idempotent on `(attempt_id, fencing_token, state)`; a status with a stale fencing token is dropped and counted (`fenced`). The controller's handler registers in G1's dispatch table. Agent stop with running attempts: cancel them, report `FAILED(node_lost, detail=agent_shutdown)` (retryable in V0.6), **then** `Goodbye`. | One channel, one replay mechanism, fencing from day one — V0.6 turns these into "0 lost, 0 duplicated". |
| D53 | **Logs:** the agent batches `LogChunk`s per (attempt, stream) — flush at 64 KiB or **100 ms** — with byte offsets; it also writes a local log file. The controller appends by offset (a replayed or duplicate range is skipped, a gap is recorded, never filled with invented bytes) into `logs/<attempt_id>.<stream>` and fans out to subscribers. Client: `GET /v1/jobs/{id}/logs` (plain, `?follow=true` as WebSocket, D44 token in the `Authorization` header of the handshake). Log volume must not evict liveness-critical reports from the replay ring — G4/G5 give logs their own bounded budget. | Criterion 2 (≤ 1 s): 100 ms batching leaves ~900 ms for two hops on a LAN. |
| D54 | **Outputs:** after exit the agent packs the declared outputs with `common.bundle` (same determinism), uploads with the fetch token (`PUT /v1/blobs`), reports `output_digest`; `compute get <job>` downloads and unpacks into `./outputs/<job_id>/`. Missing declared outputs are listed in the status, not an error. **Cancel:** `POST /v1/jobs/{id}/cancel` → `CancelAttempt`; controller backstop: an attempt still running at `timeout + 30 s` is marked `FAILED(deadline_exceeded)` and cancelled. | Criteria 1 and 3. |

## 4. Standing checklist — paste verbatim into every V0.4 brief

```
No confidently-wrong output. Before handing off, check each and say which apply:
1. Every failure path has a typed failure_type / exception and a test that triggers it for real
   (kill the process, close the socket, stop the container) — not a mock that raises.
2. Nothing is asserted from this machine's state (hostname, GPU present, driver version, IPs, Docker present).
   Tests pass on a CPU-only Windows laptop after a plain `uv sync`; Docker/GPU tests SKIP with a reason there.
3. Time: only loop.time()/monotonic for leases, timeouts and backoff; wall clock only for timestamps.
   Unit tests inject the clock; no sleep() longer than 50 ms in unit tests.
4. Idempotency: every handler tolerates duplicates and reordering across a reconnect (message_id dedupe,
   sequence/offset gaps, stale session_id, stale fencing_token) — with a test for each.
5. Concurrency: one asyncio task owns each stream; shared state behind one lock or a single-writer task;
   no fire-and-forget create_task without a kept reference and an exception handler.
6. Boundaries: controller/agent never import each other; cli imports neither; src/ never imports lab/;
   proto changes regenerate deterministically (`uv run python scripts/gen_protos.py --check`).
7. Logs: structlog events carry node_id/session_id/job_id/attempt_id as relevant; no secrets, tokens, key
   material, user file contents or full user-dir paths.
8. Docs: settings documented where defined; new ports/dirs in ARCHITECTURE §23; any §12 change amended there.
9. Hostile input: everything from the network or from a user's project (manifest, bundle, Idempotency-Key,
   paths, log bytes) is bounded and validated before use or storage, with a test per bound (max accepted AND
   max+1 rejected).
10. A guard whose failure is silent gets a mutation check: break the code, show the test fails, restore.
11. Report exact commands, pass counts AND exit codes (pytest via `scripts/pytest_exit_guard.py`); say
    explicitly what you did NOT run. Gates: `uv run ruff check . && uv run ruff format --check .`,
    `uv run mypy src`, `uv run lint-imports`, gen_protos --check.
12. Commit after every numbered deliverable (explicit paths, never `git add -A`; never `git push`; never mark
    roadmap checkboxes). A usage limit can end the run at any moment — uncommitted work is lost work.
13. Do not start another group's tasks; list what you noticed under Follow-ups.
```

Tester exit list (every V0.4 tester brief): the gates in item 11 **including ruff format**, plus exit codes of every
pytest invocation.
