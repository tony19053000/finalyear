## 2. Design decisions (Lead proposals — team approves before G1)

| # | Decision | Why |
|---|---|---|
| D133 | **Threat model first (0.7.1).** `docs/THREAT_MODEL.md`: assets (laptops, owners' files, job code/data, secrets, CA key), actors (LAN outsider, rogue controller, stolen/revoked laptop, malicious-but-enrolled user, malicious workload), and a STRIDE table **per plane**: control gRPC, REST, controller blob HTTP, peer blob HTTP, mDNS, local files (CAS seeding by the CLI), workload sandbox. Every row: mitigation + the test that proves it, or "accepted" + rationale. 0.7.11 reviews against this table, row by row. | Criterion 5 needs a list to close; without it "secure" is an opinion. |
| D134 | **Fabric CA (0.7.2).** `meshforge-controller fabric create` (controller host only — needs the CA key file) makes a self-signed **ECDSA P-256** root CA (10 y), `fabric_id` (ULID) in the subject, key in `<data>/controller/ca/` via `private_files` (same rules as ADR-0013). No intermediate CA: one controller, offline CA buys nothing here. Controller's own **server cert** issued from it (1 y, SANs = configured bind/advertise addresses + `meshforge-controller`). New module `common/pki.py` (pure: create CA, issue, verify CSR, fingerprints, SAN parsing) on `cryptography` (already a dependency). | ADR-0008 says it; P-256 because BoringSSL (grpcio) verifies it everywhere (ADR-0013). |
| D135 | **Join code (0.7.3).** `meshforge-controller fabric invite` and `compute fabric invite` (admin, over REST): code = `mf1-` + base32(version, controller host:port, **128-bit token**, **first 128 bits of SHA-256(CA cert)**) ≈ 60 chars, grouped for reading, plus `--qr` (terminal QR later; dashboard QR is V0.8). Table `join_token(id, token_hash, created_by, expires_at, used_at, used_by_node)`; **token stored hashed**; TTL default 15 min (1 min–24 h); consumed by one `UPDATE … WHERE used_at IS NULL AND expires_at > now() RETURNING` → single use under races; `compute fabric invites [--revoke ID]`. Enrollment endpoint rate-limited per source IP. | Short-lived, single-use, offline-verifiable CA pinning without a PAKE (ADR-0008 rejected PAKE-only). 128-bit truncated fingerprint = 2^128 second-preimage work. |
| D136 | **Enrollment (0.7.4).** One gRPC port, TLS with **client cert optional at the handshake**: `Enroll(join_token, CSR)` is the only RPC allowed without a cert; `Session` requires a verified client cert (checked in an interceptor via `auth_context`). The agent connects trusting nothing, gets the CA cert in the response, **checks it against the code's fingerprint before sending anything secret** (token goes in a second message after the check — or: TLS with a pinned-fingerprint custom verifier; implementer picks, reviewer checks). CSR must be signed by the ADR-0013 key and name the agent's `node_id`; cert: 30 d, SAN URI `meshforge://fabric/<fabric_id>/node/<node_id>`, EKU clientAuth+serverAuth (the peer server uses it). Same `node_id` already enrolled with another key → refused unless `invite --replace <node_id>`. Stored as `node.crt` + `ca.crt` beside `node.key`, same protection. `meshforge-agent join <code>` (+ `compute fabric join` alias on a laptop with an agent). | Pairing binds `node_id` → key → cert; closes ADR-0013's trust point. |
| D137 | **mTLS on control plane (0.7.5).** Agent verifies the controller's cert against `ca.crt` (hostname check against the dialled host **or** the SAN `meshforge-controller` — mDNS-found addresses are fine because the cert, not the address, is the trust). Controller derives `node_id` from the client cert; `Hello.node_id` must equal it (else `UNAUTHENTICATED`). This also closes ADR-0014's "rogue controller on the LAN" gap. TLS ≥ 1.2 on gRPC (grpcio exposes no min-version knob; BoringSSL negotiates 1.3 when both sides can — verified in a test), TLS 1.3 only on Python `ssl` servers. | ADR-0008. |
| D138 | **Revocation (0.7.7a).** The controller is the only verifier on the control plane, so revocation = a DB flag checked at handshake/Hello **plus** an immediate kill of the live stream (`compute node revoke <id>` → session aborted with `PERMISSION_DENIED`; criterion 1 "within one heartbeat" is met by construction, measured in a test). For the **peer plane** (agent↔agent) the controller pushes a `RevocationUpdate{serials}` command to every agent (at-least-once, D113 audit row), and peers refuse those serials; plus a revoked node can no longer obtain peer/fetch tokens (≤ 60 s life). No CRL/OCSP files — nobody outside the fabric verifies our certs. | Simple, immediate, testable; avoids CRL distribution machinery. |
| D139 | **TLS on HTTP planes (0.7.5).** Controller REST + blobs: HTTPS with the controller server cert (uvicorn `ssl_*`). Agents use their node cert as client cert for `/v1/blobs` (fetch tokens still required — two locks). Peer server 47120: TLS with the node cert, **client cert required** and its serial checked against the revocation set; the fetching agent checks the server cert's SAN `node_id` equals the peer the controller named. CLI trusts `ca.crt` (from `compute login`, D140). Plain HTTP only in `security.mode = "insecure-dev"`, which forces loopback-only binds and logs a banner — used by unit tests that do not test security; component/cluster tests run mTLS by default with a fixture CA. | Criterion 3 (no plaintext on any plane). |
| D140 | **Rotation (0.7.7b).** Agent renews at ⅔ of cert life via `RenewCertificate(CSR)` over the existing mTLS session (same key by default; `meshforge-agent rotate-key` makes a new key — `node_id` unchanged, ADR-0013). Atomic swap; next reconnect uses it. Expired cert (laptop off > 30 d) → agent says "re-join needed" with the exact command; no silent fallback. Controller server cert auto-renews at ⅔. **CA rotation is NOT in V0.7** (see Q2). | Short certs make revocation cheap; renewals need no human. |
| D141 | **User auth on REST (0.7.6).** Table `app_user(id, name, role: admin|user, pw_hash, disabled)`; password hash = stdlib `hashlib.scrypt` (n=2^15, r=8, p=1) — no new dependency. First admin: `meshforge-controller user create --admin` on the controller host. `compute login` (HTTPS, verifies CA fingerprint printed by the admin / shown in the invite) → **API token**: opaque 256-bit, stored hashed (`api_token(id, user_id, name, hash, created_at, expires_at, last_used_at, revoked_at)`), default 90 d, revocable (`compute tokens list|revoke`). CLI stores token + `ca.crt` in its config dir via `private_files`; never in URLs or logs. Every job gets `owner_user_id`; users see/cancel/download **their** jobs, admins all; node revoke, invites, users = admin. **Fabric token**: accepted for one version behind `[controller.auth] legacy_fabric_token = false` (default off), then deleted in V0.8. Brute force: per-user + per-IP backoff on login. Dashboard browser sessions are V0.8 (they reuse the same token table). | Per-user identity + audit; criterion "secrets never in logs". |
| D142 | **Owner policy (0.7.8).** The **agent is authoritative** (the laptop's owner controls it locally): `[agent.policy]` `accept_jobs`, `accept_gpu_sessions` (stored now, used by V0.11), `max_cpu_jobs`/`max_gpu_jobs` (exist), `max_ram_bytes`, `max_cpu_percent`, `max_vram_bytes`, `allow_unsandboxed`, `allowed_users` (empty = all). Advertised in `Hello` + a `PolicyUpdate` report when `meshforge-agent policy set …` changes it live; planner feasibility rejects with reason codes (`policy_*`); the agent **also** refuses a violating `StartAttempt` (`FAILED(unauthorized)` / `policy_denied`) — defence in depth. Caps are enforced by runtime limits (Docker `--memory/--cpus/--gpus`, subprocess: rlimits on Linux, job-object limits on Windows), not only by placement. Replaces `[agent.execution] enabled` (migrated: `enabled=false` → `accept_jobs=false`). | The owner must win even if the controller is wrong or compromised. |
| D143 | **Sandbox hardening (0.7.9) — gaps only.** Add/verify: default seccomp profile on (never `unconfined`), `--pids-limit`, `--security-opt no-new-privileges` kept, no Docker socket / host paths except the attempt workdir (assert at container create), tmpfs `/tmp` with size cap, output dir size cap enforced by the agent while running, `--network none` default; network only via manifest `network: true` **and** owner `allow_network`. Escape-attempt tests in a real container: mount, `/proc/sysrq-trigger`, raw socket, `ptrace`, fork bomb, disk fill, reach controller/peer ports when `network none`. **Subprocess runtime stays honestly "unsandboxed"** (needs two opt-ins); Linux optional `bubblewrap` if present is a stretch, not promised (Q3). | Most hardening shipped in V0.4 G3; V0.7 proves it by attack. |
| D144 | **Job secrets (0.7.10).** `compute secret set|list|delete NAME` (value from stdin/file, ≤ 64 KiB, per user). Stored encrypted at rest: AES-256-GCM with a controller master key `<data>/controller/secrets.key` (private_files); DB holds ciphertext only. Manifest `secrets: [NAME]` (owner's secrets only). Delivered per attempt **inside `StartAttempt` over mTLS** (never in the bundle, never in `plan_decision`, never in telemetry), materialised as a tmpfs file `/run/secrets/NAME` (Docker) / a 0600 file in a private dir (subprocess) — env var only if the manifest asks `as_env: true`. Redaction: agent log capture and controller log store replace exact values (and their base64/hex/URL-encoded forms) with `[secret:NAME]` **before** writing or streaming; structlog processor does the same for our own logs. Files wiped after the attempt. Honest limit (in THREAT_MODEL): a workload can deliberately leak its own secret (e.g. reversed); redaction stops accidents, not malice. | Criterion 4. |
| D145 | **Debt closed in V0.7.** (a) Uploaded parts attributed to the sending node (V0.6 G1 follow-up 3). (b) Score fingerprint now bound to the authenticated node (STATUS G7 debt). (c) `submitter_node_id` (D125): the CLI holds no node cert (the node key belongs to the agent's user), so it cannot be proven; it stays a **placement hint only**; it can change cost estimates, never authority (feasibility + owner policy still apply). Documented as accepted in THREAT_MODEL. (d) Non-dev controller refuses to start with the default DB password. (e) CLI-seeded CAS file ownership (D125) — seeding skipped when the agent runs as another user. | Known gaps the reviewer and STATUS already list. |
| D146 | **Proving criterion 3 without root.** The cluster harness's in-process fault proxy (D23) already sits on every link; give it a **byte recorder** and assert that known plaintext markers (job argv, a secret value, a file's content, the API token) never appear on any recorded link in a full job run. The 🧑 lab checklist adds a real `tcpdump`/Wireshark capture on the LAN. | CI-checkable and real-network-checked. |

## 4. Standing checklist

V0.4 §4 items 1–13 + V0.5 §4 items 14–15 + V0.6 §4 items 16–18, plus:

```
19. Fail closed: every auth check rejects on missing/unknown/expired/malformed input; a test per branch.
    No "warn and continue" in a security path.
20. No secret, token, key or password in logs, errors, exceptions, URLs, telemetry, plan_decision or test
    output. Each new secret type gets a redaction test that FAILS if the scrubber is removed (mutation check).
21. Every security claim in a doc names its test. A threat-model row without a test is "accepted" with a
    reason, never silently "mitigated".
22. Constant-time comparison for every token/hash compare; tokens stored hashed; random from `secrets`.
```
