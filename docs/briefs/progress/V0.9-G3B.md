**Deviations from §5d (with reasons):**
1. `expand()` returns `Expansion` (runs + groups/configs/dropped/duplicates/hours), not a bare list - `plan` must
   show what was dropped and the cost.
2. `config_id` digests (group, strategy, node, **origin**): without `origin` every node is the origin in turn,
   so origin is part of the configuration's identity.
3. Grid ranges need `steps`; `on_invalid: error|drop` added (drop is counted, never silent).
4. Bench routes are **admin only** - the fabric has no operator role (D141).
5. Extra columns on `bench_run` (`seed`, `detail`, `submitted_at`, `ended_at`) and `bench_campaign` (`run_count`,
   `summary`); run states also advance lazily from job states on every read/submit (`sync`) - no background loop.
6. Submit outcome `deferred` (node offline / no session / owner `policy_*` refusal: stays planned) besides
   `skipped` (permanent: node deleted, static rejection, library refuses params).
7. Recorder hook `campaign_of` changed from a sync per-job callable to an **async batched** `(db, job_ids)` lookup
   (a sync callable cannot query the DB); edits in `recorder.py` are confined to the hook type, one call in
   `_sources` and the `decision_shadow=` line - **merge-conflict risk with lane A's 0.9 `.get` change in the
   same function** (adjacent lines; trivial to resolve).
8. `compute bench campaigns [ID]` added (no other way to find a campaign id again).
9. `RUN_OVERHEAD_S = 15` s per run added to the hour estimate.
