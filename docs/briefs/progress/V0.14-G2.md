**Fix round 1 (after tester r1 PASS / reviewer r1 APPROVE at `c70e93f5`):**

- T2 `factor_table`: the title's server `version` goes through `render.echo` (scrubbed). Tester's strict xfail flipped.
- NB1 `CalibrationStore.refresh`: new rows record the matched-run set in `fit_inputs` (`matched_runs`, `newest_decision_id`, `runs_digest` = sha256 of the sorted decision ids, 32 hex). When that set and the fit settings (`window`, `k`, `clamp`) equal the **newest** row's, nothing is written and `skipped = "no_new_runs"` (the task logs `controller.planner.calibration_skipped`). Deviation from the brief wording "active row's fit_inputs": the newest row (active *or* rejected) is compared - comparing only the active row would still duplicate a rejected row every refresh. A digest is stored in addition to newest id + count because the read is ordered by `ended_at`, so a late-finishing old decision can change the set without changing either. An unreadable newest row is refitted, not skipped. Rows written before this fix lack the keys and never match (one more refit, then skipping works).
- NB2: `match` over the outcomes and `refit` run via `asyncio.to_thread` inside the same transaction; the advisory xact lock and the `FOR UPDATE` stay held (they belong to the transaction, not the thread), the session is not touched from the thread.
