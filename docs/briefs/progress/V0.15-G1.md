## Notes / design decisions taken here (for Lead review)
- **Term names.** Mode 3 lane terms are `lane_stage` / `lane_env` (brief: "lane stage|env"); in the stored row
  they are the one-lane row's `transfer` / `env` (`Term.planner_term`). Full list: `transfer, env, compute,
  output, lane_stage, lane_env, chunk_rate, combine`.
- **`chunk_rate` is stored as seconds per item** (`raw_s = 1 / rate_items_s`, `actual_s = sum(run_ms)/1000 /
  sum(items)` over `committed` chunk records with a run time). Same sign and same `raw x exp(y)` correction as
  every other term (a model for G4 multiplies the per-item time, not a rate). The 0.05 s floor applies to
  `raw_spi x items` (the lane's predicted compute seconds) - a per-item floor would drop every fast workload.
- **Mode 3 lane predictions** come from the node's **one-lane row of the same decision** (the planner costs the
  set from those very `Lane` objects; the set row only holds rate-weighted blends). Missing (truncated past 64
  rows or infeasible alone) = `missing_lane_row`, counted.
- **Combine actual** = the combine attempt's `stage + env + run` (skipped = 0 s, missing = `missing_phase`, `run`
  skipped = `skipped_phase`); its `collect` is the set's `output` term. Attached only to the job's **last**
  dispatched decision (a re-planned job's earlier rounds predicted a combine that the last round ran). Ran on
  another node than predicted (`detail.combine_node_id`) = `node_mismatch` (the calibration's "other node" rule).
- **Round lanes**: the job's `lane` attempts with fencing token in `[decision.attempt_no, next dispatched
  decision's attempt_no)` (consecutive tokens in the dispatch transaction, `split/lanes.create_lanes`).
- **A Mode 3 set counts only when its lead lane (`plan_decision.attempt_id`) is `done`** - that is what the
  shared read returns; the other lanes are judged one by one (`lane_not_done`).
- **Replay check before matching**: a decision without a replay is `missing_replay` once (never also
  `unmatched`).
- **`unmatched` vs per-term reasons**: a run the calibration refuses as a whole (not done / other node / wrong
  role / no chosen row) is `unmatched` once; a run whose every phase is skipped is not `unmatched` but one
  `skipped_phase` per term (`match()` returns None there; the reasons are named per term instead).
- **Features not in the brief's list**: memory bandwidth is **not** a feature - the replay does not hold it (the
  planner never reads it); reading it from today's DB would break D334. Added instead: GPU count, CPU slots,
  `cache_missing_frac`, `cache_items_tree_held`, `net_peer_link_age_s`, `net_term_bw_bytes_s`, history medians.
- **numpy is not used**: it is in the `agent` extra, not `controller` (the brief's §1 table says controller);
  G1 needs none. G2 will need it (with the `ml` extra, D340).
- **Shared Parquet options**: `WRITER_OPTIONS` / `ROW_GROUP_SIZE` moved to a constants-only
  `telemetry/parquet_options.py` (re-exported by `telemetry/export.py`) so the pure dataset module does not
  import database code.
- **Sidecar key** is `dataset_schema` (not `schema`: pydantic's `BaseModel.schema` would be shadowed). API
  models are `Ml*Out` (an unprefixed `TermOut` collided with the decisions answer's schema name in OpenAPI).

## Open questions
1. **`measured` transfers are excluded (D293/§5a rule) - a lot of real data.** The estimator marks a transfer
   `measured` when its bandwidth comes from a fresh probed link (a measured *input*, not an exact *prediction*),
   and every lane/whole-job transfer over the LAN matrix is like that on a probed fabric. Following the brief, G1
   excludes them (`measured`); the calibration does the same (never scales them). If the Lead wants ML to learn
   transfer residuals over probed links, the rule should become "exclude only terms that are exact by
   construction" (`queue`, 0-byte transfers, cached env) - a decision for D333/D293, not taken here.
2. Combine actual (`stage + env + run`) - confirm this is the honest measure (the alternative,
   `job.split_combine_ms`, is the run phase only and misses the parts fetch the term predicts).
