## Open questions for the Lead (found in prep)

1. **The release controller package has no `ml` extra.** `scripts/build_bundle.py --role controller` installs the
   `controller` extra only (`.github/workflows/release.yml`), and the ML training libraries live in the `ml`
   extra (`compute planner ml train` → 409 `ml extra is not installed`). On the installed rc, V0.15 training,
   B6, A1–A3, A5, A6 and therefore `V0.15-c1/c2` cannot be measured. The campaign checklist stops Day L4 at
   L4.0.2 if `can train False`. Needs a decision before the rc is built (ship the controller with `--extra ml`
   and accept the bundle size, or an optional ML add-on, or an evaluation-only exception to D406).
2. **`not_separable` vs `release_check.py`.** The brief (§0) accepts an honest `not_separable` ML result, but a
   lab row can only be recorded PASS or FAIL, so `V0.15-c1` would block exit 0. The checklist records it as FAIL
   with the line; the Lead must decide how it closes (a decision-backed reading of the criterion, or a waiver).
3. **Calibration cannot be pinned during the matrix.** Every evaluation profile sets
   `MESHFORGE_CONTROLLER__PLANNER__CALIBRATION='auto'`, which overrides a pinned version in `controller.toml`,
   so B5/B6 refit every 30 min on the matrix's own runs (incl. the held-out families). Listed as a threat to
   validity; pinning would need a profile change in `scripts/eval/evalkit/arms.py` + `lab/eval_profile.sh`.
4. **The runner from the installed bundle is untested.** Evaluation data counts only when `run_campaign.py`
   runs on the bundle interpreter (`build.source = bundle`); no CI job runs it that way. The checklist's smoke
   step (L4.0.3) catches a missing module on the day; a CI check against the built agent bundle would catch it
   before the lab.
5. **`release_check.py` needs the extras.** Run without `--all-extras`, every node id in a module that
   `importorskip`s at import exits pytest 4 and the row is FAIL (seen in this prep: 25 FAILs in a bare venv), and
   without a built dashboard the three e2e-backed rows are MISSING. The documented call should be
   `uv sync --all-extras --group evaluation && (cd frontend && npm ci && npm run build)` first (or the script
   should check both up front).
