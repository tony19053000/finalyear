## Decisions taken in the implementation (for the Lead)
1. **Controller program dir `/opt/meshforge/controller/<ver>` + `/opt/meshforge/controller/current`**
   (not `/opt/meshforge/<ver>` like the agent): both packages can be installed on one machine (brief
   item 3) and dpkg forbids two packages owning `/opt/meshforge/current`. `stable_root()` works
   unchanged (`<parent>/current`).
2. **Controller config file `/etc/meshforge/controller.toml`** (unit sets `MESHFORGE_CONFIG`; the CLI
   re-exec passes the same): the agent keeps `config.toml` (G1 migrates it, G3's console edits it), so the
   two packages never edit one file.
3. **Controller CLI re-exec only for admin sub-commands** (`token fabric node user ca db doctor`): the
   bare command is the server; a human's `meshforge-controller` stays a developer server in their own
   state (a second server over the service's cluster would be refused by the managed lock anyway).
4. **Managed DB tests are `slow`** (like SP2's): they need the 39 MB bundle once (cached in
   `.cache/meshforge-pg`). `--run-slow` runs them; offline they skip with the reason.
5. **Q19 mirror URL is pinned but not uploaded yet** (needs a GitHub release on our repo - a human step,
   agents do not push): `https://github.com/tony19053000/finalyear/releases/download/pg-16.15.1/...`.
   The fetcher tries it first and falls back to upstream; the sha256 decides.
6. **Upgrade failure exits 4 (`config_error`), not 1**: the unit's `RestartPreventExitStatus=4 5` then
   keeps systemd from restarting the new version into the same failure (and re-migrating the restored
   data each time). G5's pointer switch-back starts the previous version.
7. **Socket dir stays `<root>/run` (`/var/lib/meshforge/db/run`) in the package, no
   `RuntimeDirectory=`**: `db backup|restore` must be able to start the cluster while the service is
   stopped, and systemd deletes a `RuntimeDirectory` on stop (`/run/meshforge` is root-owned, so the
   service user could not recreate it). The path is 40 bytes, well under the 107-byte limit.
8. **`numpy` added to the `controller` extra** (pyproject + `uv lock`, 2-line lock diff, same numpy):
   found by running the controller bundle - the server imports `controller/ml/artefact.py` (numpy-only
   model serving, D359) at start-up, and numpy only came in through the agent extra in dev checkouts, so
   the packaged controller could not start at all (pre-existing bug, not caught because no test ran the
   controller from a bundle). The `ml` training extra stays optional.
9. **Setup page = loopback-only plain HTTP** (`[controller.setup] bind`, default `127.0.0.1:<http port>`),
   still token-gated (Q20 single path): the admin password must not cross the LAN in clear text, and there
   is no TLS before the CA exists. From another computer: `ssh -L 47110:127.0.0.1:47110 <controller>`
   (printed by `setup url`). The controller then restarts itself in-process into the normal (TLS) mode.
10. **No "fabric name" step**: the system has no fabric-name concept (the fabric is identified by its
    `fabric_id` + CA fingerprint, both shown). Adding a name is a data-model change - follow-up if wanted.
11. **No "chosen IP" step on the page**: the address laptops join is the `[controller.enroll]` bind the
    package's postinst writes into `/etc/meshforge/controller.toml` (the LAN IP of the default route); the
    page shows it, warns when it is loopback, and names the file to change it in (the server certificate's
    names come from the same binds, so the IP must be fixed before the CA is made).
12. **Setup token at `<data_dir>/controller/setup-token`** (brief: `/var/lib/meshforge/setup-token`): keeps
    every controller file under `controller/` so the agent package's purge can tell them apart.
13. **First admin password rule**: >= 12 chars, >= 6 distinct, not containing the name, not a common one
    (the general user rule stays 8+).
14. **OPEN for the Lead - controller .deb size: 151.6 MB vs the 150 MB Q17 budget.** The same bundle is 120.9 MB
    as `.tar.xz` (within budget); nfpm's built-in xz compresses weaker. The CI/test builds use
    `--no-size-budget` until decided. Options: (a) drop test suites/headers from the controller bundle
    (`numpy/**/tests` + `pyarrow/tests` + `pyarrow/include` ~ 25 MB on disk; changes G1's bundle rules);
    (b) a .deb-specific budget (e.g. 160 MB) noting nfpm's compression; (c) repack `data.tar` with system
    `xz -9` (deterministic, but a second tool in the chain). Recommendation: (a).
15. **The controller package does not put `compute` on PATH**: `/usr/bin/compute` belongs to the agent package
    (dpkg forbids two owners). On a controller-only machine: `/opt/meshforge/controller/current/bin/compute`.
16. **The controller binds the LAN IP found at install** (security posture unchanged: no wildcard bind). A
    laptop controller whose DHCP address changes must edit `controller.toml` (+ `extra_sans` after the fabric
    exists) - follow-up: a doctor check / console hint, or bind-by-interface.
