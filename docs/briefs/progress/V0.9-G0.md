## Item 1 — clock skew in the UI perf measure (D210 item 1, D213) — done

- **Controller stamps `recv_at`.** `LiveSample.received_wall` (controller wall clock when the heartbeat
  arrived, set in `resources.live_sample`); `events/watcher.metrics_frame` puts it in every
  `node.metrics` payload as `recv_at` (epoch s, 3 decimals, like the bus `at`), and the REST
  `MetricPoint` carries it too (optional field, `None` never happens today).
- **`GET /v1/clock`** → `{"server_time": <epoch s, µs>}` (authenticated like every route, read-only;
  `routes.wall_clock` is the injectable source). OpenAPI + `frontend/src/api/schema.d.ts` regenerated
  (`npm run gen:api`); no frontend code change.
- **Shared estimator `meshforge.common.clock_offset`** (pure; G1/D213 reuses it for per-node offsets):
  `ClockExchange(sent, remote, received)`, `estimate_offset` = minimum-RTT exchange, offset = remote −
  midpoint, bound = RTT/2 (+ half a local clock tick: `resolution_ms`, 1 ms for `Date.now()`, which also shifts the estimate by half a tick - fix `4d7bdd7`); refuses empty / non-finite / backwards exchanges (`ClockOffsetError`).
- **`scripts/ui_perf.py`**: `measure_clock` (16 sequential `fetch('/v1/clock')` from the signed-in page,
  stamped with the page's `Date.now()` — the clock the DOM probes use); heartbeat lag = DOM time −
  (`recv_at` moved onto the browser clock), joined to the WS frame by `observed_at` used only as an id
  (`HeartbeatSamples`, `MetricsFrames` = Playwright `framereceived` on `/v1/events/ws`, attached before
  `goto`); `job.state` transition times (controller clock) are moved the same way. Results carry
  `events.clock = {clock_offset_ms, clock_offset_bound_ms, rtt_ms, exchanges, max_bound_ms, uncertain}`,
  `heartbeat_unmatched`, `heartbeat_frames_unreadable`, and a run-level `verdict`.
  `verdict()`: a broken list limit → `fail` (no clock involved); else any phase with bound > 50 ms (or no
  clock) → `skew_uncertain`; else any broken limit → `fail`; else `pass`. Exit codes 0 / 1 / **3**.
  `check()` is unchanged (existing tests untouched).
- Lab checklist `lab/checklists/V0.8-visual.md` E2/E3 updated (E2: the shown time is L2's own clock; E3:
  skew-safe, `clock (...)` lines, `VERDICT`, exit 3 meaning, paste-back).
- e2e `tests/e2e/test_v08_g7_perf.py` additionally asserts the bound ≤ 50 ms, |offset| ≤ bound + 1 ms
  (one host), no unreadable frames, `verdict == "pass"`.

Design note: the brief says the controller stamps `recv_at` "on the bus event". The bus event already has
`at` (publish time); `recv_at` is put in the `node.metrics` *payload* instead, because it is the heartbeat's
**arrival** (before the watcher's ≤ 0.25 s diff interval and the 1 s metrics cap), so the measured lag
includes the controller's own delay, as a user feels it. `job.state` events need no new stamp: their
transition `at` is already the controller's clock.

Tests: `tests/unit/test_v09_g0_clock_skew.py` (estimator; **+5 s / −5 s / +1 h agent clock → identical
heartbeat lags**; a browser 2.75 s behind corrected; the old measure shown to be skewed; unmatched
changes; frame filtering; job.state correction; verdict matrix; controller `recv_at` independent of the
agent's `observed_at`), `tests/component/agent/test_v09_g0_clock_skew_stream.py` (real HTTPS controller +
Postgres + agent session: `/v1/clock` 401 without a user, offset ≈ 0 within bound on one host; an agent

## Item 3 — T-8b: live numbers exclude retries (D210 item 5) — done

`events.JobStateSamples.add`: a transition into a state the job already entered (a retry: `running -> queued ->
running`) is a **re-entry**: never a latency sample (the page probe keeps only the first display of each state, so
it cannot be timed) and never used to supersede an unshown state; counted in `revisited`, its job in
`retried_jobs`; the events results report `job_state_revisited` and `job_state_retried_jobs`. Jobs without a
retry give exactly the old samples. The tester strict xfail
`tests/unit/test_v08_g7_tester_r2_unit.py::test_t8b_a_revisited_state_shown_30_s_late_fails` now passes (marker
removed, assertion untouched). Tests: `tests/unit/test_v09_g0_retry_samples.py` (retry counted not timed, no-retry
unchanged, a re-entry never supersedes, a state seen only via a re-entry is missed, counts add up).

## Item 4 — THREAT_MODEL: `MIN_KNOWN_CHARS = 8` (D210 item 2) — done

A note after the §5.9 B9 table: the e2e leak gate searches credential **shapes** at any length and **known values**
only from 8 characters (shorter needles match ordinary page text: noise, meaningless findings). Passwords are
>= 8 already and tokens have shapes, so nothing is lost for them; a 4-7 byte job secret would not be caught by
value - covered by design (secret values are write-only; `GET /v1/secrets` returns names and timestamps). A
property of the test oracle, not of product redaction (LF-I4/WS-I3 unaffected). No new §5 row (no new threat);
`scripts/threat_model_check.py` still exits 0.
