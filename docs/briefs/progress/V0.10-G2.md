## Decisions (implementer; Lead to confirm)
- **I1 - package imports only `common`.** `meshforge.workqueue` is a new top-level package (D262) with its own
  import-linter contract (`workqueue imports only common`); controller may import it, agent / gpu_service / sdk /
  cli / bench / common forbid it (`tests/unit/_import_guard.py` ALLOWED_DEPS updated). Stronger than "no import of
  jobs/planner": it imports nothing of the controller at all.
- **I2 - tables on their own `MetaData`** (`workqueue/tables.py`, SQLAlchemy Core `Table`s, same naming convention
  - a unit test holds the copy equal to `controller.store.base.NAMING_CONVENTION`). Alembic `env.py` copies
  `Base.metadata` + the work-queue metadata into one combined `MetaData` (a *list* of targets loses the naming
  convention for `op.drop_constraint` in old migrations - the downgrade chain broke that way). `alembic check`
  covers both. `Base.metadata` itself is unchanged (its registry unit test still lists only controller tables).
- **I3 - `bigint` identity ids**, not prefixed ULIDs: rows are internal, created in bulk (10 000 items in one
  statement), referenced from outside as `(item_id, seq)` (fencing) plus `lease_id` in grants. Ids are not secrets;
  ownership is checked by holder.
- **I4 - holder + site.** A lease has an opaque `holder` (who may renew/complete/fail it, e.g. a lane attempt) and
  an opaque `site` (where it runs, e.g. a node; defaults to the holder). Speculation refuses the same site/holder;
  `failed_sites` makes `lease_next` hand out items that did not fail at this site first (D267c "retry on a
  different node when possible"), and `max_failed_sites` (policy) fails an item failing at N distinct sites
  (Mode 3: 2).
- **I5 - item / lease states.** Item `pending -> leased -> done | failed`. Lease `live -> completed | failed |
  expired | released | superseded`. Queue `open -> done | failed | cancelled`. A late result from an `expired` or
  `released` lease **commits** if the item is not done (ADR-0015 / D267b); from a `failed` lease, a wrong holder,
  an unknown seq, a failed item or a closed queue it is `Fenced(reason)`. A result for a done item is
  `AlreadyDone(winner_seq, winner_digest)` (`.own` = replay of the winner) - also after the queue is done, so
  replays get acked. A wrong holder never learns the winner digest.
- **I6 - attempts.** `fail` always counts; expiry counts only with policy `count_expiry` (default **off**: an expiry
  usually means a partitioned worker, not a bad item); `release`/`release_holder` never count (D267d). Item fails
  at `max_attempts`, on a non-retryable failure, or at `max_failed_sites`; the queue then becomes `failed` in the
  same transaction and every live lease is released (returned so the caller can cancel the holders).
- **I7 - at most two live leases** = one ordinary + one speculative, enforced by the core *and* by the partial
  unique index `ix_work_lease_live_slot (item_id, speculative) WHERE state = 'live'`. A copy is issued only while
  exactly one ordinary lease is live, held elsewhere, and no item is pending. The budget
  `ceil(speculative_max_frac * items)` counts **items**, not copies (an item whose copy ended may get another).
- **I8 - locking.** Order is queue row then items ascending. Pull = `FOR KEY SHARE` on the queue +
  `FOR UPDATE SKIP LOCKED ORDER BY idx` (two passes: not-failed-here first). complete/speculate/release_holder =
  `FOR NO KEY UPDATE` (serialises commits of one queue -> the last commit sees `done_count = item_count` in its own
  transaction and gets `queue_done=True`). fail/expire_due/cancel = `FOR UPDATE` (conflicts with pulls, so a close
  can never overlap a grant - found and fixed with a test, commit 827d5a6). renew/release(one) = `FOR KEY SHARE`.
- **I9 - time from the caller.** Every mutating op takes an aware `now` (single controller clock); deadlines are
  `now + timeout` (policy, or a per-call `timeout_s` override, e.g. D267b `max(60 s, 4 x p50)`).
- **I10 - no hypothesis** (pypi unreachable; §7 Q5 open): seeded in-house model test (D276 fallback).

  core purity, naming convention, state CHECK/enum parity, migration frozen states).
- Component (real PostgreSQL 16 testcontainer):
  - `tests/component/workqueue/test_v010_g2_store.py` (26): SKIP LOCKED (verified to time out without SKIP LOCKED),
    order + payloads, site preference, idempotent completion, last-commit `queue_done`, fencing, 10 rounds of
    concurrent original-vs-copy completion (exactly one commit), expiry + late commit + supersede, renew vs expiry,
    counted expiry failing the queue, speculation rules + DB index refusing a 3rd live lease, release in the caller's
    transaction (rollback keeps leases), failure on two sites, non-retryable, close waits for an open pull
    (verified to fail with NO KEY UPDATE), cancel, single release, budget counts items, restart (new engine).
  - `test_v010_g2_stress.py`: 16 pullers x 10 000 items, crashing (0.4 %), failing (0.6 %), slow > timeout (0.6 %)
    workers, expiry sweeper every 50 ms, tail speculation, live-lease monitor. Typical run:
    `10000 items, 16 pullers, 47 s, grants=10158, expired=110, abandoned=25, slow=64, failed=48,
    already_done=85, fenced=0, speculated=2, peak_live=2`; every item done, exactly one completed lease per item,
    digest = winner, done_count = 10000, 0 live leases.
  - `test_v010_g2_model.py`: 24 seeds x 150 random steps (lease/renew/complete/fail/expire/release/speculate/cancel,
    incl. wrong holder and unknown seq), store vs pure-core model, every outcome and every item/lease row compared
    after every step; asserts every outcome kind is reached.
