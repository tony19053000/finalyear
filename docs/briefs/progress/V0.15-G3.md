  * held-out slice = `planner.calibration.split_holdout` (D329) over the dataset's decisions (every row

  * the gate refits the **shipped configuration** on the other rows (no re-selection), so every shipped
    learned member has a judged counterpart (a re-selection could pick a different algorithm and leave
    the shipped one unjudged); the price is mild optimism (config chosen on all rows) - documented;

    effective log error > calibration + 0.05), `worse_than_reference` (> reference x 1.05),
    `not_better` (no learned term beats calibration by > `ml_min_effect_log` 0.02 - the brief's "noise
    -> rejected `not_better`");
  * a training run where **every** term is `insufficient_data` is not gated and writes no set (like the

## Merge with main (G4 = 0.15.6 + b8e52dcf) - merge decisions

   (3 src uses: dispatch.py, dispatcher.py, predictor.py; docs). G3's registry-side `ml/source.ModelSource` keeps its
   name (every G3 test incl. the tester r2 file imports it). `StaticModelSource` kept (G4 tests import it).
2. **One server attribute:** `server.ml_source: RegistryMlInputSource` (new, `ml/source.py`) - the dispatcher's
   `MlInputSource`. Per tick: `ModelSource.refresh()` (one query) and, when the loaded set object changes,
   `ml_input(SetPredictor(set), max_interval_log=cfg.planner.ml_max_interval_log,
   budget_ms=cfg.planner.ml_predict_budget_ms)` in a worker thread (warm-up); None from `ml_input` = no model
   (cached per set, so a failing warm-up logs once). G3's `server.ml_models` **dropped**; API + retrainer get the
   `ModelSource` as `ml_source.models`. Tester r1 runtime / without-extra tests: `runtime.ml_models` ->
   `runtime.ml_source.models` (mechanical rename only).
3. **`SetPredictor`** (TermPredictor over a `LoadedSet`): `predictor_version` = set version; answer
   `model_version` = member artefact version; `has_model` False for an `algorithm none` member, a term not in the
   set, **and a member whose conformal q is infinite** (it could never pass the width test; asking it would give
   non-finite `lo/hi`, which G4's `_valid` treats as a malformed answer -> whole-decision fallback). Per query
   `ArtefactError` -> `PredictorFailed("artefact_error:<reason>")`, wrong width -> `PredictorFailed("malformed_features")`
   (D363). Features passed raw (pre-prep): `LoadedModel.predict` applies the artefact's own prep; warm-up uses G4's
   raw NUMERIC_FEATURES-width rows.
4. **FEATURE_VERSION 2:** decode / `_probe` already read `schema.FEATURE_VERSION` / `NUMERIC_FEATURES` (no list
   change in G4, only the version). `ModelSource._load` skips a set whose `feature_version` != the code's: one
   `controller.planner.ml_set_stale_features` **info** line, `unavailable = "stale_feature_version"`, never loaded,
   never retried, no error lines; the planner keeps calibration. A configured pin / API pin of a stale set is
   still refused (load fails) - unchanged D306-style strictness.
5. **Settings:** one `ml_max_interval_log` (G4's, ge 0 / le 20; description mentions the gate); G3's copy removed.
6. **Purity test** file list = union (`SERVING`, `registry.py`, `source.py`, `predictor.py`).
