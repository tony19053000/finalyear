  **Gate design notes (for Lead review):**
  * held-out slice = `planner.calibration.split_holdout` (D329) over the dataset's decisions (every row
    of a decision on one side) - reused, not copied;
  * the gate refits the **shipped configuration** on the other rows (no re-selection), so every shipped
    learned member has a judged counterpart (a re-selection could pick a different algorithm and leave
    the shipped one unjudged); the price is mild optimism (config chosen on all rows) - documented;
  * the judged models go through artefact bytes -> `serve.load_model` (the serve path itself is gated);
  * judged on **effective** log error = model where in distribution and `2q <= ml_max_interval_log`,
    else calibration (what G4's precedence will deliver);
  * reference = pinned set, else active set, as stored (like D306 judges the active calibration as
    is); a reference member that cannot be loaded -> calibration for that term, recorded;
  * rules, first failure is the reason: `too_few_held_out` (< 20 held-out rows for a shipped learned
    term), `coverage` (pooled < 80 %, family >= 20 rows < 70 %), `family_tolerance` (family >= 5 rows:
    effective log error > calibration + 0.05), `worse_than_reference` (> reference x 1.05),
    `not_better` (no learned term beats calibration by > `ml_min_effect_log` 0.02 - the brief's "noise
    -> rejected `not_better`");
  * a training run where **every** term is `insufficient_data` is not gated and writes no set (like the
    calibration's `too_few_runs`).
