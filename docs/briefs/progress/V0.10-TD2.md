## Item 1 - audit: every path where job / agent text reaches an operator

## Design (implementer decisions - for the Lead)
- **D1 (D-1) Extended the one function, no sibling.** Every caller of `strip_terminal_controls` (only `clean_tail`
  and now `clean_detail` / `_display_safe`) wants spoofing removed too, and two near-identical functions would
  drift. The new characters are added to the `str.translate` drop table: no regex change, so linearity is
  untouched (the escape pattern's bodies still stop at every introducer; the bidi / zero-width chars are not
  introducers). Kept (not dropped): U+2028/U+2029, NBSP, soft hyphen, RTL *letters*. **Trade-off stated in the
  module docstring:** a ZWJ emoji sequence loses its joiner (a family emoji shows as separate people) and ZWNJ used
  for Persian / Indic shaping goes; text stays readable, only rendering changes. The tester's
  `test_ordinary_unicode_is_untouched` ZWJ case was changed to the joiner-less sequence (commented), and its strict
  xfail `test_bidi_override_is_removed` is now a normal test.
- **D2 Workload params / condition measured: cleaned, not refused (deviation from D22's "refused, never cleaned").**
  These are free-form JSON documents, `params_json` written by the *job*; a refused `AttemptStatus` is dropped and
  acked (dispatcher `controller.jobs.status_rejected`), i.e. the attempt's **terminal report would be lost** over a
  benchmark string. Cleaning keeps the report and makes the stored document display-safe. Two keys that clean to
  the same text keep the later value (JSON's own repeated-key rule). Strings in legitimate params never contain
  controls, so ML features are unaffected.
- **D3 CLI left unchanged.** The CLI never prints raw server text except job logs: every other path already maps
  each non-printable char to a space (no control can reach the TTY - inert `[31m` residue at most, and the
  controller now strips sequences whole before storing). Changing the CLI flatteners would also change the
  spellings `secret_commands` registers for masking (T-9: `\r\n` would flatten to one space instead of two) - risk
  without a security gain. **Question for the Lead (not implemented):** should `compute logs` / `compute run -f`
  strip controls **when stdout is a TTY** (keeping raw bytes for pipes / `> file`, plus `--raw`)? Today they are
  raw by contract ("the workload's own bytes", `cli/follow.py`), like `docker logs` / `kubectl logs`; colours and
  progress bars of the user's own job would be lost. A UX decision, so left for the team.
- **D4 (D-2) Stray files are removed, stray directories are a skip.** The folder `<cache>/<sha256[:16]>/` is this
  module's own (named after the wheel's hash; nothing else writes there). A stray file would be offered to the
  agents' `uv` via `find_links` (another wheel could be installed in place of the locked one) and would change
  their env hash; a *skip* would silently disable every Mode 3 cluster test on that machine. So files / symlinks
  are unlinked (a link's target is never touched), on both the hit and the download path. A stray **directory** is
  not deleted recursively (that would be deleting someone's data on a guess) - the caller gets a skip reason
  naming it.
- **D5 (D-3) `.part` via `tempfile.mkstemp(dir=<cache root>)`** - beside the folder as before (the folder only
  ever holds the wheel; same filesystem, so `os.replace` stays atomic), unique per call. `mkstemp` creates 0600, so
  the file is `chmod 0644` before the move (a lab cache may be shared). The `.part` is unlinked on every failure
  path but **not** after a successful move (the name is free then and could, in principle, be another call's).
- **D6 Hard failure on a bad fresh download.** New `WheelDownloadMismatchError` - deliberately **not** a subclass
  of `WheelhouseUnavailableError`, so `except WheelhouseUnavailableError: skip` can never swallow it. The cluster
  conftest's `numpy_wheelhouse` fixture turns it into `pytest.fail(..., pytrace=False)` with the URL, expected
  sha prefix / size and bytes received. A corrupt *cached* wheel is still re-downloaded (and only a mismatching
  re-download fails). The two existing "does not match" tests now expect the new error.
