# V1.0 G11 - D457: `compute run --local` finds the installed system agent

Source: lab chat `origin/lab/chat:lab/chat/20261112-050034-L1-to-LEAD.md` and
`20261112-051223-L1-to-LEAD.md` (L1, Linux .deb). Release target v0.17.3. This blocked demo 01 and the
Local act of demo 04.

## Finding

On a packaged Linux install, `compute run --local` exited 4 with "this laptop has no MeshForge agent
identity yet". The planner's Local candidate was also missing: the CLI sends `submitter_node_id` only when
it can find the local node.

## Cause

The `.deb` system agent keeps its identity in `/var/lib/meshforge/identity/node.json`, inside
`/var/lib/meshforge` (`0750 meshforge:meshforge`). The CLI user cannot read it, and should not be able to,
because `node.key` sits next to it. The CLI looked only in the user's own data dir. Windows has the same
gap: `%ProgramData%\MeshForge\identity` is restricted to the service, SYSTEM and Administrators.

## Fix

1. **The agent publishes a public node record** (new `agent/public_node.py`, wired in `agent/runtime.py`).
   The installed service (`MESHFORGE_INSTALL_MODE=system`) writes `node-id.json` at every start, and again
   after a key rotation through the renewer's `on_renewed` hook. The record holds
   `{"format": 1, "node_id", "key_fingerprint_sha256", "agent_version", "written_at"}`. These are public
   facts only: no key, certificate, session epoch or private path. The write is atomic (temp file in the
   same folder, `fchmod 0644` so the unit's `UMask=0077` cannot narrow it, fsync, `os.replace`, dir fsync).
   If the folder is missing or not writable, the agent logs the warning `agent.public_node.not_written`
   with the fix and keeps running. The agent never creates the folder itself, so it cannot create one with
   the wrong owner or ACL. User-mode agents publish nothing.
2. **Where the record lives** (`common/local_node.system_public_dir`):
   * Linux: `/var/lib/meshforge-public/node-id.json`. This is a **sibling** of the state dir, not
     `/var/lib/meshforge/public`. A child folder would need `o+x` on `/var/lib/meshforge`, which makes every
     other folder under it reachable by path. The state dir stays `0750`.
   * Windows: `%ProgramData%\MeshForge\public\node-id.json`. Windows grants "bypass traverse checking" to
     everyone, so the restricted parent folder does not block reading this file.
3. **The CLI resolves the local node** (`common/local_node.resolve_local_node`,
   `cli/job_commands._own_node`). It checks the user-mode identity in the CLI's own data dir first, then the
   system public record. A private `node.json` that is missing or unreadable (`PermissionError`) is skipped.
   Only `node.json` is ever opened there, with no listing and never the key. If nothing usable is found, the
   most informative error is reported: a garbled file (CONFIG_ERROR) beats "no identity" (NOT_FOUND), and
   the NOT_FOUND message names both fixes. On POSIX the record is refused if it is a symlink, not a regular
   file, or if the file or its folder is group- or world-writable, because anyone who could rewrite it
   would decide where `--local` jobs run.
4. **Seeding (D109)** happens only when the local node came from the CLI's own data dir. The system
   service's cache is not the CLI's cache. Seeding into `~/.local/share/meshforge/cas` would have sent
   `seeded: true` for a cache the agent never reads. With the system agent, the CLI notes "not seeded (the
   installed agent service keeps its own cache)".
5. **Controller: no change needed.** `placement.local` is only a label (`job_routes`: mode `local`), and
   the Local candidate is `submitter_node_id` (`planner`, `ml/features`). Both are now filled from the same
   resolver, so `--local` and the planner's Local candidate use the same "local node".
6. **Packaging.**
   * `.deb` postinst creates `/var/lib/meshforge-public` as `0755 meshforge:meshforge`. On upgrade it runs
     `chown` and `chmod go-w`, and never loosens a stricter mode.
   * The unit adds `-/var/lib/meshforge-public` to `ReadWritePaths`. The `-` means a missing folder costs
     only `--local`.
   * postrm purge removes the folder.
   * Windows: `MachineLayout.public_dir` is part of `folders`, so `install` creates it on install and on
     every upgrade. Its ACL in `acl_plan` is SYSTEM and Administrators full, the service modify, and
     `BUILTIN\Users` (S-1-5-32-545) read. Users get no other folder.

Not done (not needed): a controller lookup by hostname or fingerprint. The public record is unambiguous;
a hostname match could pick a revoked or same-named node.

## Tests

* `tests/unit/cli/test_v1_0_g11_local_node_resolution.py`: resolution order (user wins, falls back to
  system), unreadable private dir skipped, only `node.json` opened, NOT_FOUND names both fixes, garbled
  public record gives CONFIG_ERROR (7 cases), garbled user identity falls back to a good record or else
  reports the garbled file, shared-writable file or folder refused, symlink refused, paths per platform,
  Linux public dir outside `/var/lib/meshforge`, packaging modes, CLI `_own_node` (system agent found;
  none gives exit 4), seeding skipped for the system agent.
* `tests/unit/agent/test_v1_0_g11_public_node.py`: record has public facts only (no key PEM, path or
  epoch), `0644` in a `0755` dir under umask 0077, no temp file left, failed replace keeps the old record,
  user mode writes nothing, system mode writes and the CLI resolves it, missing folder logged and never
  created, runtime wiring (start and rotation), Windows ACL (Users read on `public` only), Windows path
  matches the CLI lookup.
* Updated: `test_winservice.py` and `test_v017_g4_windows_pure.py` (new folder); `test_v017_g1_deb_package.py`
  (component, ReadWritePaths); two CLI tests now patch `_own_node`.

## Lab re-run (L1, after installing the v0.17.3 .deb)

```
ls -ld /var/lib/meshforge /var/lib/meshforge-public   # drwxr-x--- meshforge ... / drwxr-xr-x meshforge ...
cat /var/lib/meshforge-public/node-id.json            # {"agent_version": "0.17.3", ..., "node_id": "<L1 id>"}
stat -c '%a %U' /var/lib/meshforge-public/node-id.json  # 644 meshforge
compute nodes | grep -i l1                            # same node id
scripts/demo/01-local.sh                              # job placed on L1, exit 0
```

On Windows, as a non-admin user: `type C:\ProgramData\MeshForge\public\node-id.json`, then run
`compute run --local`.
