  for evaluations is a follow-up if lab datasets make folds slow.

  depend on machine load; latency is criterion 3's job.

  brief's wording, same intent (no leak).
- **Fold per-term metrics are the pure model's** (y_hat on all held-out rows) plus `usable_rate`; the
  report has no "effective" (ML-or-calibration) MALE per term - the regret rows already measure the
  effective planner.
- **G3 tests edited** (they pinned `regret == "pending_g4"` as the new value, which D371 retires):
  `test_v015_g3_fit_gate.py`, `test_v015_g3_tester_r1_gate.py`, `test_v015_g3_registry_pg.py` now assert

## Fix round 1 (reviewer REQUEST_CHANGES B1/B2 + non-blocking, tester r1 pending tests)
- **B1 - one training child at a time.** `ml/child.TRAINING_GUARD` (`TrainingGuard`: one `asyncio.Lock` per
  event loop in a `WeakKeyDictionary`, so a module-level guard never binds to a dead loop) is held around the
  child call by `folds.train_fold` (`guard=` parameter, default the shared one) **and** `MlRetrainer._retrain`
  (logs `controller.ml.retrain_waits_for_training_child` when it has to wait). Only the child is guarded (the
  dataset build / reads / regret check are not CPU-heavy children). The retrain's wait is not part of
  `ml_retrain_timeout_s`; a fold's wait is part of the eval budget (below). Behavioural test: a fold run + a
  retrain run started together through `asyncio.gather` with a counting fake child -> peak 1; mutation
  "retrain skips the guard" fails it (checked by hand), and a guardless control run shows peak 2.
- **B2 - total fold budget.** `PlannerSettings.ml_eval_timeout_s` (default `common.ml_eval.
  DEFAULT_ML_EVAL_TIMEOUT_S` = 3000 s, 1..86 400). `FoldMlInputs._folds`: a monotonic deadline; each fold
  runs under `asyncio.timeout(remaining)` (covers the guard wait + the child + the read) with child timeout
  `min(ml_retrain_timeout_s, remaining)`; when the deadline fires mid-fold the cancel kills the child and the
  fold gets `eval_budget_exhausted: stopped, ...`; every family left gets `eval_budget_exhausted: not trained,
  ...` (source `none`, input None -> its ML rows count `no_fold_model`). New shared `folds.budget_exhausted`.
  CLI `_EVAL_TIMEOUT_S` = `DEFAULT_ML_EVAL_TIMEOUT_S + EVAL_REPLAY_MARGIN_S` (600) = 3600 s, from the new
  `meshforge/common/ml_eval.py` (the CLI may import only `common`).
- **Non-blocking:** `run_child` on cancel kills **and reaps** (`await asyncio.shield(proc.wait())`; test with
  a real `sleep` child: `returncode` set before the cancel reaches the caller; mutation without the reap
  fails it). New `child.scratch_dir` (mkdtemp + rmtree via `asyncio.to_thread`, shielded) replaces
  `tempfile.TemporaryDirectory` in the evaluator **and** the retrain. The report's `ml` block gains `until`
  (the folds' cut-off, None without folds) + `EvalMlOut.until` (OpenAPI + `schema.d.ts` regenerated by
  `npm run gen:api`); Markdown prints "fold models trained on runs finished by ..." under the ML status.
  `ml_model_routes.MlSetDetailOut.gate` doc string fixed (attribute doc strings are not in OpenAPI, so no
  G5b conflict; D371 is G5a's).
