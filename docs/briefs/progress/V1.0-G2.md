## What exists (all under `scripts/eval/`, package `evalkit`)
- `run_campaign.py` - the live matrix (family x size x arm x rep) over the real REST API (`compute`'s own client
  and upload code); block randomisation grouped by controller profile; per-run workload seeds; resumable
  (`runs.jsonl` append-only + fsync, idempotency keys per (spec digest, run, copy) -> no duplicate job after a
  resume); records SHA / package version / inventory / link per session (D406). `--plan` prints the schedule.
- `evalkit/arms.py` - B0-B6 (D416) + A5/A6 (D418) and their controller profiles (`calibrated`, `uncalibrated`,
  `ml`, `ml_no_mode3`, `ml_no_mode1`), rendered as TOML and as a systemd EnvironmentFile.
- `analyze.py` - raw -> `analysis.json` (canonical JSON) + `tables/*.csv` + `SHA256SUMS`; reuses
  `planner_eval.core.best_median/group_regret`, `bench.stats`, `ml.train.metrics.paired_verdict` (D357 rules);
  A1-A4 / RQ2 from the existing evaluator and `ml compare --ablations` reports (`evalkit/offline.py`); A7 when one
  campaign per link is given.
- `make_report.py` - Markdown report + 5 SVG figures (matplotlib, `evaluation` dependency group, fixed style).
  "Not evidence" banner for smoke / < 10 reps / incomplete / mixed builds / not the release packages.
- `check_sample.py` + `sample/raw` (committed synthetic noise campaign, 36 runs) + `sample/expected.sha256`
  (11 output hashes, figures included) -> CI job `eval-repro`.
- src: `[controller.planner] disabled_modes` (`mode1` / `mode3`; A5/A6) through settings -> `PlannerConfig` ->
  candidate generator; replay key written only when non-empty, plan digest unchanged without it.
- `lab/eval_profile.sh` - the `--profile-hook` for the installed Linux controller (systemd drop-in with the
  profile's EnvironmentFile + restart; `--clear`; `--check`).
