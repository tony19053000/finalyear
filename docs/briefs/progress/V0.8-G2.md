## Fix round 1 (implementer, 2026-10-16; D189)

Every `it.fails` / `xfail` of tester r1 is removed and its assertion kept.
- **T-2 (major), fixed:** `RequireSession` keeps the shell whenever session data exists. A failed session re-check (controller restarting, network blip) no longer unmounts the shell or its event stream. Only a first load with no session yet shows the full-page "Cannot reach the controller". The stream recovers by itself: backoff, then reconnect, then `resync` (new epoch) refetches everything, including the session.
  - Tests: tester vitest T-2 (now `it`); new `shell.test.tsx` "controller restart (T-2)" (shell kept, header says reconnecting, goes live again on its own); tester e2e `test_T2_...` (xfail removed).
  - Two changes to the T-2 e2e:
    - (a) It runs with `fabric_options={"record_links": True}` through a new `fabric_options` fixture in `tests/e2e/conftest.py`. The harness restarts the controller on a *new ephemeral port*, which no page can follow; a real controller keeps its configured port, and the stable REST proxy models that.
    - (b) The controller now stays down 10 s (`kill_controller`, wait for `reconnecting`, check the shell is still there, then restart). As first written, the restart was faster than the session re-check, and the test passed even without the fix. All three T-2 tests were checked to fail without the fix and pass with it.
- **T-1, fixed:** `hello`/`resync` frames after the greeting are control frames, never app events. A `resync` resets the position and calls `onResync(reason)`. A `hello` of the same epoch is ignored; a `hello` of a new epoch counts as a resync with reason `epoch`. Tests: tester T-1 (now `it`) + 2 new tests in `eventStream.test.ts`.
- **T-3, fixed (backend, `src/meshforge/controller/api/event_routes.py` only):**
  - Root cause: uvicorn's sans-I/O WebSocket protocol, the one `uvicorn[standard]` uses, silently drops `websocket.accept` when the client's transport is already closing. It then refuses our first `send` with `RuntimeError("Expected ASGI message 'websocket.accept' ...")`, which it logs as "Exception in ASGI application".
  - Fix: `_send_first()` sends the hello frame. A `RuntimeError` there can only be that refusal, because Starlette's state is `CONNECTED` right after `accept()`. It is logged at info as `controller.events.client_gone_in_handshake` and re-raised as uvicorn's own `ClientDisconnected`, which uvicorn ends quietly (other servers get `WebSocketDisconnect`, caught as a normal disconnect).
  - Deterministic test `tests/unit/controller/test_v08_g2_events_handshake_abort.py` (2): it drives the REAL uvicorn sans-I/O protocol object with a fake transport that is already closing when the route runs. It asserts no "Exception in ASGI application", no ERROR log, no 500, and the follower unsubscribed. It fails without the fix. A second test fails if uvicorn ever stops dropping the accept, which would make the workaround dead code.
  - The tester's e2e `test_T3_...` has its xfail removed and passes.
- **Found and fixed while running the e2e tier repeatedly:**
  - (1) pytest-playwright's session-scoped `playwright` fixture kept the sync API's event loop running after the e2e tests, so every later `asyncio` test in the same run failed. This would have broken a plain full `pytest` run. `tests/e2e/conftest.py` now overrides `playwright`/`browser_type` (and `chromium_installed`) at module scope.
  - (2) The reduced-motion CSS used the `transition-duration: 0.01ms` trick. With the default `transition-property: all`, that turned every colour change into a one-frame transition: axe intermittently read dark text on the light theme right after the switch. It is now `transition: none; animation: none`.
  - (3) A logout race: the controller's 4401 stream close could land after the DELETE had settled but before its navigation ran. The page then said "Your session ended" instead of "You are signed out". The Header now calls `onSigningOut()` before the request, and the shell ignores session-end signals from then on. The new vitest guards the flow but cannot reproduce the browser timing.
  - (4) The tester files had ruff errors (E501/N802/C416). Fixed lint-only, with `# noqa` on JS/test-data lines and T-id names and `list()` for C416; no assertion changed.
