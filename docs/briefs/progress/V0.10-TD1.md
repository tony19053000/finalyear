## Design (implementer decisions - for the Lead)
- **T1 (item 2) Pure ledger check.** The rules moved to `tests/_support/mf_split_ledger.py::assert_exactly_once(leases,
  records, items)` (no psutil / DB import, so a unit test can feed it rows); `mf_split_cluster.check_exactly_once`
  reads the same two queries and calls it. New rule: **no lease in state `live`** once the job has ended (message
  names chunk, seq, holder). Unit test `tests/unit/test_v010_td1_split_ledger.py`: clean ledger passes; a live
  speculative copy that even has a record (so every *old* rule holds) fails; a live lease without a record fails on
  the live rule; six other broken ledgers still fail. Mutation-checked: with the new assert disabled the two
  live-lease tests fail.
- **T2 (item 1) What was folded in.** G4 (`lanes`, `r1`, `fix2`, `r3`), G5 (`combine`, `r1`, `r2`) and G8
  (`split_campaign`) no longer define TIMING / EXEC / TERMINAL, `_fabric`, `_upload`, `_job`, `_wait`, `_rows`,
  `_sql`, `_output`, `_combines`, `_runs`, nor the hand-written `compute get` env; and the G4 tester files no
  longer import helpers from another test module (`test_v10_g4_lanes_cluster`). Shared module gained:
  `split_fabric(lease_s=, controller_jobs=, agent_extra=, wheelhouse=)`, `submit(submitter=)`, `combines`,
  `fetch_output` (path-returning; `output_files` builds on it), `live_leases`, `campaign_runs`. File-specific
  pieces (workload scripts, manifests, `_parts`, `_read_items`, `_expected*`, G5 r1's 2-agent `_fabric` that r2
  reuses) stay local. `test_v010_mode3.py` also dropped its own `_live_leases` / `_campaign_runs`.
- **T3 (item 1) Deliberate, small behaviour differences** (all stronger or inert):
  - the G4 `_ledger` checks (lanes + r1) now call `check_exactly_once` (adds chunk-record, item-span, lease-set and
    no-live-lease rules) plus the original chunk-count assertion;
  - shared `wait_job` polls every 0.2 s (was 0.1 s in the G4/G5 copies); upload timeout 60 s (was 30 s);
  - chunk parts fetched in G4 r1 are now sha256-checked (`fetch_output`), as the other files already did;
  - agents get `SSL_CERT_FILE=certifi` (the shared `split_fabric` default) - only uv's index access reads it; these
    jobs have no requirements;
  - `combines()` is sorted by fencing token everywhere (G5 r1 used attempt order; only `len()` / `[0]` of a single
    combine were read there);
  - lease timeouts kept per file: 10 s (G4/G5), 5 s (G4 r1 partition test), 60 s (G8) via `lease_s`.
- **T4 (item 3) Wheelhouse.** `tests/_support/mf_wheelhouse.py` + session fixture `numpy_wheelhouse`
  (`tests/cluster/conftest.py`). The wheel is the one **`uv.lock`** lists for `NUMPY_REQUIREMENT`'s version, chosen
  by `packaging.tags.sys_tags()` priority (the agents run this interpreter: subprocess runtime). Cache:
  `$MESHFORGE_TEST_WHEELHOUSE` or `$XDG_CACHE_HOME/meshforge-tests/wheelhouse/<sha256[:16]>/<wheel>` - one folder per
  wheel, holding only that file (the agent's env hash covers the folder's file names + sizes). A cached wheel is
  used only if size + sha256 match the lock (no network on a hit). On a miss: download once over HTTPS with the
  public roots (`certifi`; the test process's `SSL_CERT_FILE` is the fabric CA), verify, `os.replace` into place;
  the `.part` file lives beside the folder. Neither cache nor network -> `pytest.skip` with the reason (and how to
  pre-fill). `split_fabric(wheelhouse=...)` sets `[agent.envs] find_links` + `no_index = true` - the product's own
  offline-lab setting, so the agents never contact an index. Used by `test_v010_mode3.py` and
  `test_v010_g9_tester_failures.py` (same numpy job); their `index_reachable` skip is gone (helper deleted).
  Unit test `tests/unit/test_v010_td1_wheelhouse.py` (lock parsing, tag choice, cache root, hit/miss, offline,
  tampered download, corrupt cache).
- **T5 (item 4) Where and what is stripped.** `meshforge/common/terminal_text.py::strip_terminal_controls`, called
  in `controller/split/records.py::clean_tail` - the single place a `ChunkResult.stderr_tail` becomes the stored
  `chunk_record.stderr_tail` (API `GET /v1/jobs/{id}/chunks/{index}/tries`, any CLI view). The controller does it, not only the
  agent: the agent and the job are untrusted. Removes whole CSI / OSC / DCS / SOS / PM / APC sequences (7-bit and
  8-bit introducers; OSC/DCS only when terminated - an unterminated one loses only its introducer, no text is
  hidden), the short `ESC x` forms, every other C0 except `\t` `\n`, DEL and C1. **Deviation from the literal ask:**
  CR is not just deleted - `\r\n` -> `\n` and a lone `\r` -> `\n` (progress bars stay readable; a CR can no longer
  overprint a line). Linear regex (no nested quantifiers; pathological inputs tested < 2 s). Placed in `common` so a
  future CLI view of other untrusted text can reuse it; `common` imports only stdlib here. Two G8 unit tests that
  pinned the old behaviour (`ESC[31m` kept; CRLF kept) were updated.
