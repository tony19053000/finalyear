Findings driving the work:
- Output paths: Rich consoles built in `app._out` **and** ad hoc in network/explain (via `cli._out`), ~70 raw
  `typer.echo` calls across 8 modules; data ls hand-formats sizes with its own `_size` (duplicate of
  `render.format_bytes`); `_printable` in fabric_commands duplicates `render._cell`.
- `--json` inconsistent (one line vs indented; server vs sorted key order), no `schema_version`, undocumented.
- Exit codes: auth and not-found are indistinguishable from any other refusal (all 1); wrong password = 1.
- Errors mostly say what + what to do already; a 404 says only "the controller refused the request (404): ...".
  No catch-all for an unexpected exception (Typer prints a Rich traceback; `show_locals` is off in Typer 0.27).

- No docs/CLI.md.
- Found while auditing: Typer's Rich help ate `[cli]` as a markup tag ("overrides  token and ..."); `tokens list`
  formatted `row['user']:<16`, which raises on a null user; `explain` did `int(ms)` on a server value; `data ls`
  did `int(item['size'])` - all three a traceback on odd REST data.

## Deliverables 2 + 4 (+ part of 5) - commit `a9a81b4`

- **One renderer**: `render.py` gained the output path - `show` (tables), `line` (plain line, control characters
  flattened, not Rich so nothing wraps), `note` (`compute: ...` on stderr), `fail` (error line, scrubbed with
  `common.redaction.scrub_text`), `emit_json`, `console()` (no markup/emoji/highlight, `no_color=NO_COLOR`), public
  `cell`/`table`. Every `typer.echo`/`Console` in the command modules now goes through it (`app._out`/`_echo_json`
  kept as thin wrappers). Exception: `compute logs` copies the workload's bytes verbatim (by design).
- **Exit codes**: new `cli/exits.py` - `CliExit` table, `exit_code_for` (the one FailureType mapping; `client.py`
  re-exports it), `job_exit_code` (moved from `outcome.py`, which re-exports). New: `AUTH = 3` (401/403, wrong
  password, CA fingerprint mismatch), `NOT_FOUND = 8`, `invalid_input` (400) -> 2. **Deviation from D178's
  numbers** (see DEVIATIONS below): unreachable stays 6 (D18), config stays 4, `run -f` keeps D76.
- **Lists as tables**: `tokens list` (+ KIND column, G1's `kind`), `secret list` (+ CREATED), `data ls|show`
  (`format_bytes` replaces a duplicate `_size`; PINNED yes/no), `fabric invites`. `network`/`explain` tables now use
  the shared ASCII style (were Unicode box, bad on `cmd.exe`).
- **`--json`**: all read commands through `emit_json` - one line, keys sorted, `schema_version: 1` (data/network/
  explain were indented). `data ls|show`, `network`, `explain` now use the shared `JsonOption`.
- **Errors**: client messages add what to do (unreachable -> `compute status`/address; timeout -> retry/`timeout_s`;
  403 -> ask an admin; 404 -> check the id; 503 -> retry). `status` reports `reachable: true` when only the node
  list was refused (401), exit 3.
- **Unexpected exceptions**: `main()` prints `internal error (TypeName) - this is a bug ...` and exits 1;
  `COMPUTE_DEBUG=1` re-raises. Typer pretty exceptions off.
- **Help**: `rich_markup_mode=None` on every Typer - plain ASCII help, `[cli]` shown literally.
- **Completion**: `add_completion=True` (`--install-completion`, `--show-completion`).
- **Existing tests changed (intended output changes only):** `test_cli_failures.py` (404 -> 8, 400 -> 2, json
  `schema_version`; two tests renamed to say so), `test_cli_node_id_validation_tester.py` (404 -> 8),
  `test_cli_render.py` x2 + `test_cli_render_scores.py` + `test_v06_g4_cli_network.py` (`schema_version` in the
  json), `test_v06_g4_tester_cli.py` (one line instead of indented; still sorted), `test_v07_g4_cli_login.py` x3
  (401, wrong password, `--ca`/`--fingerprint` mismatch -> 3), `test_v07_g6_secret_cli.py` (secret list is a table).
