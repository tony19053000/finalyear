## Deviations / decisions taken here (for Lead review)
- **Tabs, not a third section.** The Planner page had no tabs; the existing two sections became one tab so
  their tests and links (`?calibration=`, `?report=`) are unchanged.
- **Predictions are fetched once (limit 500 or 2000) and split by term / set in the browser**, not one request
  per term: the points carry `term` and `ml_model_version`, and the fallback table needs all terms anyway. The
  route's own `term` / `set` filters stay for the CLI / scripts.
- **Scatter axes**: a shared square log domain (min..max over predicted and actual) so y = x is the diagonal;
  points with a missing or zero value are counted ("not plotted") rather than clamped.
- **Fallback buckets**: `used`, each `reason`, `planned without a model set` (`ml_model_version` null) and
  `no reason recorded`.
- **Gate document is read tolerantly**: `regret` may be G3's `"pending_g4"` (shown as "not checked"), G5a's
  `{status, reason?, groups?, ...numbers}` (status + numbers + reason; unknown keys printed as they are), or junk
  ("—"). G5a's exact key names were not final when this was written; the generic rendering means no change is
  needed when G5a merges, but the Lead should glance at the line with a real G5a gate document.
- The OPERATIONS explain example was stale (`ML 12.00s -> 9.40s`); updated to the D373 text.
