## Design notes / deviations (for the reviewer)

1. **Generations.** `bench_run.generation` (extra column in 0024): bumped on every requeue (infra retry *or*
   owner pre-emption). Job key = `bench:<run_id>` for generation 0 (G3/G4 keys unchanged), else
   `bench:<run_id>:<g>` - the brief's `bench:<run_id>:<tries>` cannot work because a pre-emption keeps
   `tries` unchanged (D246) and would replay the old failed job. Fillers of generation g are numbered
   `g*k+1..g*k+k`, warm-ups `bench:<run>:warmup:<g>`. Old generations' jobs keep their campaign identity
   (`campaign_identities` falls back to the key, with `_link_orphans`'s owner/origin/node checks).
2. **Runner ownership = `started_at` set** (no new state besides `paused`): a created campaign stays manual
   (G3 submit) until `start`; after it manual submit is `409` with `error.reason = campaign_running`.
3. **`owner_preempted` is a new `FailureType`** (proto 24, CHECK constraints widened in 0024); it falls in the
   record's `infrastructure` class (no schema bump); `compute bench status` / the runner exclude it.
4. **Owner guard is a live rejection** (`RejectCode.BENCH_PAUSED = policy_bench_paused`, not static): a
   static policy code would fail a queued bench job `no_feasible_plan`. `owner_policy.refusal` checks
   `pause_benchmarks` only for `JobAsk(benchmark=True)` (agent re-check); the planner's static check never.
   The shadow plan (planner preference) ignores the guard like slot occupancy.
5. **`StartAttempt.benchmark`** (new proto field) tells the agent which attempts the guard may stop.
6. **CPU rule exclusions:** agent process tree + `containerd-shim*` trees + (while an attempt runs) the
   Windows WSL VM process `vmmem` (Docker Desktop jobs). Documented in OPERATIONS 0d3.
7. **Cool-down / budget use database time** (`now() - ended_at`, `now() - started_at`).
8. Infra retries settle in `BenchStore.sync()` (every read and every tick), not only in the runner, so the
   API never shows a runner-owned run `failed` that would be retried.
9. **Netem 0.3:** entries without `netem_expect` (G4 agents before an upgrade) keep the G4 rule (logged); six
   G4 tests updated (exact marker dicts gain `netem_expect`; direct `delete_netem` calls pass `expect=None`).
10. `kill_and_reap` is public in `conditions/base.py` (used by two modules), not `_kill_and_reap`.
