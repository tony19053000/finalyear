## Design (implementer decisions - for the Lead)
- **I1 Names.** The brief says `workqueue.core.speculate_candidates`; G2 already shipped
  `speculation_candidates` (eligibility: tail only, one live ordinary lease elsewhere, budget in items). G6 adds
  the *choice* next to it as `core.pick_speculation(candidates, site, now, copy_s, expected_s, factor,
  exclude)` - generic (sites/holders/items, no caller words; the package vocabulary test still passes) - and
  `core.predicted_remaining_s`. Nothing in G2's transitions or refusals changed.
- **I2 Remaining time without a progress signal.** `remaining = |expected - elapsed|`: on schedule it is the
  time left; overdue, the overdue time itself (the longer a chunk is late, the longer it is predicted to stay
  late). A copy is issued when `remaining > speculation_factor x copy` (D266's 1.5), largest remaining first
  (ties: lower chunk index). Consequences: a slow node's chunk at the tail is copied by a much faster idle node
  at once (heterogeneity); an equal-speed node's chunk is copied only once it is overdue by more than 1.5 x the
  idle node's time; a chunk about to finish on schedule is never copied.
- **I3 Expected times.** Per node, from **this job's committed chunks** on it: p50 of `(done_at - leased_at) /
  items` over the winning leases (SQL `percentile_cont`, one row per node - bounded memory), times the
  candidate chunk's item count (a ragged last chunk scales). A node with no committed chunk yet: the planner's
  `rate_items_s` for that node from the job's latest `dispatched` `plan_decision` row (the Local / Mode 1 rows
  of a split decision carry it, D265) + `chunk_overhead_s`. A node with neither: no copy to it and none of its
  chunks copied (no estimate, no duplicate work). `done_at` (commit time) instead of `ended_at`: a late commit
  of an expired lease keeps its expiry time as `ended_at`.
- **I4 Trigger and transaction.** Only in `ChunkStore.request`, after the lane got no fresh or re-granted chunk,
  when `pending == 0` and the lane asked for more than it holds: candidates (unlocked read), times, pick, then
  `wq.speculate` re-checks every rule under the queue (`FOR NO KEY UPDATE`) + item locks - a race (original
  committed, budget gone, chunk pending again) is a refusal -> `NoWork(wait)`, logged
  `controller.split.speculation_refused`. Lock order unchanged: the lane's attempt + job rows (`FOR SHARE`) are
  already held, work-queue rows second (ADR-0019 addendum). An idle lane re-asks every `wait_retry_s`, which is
  the re-evaluation period.
- **I5 Never the same node, nor a node where the chunk failed.** Core already refuses a copy at the original's
  site (and one lane per node, D267f); `pick_speculation` also skips items whose `failed_sites` contain the idle
  node and items in the lane's unverified-result cool-down (`avoid`).
- **I6 Cancel races.** The commit path already supersedes the other live lease and the service sends it
  `CancelChunk` (G4). G6 makes the agent honour a `CancelChunk` that arrives **before** its chunk ran (the grant
  was still in the lane's inbox: kept in a bounded `cancelled_early`, 64 entries; skipped with no result) and
  one that arrives while the chunk's inputs are staged (no process started). A loser whose process already
  ended still reports -> `already_done` (no second commit); a different verified digest -> the G5
  `nondeterministic_chunk` hook. Job cancel -> queue cancelled, every lease released, lanes cancelled (G4 path,
  unchanged).
- **I7 Lane LOST mid-speculation** needs no new code: `release_holder` in the LOST transaction releases the lost
  lane's lease (original or copy); the other one stays live and finishes; if the copy's lane is lost the chunk may
  be copied again later (the budget counts chunks, D277).
- **I8 Config over constants.** `planning.SPECULATIVE_MAX_FRAC` removed; `[controller.split]
  speculative_max_frac` (0.10, [0,1]) is frozen into the queue policy at queue creation (0 when
  `split.speculative: false`); `speculation_factor` (1.5, [1,100]); `chunk_overhead_s` reused for the planner
  fallback. OPERATIONS updated.
- **I9 Telemetry.** Both copies are already rows: `work_lease.speculative` + state `completed` (won) /
  `superseded` (lost) / `released`; G8's `chunk_record` reads them. New counters `SplitStats.speculated`,
  `copies_won`, `originals_won`; logs `controller.split.speculated` (elapsed/expected/remaining/copy seconds +
  sources) and `controller.split.speculation_resolved` (`winner`).
- **I10 Fake lanes** (`tests/_support/mf_fake_lanes.py`): `chunk_speed(grant)`, `honour_cancel`, `cancelled`,
  `speculative`, `timeline`; a `CancelChunk` or `CancelAttempt` now stops the chunk being "worked" (it used to
  finish it first - unlike the real agent).

  level (single lane, 1 chunk, cancel while in flight, lane ignoring cancel): transitions `running -> cancelled`. Per code
  reading the window exists only if a commit lands between the cancel request and the job row change; severity minor (a
  cancelled job ends CANCELLED with no live lease and no combine either way; cosmetic transition history).
- N2 (note): I2 boundary is strict (`remaining > 1.5 x copy`); exactly 1.5x is not copied - as documented.
- No defects found in: single-copy under races, budget exactness, failed-site/original-node/no-estimate exclusion,
