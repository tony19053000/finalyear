## Design (implementer decisions - for the Lead)
- **I1 "Combine owed" instead of an attempt row in the commit tx (D283 pin 1 vs pin 2).** `attempt.node_id` is
  NOT NULL and pin 2 wants placement through the dispatcher (feasibility, owner policies, "none feasible ->
  waits like a QUEUED job"), which only exists in the dispatch tick. So the last-commit transaction writes the
  durable fact - parts index + `RUNNING -> COLLECTING` - and a COLLECTING split job with a parts index and no
  live `role='combine'` attempt **owes a combine** (`split/combine.py::owed_jobs`). The service wakes the
  dispatcher in the same handler, so the combine is created on the next tick (ms later), in the dispatch
  transaction (advisory lock, `FOR UPDATE SKIP LOCKED`, next fencing token). Crash-safety is the same (the fact
  is committed with the last chunk); a lost/failed combine leads back to the same query.
- **I2 Placement.** `DispatchPlanner.decide_combine`: the planner's normal `plan()` for the job's manifest
  **without its GPU need** (`spec.combine_manifest`; the combine needs no GPU, also sent to the agent so
  plan_attempt agrees), restricted to `exec-split` nodes (agents of this version run lanes and combines; G4
  agents never shipped), soft exclusion of nodes where a combine failed/was lost (combine attempts only, not
  lanes); then submitter > most committed results (winning lease's `site`) > planner rank. Nothing feasible ->
  wait; every `exec-split` node statically rejected -> `FAILED(no_feasible_plan)`. No `plan_decision` row is
  written for a combine (the job's latest decision stays its Mode 3 plan for `compute explain`).
- **I3 Retry budget.** Combine failures other than `combine_error` follow `retry_verdict` with
  attempts = the job's combine attempts and the job's `retry.max_attempts`/backoff/`on_lost`; a retry keeps the
  job COLLECTING with `not_before` (no RETRYING arrow: that would re-plan lanes). Cancel while owed (no live
  attempt) -> CANCELLED at once (`request_cancel`) or at the next tick.
- **I4 Parts as plain blobs in the fetch token.** `FetchTokens.mint(blobs=...)` (bound `MAX_SPLIT_CHUNKS+1`),
  `FetchGrant.blobs` never treated as tree roots (a refused read stays O(roots), not O(10 000 parts)). Built-in
  combine token = parts index + parts only; script = + project tree + inputs.
- **I5 Extra error detail `invalid_json`** (a part file that is not one JSON document, NaN, 1e400, empty) - not in
  D283's list but needed; same COMBINE_ERROR type, not retried.
- **I6 Sizes.** Built-in raw write cap = `[agent.execution] max_written_bytes` (disk guard); the packed output
  cap = the attempt's upload quota (`max_output_bytes`); either -> `combine_error(too_large)`. A part bundle is
  fetched/unpacked with `split.max_chunk_output_bytes` as its bound. CSV header line <= 1 MiB.
- **I7 Built-in crash / could-not-start** (not a refusal, not timeout/oom) -> `internal_error`, retryable (another
  node may do better; bounded by `retry.max_attempts`). Timeout -> `deadline_exceeded`, OOM -> `oom` (not
  retried). Script: non-zero exit -> `combine_error(script_failed: exit N ...)`; env build / infra failures keep
  their own types and retry rules.
- **I8 Built-in process.** `SubprocessRuntime` instance owned by the executor (process tree, time limit = job
  `limits.timeout`, cancel/kill), the agent's `sys.executable`, `PYTHONPATH` = the agent's own package root,
  env = the workload allowlist; runs whatever runtimes the owner offers to user jobs (trusted code). Output
  streams go to the attempt's logs like any run.
- **I9 Upload deadline of a combine** counts from when this controller process first sees it UPLOADING (the
  job's COLLECTING arrow predates the combine).
- **I10 `job.output_digest`** in `JobDetail` (final attempt's, never a lane's) and `compute get` prefers it.
- **I11 `nondeterministic_chunk`**: hooked on `already_done` with a different, *verified* digest while
  `split.deterministic` (default) - one aggregated entry per code `{code, count, chunks[<=64], detail}` in
  `job.warnings`, written in the result transaction; `SplitStats.nondeterministic`; log
  `controller.split.nondeterministic_chunk`. G6 produces the duplicates; today a late result after expiry does.
