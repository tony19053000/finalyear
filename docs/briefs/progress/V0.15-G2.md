## Notes / design decisions taken here (for Lead review)
- **CLI runs the comparison in a child process** (`sys.executable -m meshforge.controller.ml.train compare`).
  The `cli-imports-common-and-sdk-only` contract forbids the CLI importing `meshforge.controller`; a child
  process with the same interpreter is the existing pattern (`compute fabric join` runs the agent binary).
  Still offline, no server (D353). Exit 2 without the extras: the CLI checks `find_spec` of pyarrow, numpy,
  sklearn, lightgbm, xgboost first; the child checks again (its own `missing_libraries`).
- **xgboost-cpu** on Linux and Windows (plain `xgboost` pulls `nvidia-nccl-cu13`, 216 MB, on Linux); plain
  `xgboost` only on macOS (no xgboost-cpu wheel there; no NCCL on macOS). Same `xgboost` module.
- **Watermark (D355) is wider than the brief's**: matched-run count + newest `(ended_at, decision_id)` **plus**
  the count and newest end of every ended attempt, feature version and the cap. A lane, a combine or a
  node-caused failure that ends after the lead lane changes Mode 3 rows / `node_failures` without touching
  the matched set; the brief's key alone would serve a stale dataset then.
- **`node_failures` window**: every node-caused end when the whole matched set was read; since the oldest read
  run when `ml_dataset_max_runs` truncated the read.
- **Calibration baseline per ML term**: factors fitted on that term's training rows only (key ladder, config
  and observation rules from `planner/calibration.py` - `term_observation` / `applied_factor` are new shared
  helpers, `match()` and `holdout_error()` now call them). `lane_stage` rows fit the `transfer` table the
  planner applies to a lane's stage; `chunk_rate` / `combine` are never scaled by the planner -> factor 1
  (= raw), exactly the live fallback.
- **Interval width** = full width `2q` (gate `<= ml_max_interval_log` = ln 2: the interval spans at most x2).
- **Content digest**: the report names the digest of the canonical re-encoding of the rows (= the G1 digest
  for a controller-written file), so a shuffled / re-written file with the same rows gives the same report.
- **Boosting prefix sharing**: LightGBM / XGBoost configs differing only in rounds are fitted once with the
  most rounds and predict with the first n (no row/column sampling -> identical trees; unit-tested).
- **Effective MALE** (model where usable, else calibration) is reported next to the model's MALE: the
  verdict is on the model (D351), the effective number is what G4's precedence would deliver.
- `ml_min_rows` / `ml_min_families` are `CompareSettings` fields + CLI flags (`--min-rows`, `--min-families`);
  the `[controller.planner]` settings keys belong to G3 (server-side training).
