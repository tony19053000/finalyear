### Deviations / decisions for the Lead
1. **Routes are `/v1/planner/eval-reports`** (every route is `/v1`; the brief's `/api/v1` is the same API).
2. **Oracle refusal = `400 invalid_input`**, not 422. That is the API's convention for any refused body (G3 deviation 3). Also refused by the manifest, `plan()`, `compute run --policy` and the `plan_decision.policy` CHECK.
3. **Vote ties with `unmeasured`:** D313 says ties go to the smallest config id. I added one rule: `unmeasured` wins a tie it is in, so a policy is never credited with a measured pick it made only half the time. Records with no pick (no feasible node) vote `unmeasured`.
4. **Mode 3 mapping compares the set of active lanes, sorted.** Campaign sets are stored sorted and plan lanes are fastest-first. A set with one active lane maps to that node's `local`/`mode1` config.
5. **Held-out filter is stricter than D316.** It also removes runs whose fingerprint matches one of the evaluated family's records (the same workload without a family, e.g. a user job). A refit with no factors plans uncalibrated (`source: none`).
6. **Each policy is judged on its own counted groups.** An `unmeasured` pick removes a group from that row only, so the D317 CI comparison (criterion 2) is not paired. The D319 gate is paired (only groups counted under both versions).
7. **D319 "held-out slice groups"** = the labelled groups, in the newest 20 campaigns holding the held-out jobs, that one of those jobs ran in. A skip writes its note into the **active** row's `reason` (as D319 says). A campaign too large for the label cap also counts as a skip. A label read failure fails the whole refresh (nothing written).
8. **Loader "DB and Parquet export — same rows":** the Parquet export holds no replays. `records_from_rows` takes DB or Parquet rows (unit-tested as identical), but replays always come from `plan_decision`. A file-only evaluator would need a replay export: follow-up.
9. **Record -> decision:** use the dispatched decision of the record's attempt; otherwise use the job's first dispatched decision (a split job's record is the combine row).
