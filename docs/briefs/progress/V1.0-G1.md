## Design notes / deviations
- **Restart-aware leak rules (D410 rules 3-4).** Chaos restarts processes, and a restarted process
  starts small: quiet-1 of the old process vs quiet-2 of the new one, or one fit over the sawtooth,
  would *hide* a leak. Series are cut into lifetimes by `(pid, create_time)`, each minus its own
  warm-up; the slope is a pooled within-lifetime fit; when no lifetime spans both quiet windows the
  growth compares first vs last third of the longest lifetime (`growth_basis` in the details).
  Unit tests: leak hidden by a restart caught; warm-up after restart not a leak; FD leak hidden by
  a restart in quiet-2 caught; pooled slope maths. -> Lead: record as a D410 clarification.
- **Dry-run chaos kinds:** kill_agent, kill_controller, reboot, net_down_short/long, netem (200 ms,
  no loss - the fault proxy has no loss), kill_job_tree, cancel_mode3 (REST, by chaos.py).
  Not in the dry run (lab only): restart_postgres (shared test container), revoke_rejoin (person),
  upgrade_reinstall (packages), **disk_fill**: the agent refuses work below a fixed 1 GiB free-disk
  floor (`agent/cas/store.py` DEFAULT_FREE_DISK_FLOOR_BYTES, not configurable), so a namespaced
  tmpfs agent would need > 1 GiB RAM each to be fillable (first attempt with 256 MiB tmpfs: every
  job failed disk_full - the floor working as designed).
- The dry run asserts rules 1, 2, 7, chaos, coverage = PASS; rules 3-6 are computed and printed but
  not asserted (their bounds are for 72 h; a 6 min quiet window right after start-up measures warm-up).

## Fix round 1 (reviewer REQUEST_CHANGES + tester T1-T3 on e3895183)
- **disk_fill = leave 512 MiB free** (`DISK_FILL_LEAVE_FREE_MIB`, half the agent's fixed 1 GiB
  floor) in both executors (`mf-chaos disk-fill`, `chaos_win.ps1`); param `leave_free_mib`
  replaces `fill_pct`. **Proof rule:** a `disk_fill` counts for D411 only when a job attempt on
  its laptop ended `disk_full` inside its window (`PROOF_FAILURES`; a refused attempt retried
  elsewhere = "deferred", counts too). Applied but unproven -> not counted, rule at best
  INCONCLUSIVE (`unproven`, `proof` in the details, shown in the Markdown report). Checklist A5b:
  the fill file must be on the agent CAS volume; L1's PostgreSQL data dir is usually there too.
- **Cleanup.** Root-owned wrapper `lab/mf-chaos` -> `/usr/local/sbin/mf-chaos KIND ARGS`
  (POSIX sh): every argument pattern-checked (fill file must end `/mf-chaos-fill.bin`, no `..`;
  pg paths under `/opt/meshforge/` + `/var/lib/meshforge/`; `.deb` root-owned, not group/world
  writable, in a root-owned folder), lasting faults detached as unit `mf-chaos-ID` with
  `trap '<undo>' EXIT INT TERM HUP` and an interruptible `sleep & wait`; `mf-chaos cleanup
  IFACE|- FILL|-` stops `mf-chaos-*` units, `nmcli networking on`, deletes a netem root qdisc,
  removes the fill file (idempotent). `lab/chaos.py cleanup (--dir|--targets) [--only]` runs it
  on every ssh/local laptop (Windows: prints the `chaos_win.ps1 -Cleanup` line; harness: skip);
  `chaos.py run` runs it at start/resume and on SIGINT/SIGTERM/SIGHUP (then exit 130).
  `chaos_win.ps1` cleans up at every start, `-Cleanup` = only that. Checklist A5 (install
  wrapper, sudoers = only the wrapper - no `sh`), B6/B7, C3 (abort), D4, G1-G3.
- **Template values** are pattern-checked (`SAFE_VALUE` = shlex's safe set) and `shlex.quote`d
  before `format` (`_fill`); an unknown placeholder is a `TemplateError`.
- **Leak rules:** each row reports `excluded_share` (samples cut as warm-up). The
  `longest_lifetime` fallback is `too_short` -> INCONCLUSIVE when the longest lifetime spans
  < 12 h x `min(1, hours/72)` (10 min at the 1 h dry run, 1 min at 0.1 h - so a compressed run
  still gets a comparison when its lifetimes are long relative to the run, and a 72 h run whose
  agent is restarted every few hours cannot pass memory/handles on a short lifetime). Memory is
  also INCONCLUSIVE when no growth comparison exists at all (was: could PASS on the slope alone).
- **T1** `Note.covers(host=None)` matches only `"*"` notes (an event on no known laptop - the
  job-level fallback - can no longer be explained by a note for another laptop). **T2**
  `_terminal_at` / `_committed` / `_job_failure_explained` skip non-object list entries. **T3**
  `notes.json` with non-object events or a non-list `events` -> `problems` entries, no traceback
  (the report's exit follows the verdict; a `notes.json` that is not JSON is still exit 1). The
  three strict xfail markers are removed (+1 case: `events` not a list).
