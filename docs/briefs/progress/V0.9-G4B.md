## Fix round 1 (reviewer REQUEST_CHANGES, 2026-10-18)

**Blocking race fixed (item 1).** `ActiveCondition.apply()` runs the controller's apply in its own task;
`finish()` cancels it **synchronously and once** (a second cancel would cut cleanup), and `_finish` waits for it
to end before reverting; `apply()` refuses (`stopped before it was applied`) once finishing began; a cancelled
apply is reported `verified = false` (`stopped while applying (<reason>)`), its caller gets `ConditionFailedError`
(stop_all) or `CancelledError` (its own cancel). `TcRunner.run` cancelled → kills `tc` and reaps it (survives a
second cancel) before re-raising, so a replace cannot land after the revert. The marker is written **on the loop**
(sync, small file) - a `to_thread` write could land after `remove` - and `remember()` is a no-op once finishing
began (B3). Marker removal happens only after apply ended and the revert succeeded.

**Installed bit (item 2).** `NetemController.marker_entry` carries `netem_installed: true` only from right before
`tc replace` (an `on_change` hook writes it). The sweep deletes netem only for entries with the bit;
`delete_netem` runs `tc qdisc show` first and deletes only a root qdisc that is a netem (never a non-netem root,
never a foreign netem - that one was refused by the pre-check before any bit was written). Tests that put
`{"netem": "eth9"}` markers by hand now add the bit (`test_v09_g4_agent_conditions.py`,
`test_v09_g4b_tester_r1_agent.py` hostile + idempotent sweep, `test_v09_g4_conditions_exec.py` restart sweep); the
exec test's expected `tc` call list gains the revert's `show` before `del`.

**Items 3-5.** `_kill_burners`: pid must be a non-bool int > 0, creation time a non-bool number; psutil errors,
`ValueError`, `OverflowError` suppressed; each marker entry swept in its own try (`_sweep_one`), a crashing entry
logged (`agent.conditions.sweep_entry_failed`) and removed. `prepare`: cache controller construction wrapped →
`condition_failed:cache: bad tree id (...)`. `condition_outcome`: `fillers_ahead` bool is not a count;
`dispatched_after_s` formatted only when a non-bool number, else `the run's dispatch time is not valid`.
