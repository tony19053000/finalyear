   execution-enabled agent's capability list gains one `bench-conditions:` tag.

   linked as runs (correct).
2. `controller/telemetry/record.py` `RecordSource.campaign` docstring: trivial — keep A's `condition` /
   `condition_measured` fields or drop them (see 3).
3. **Semantic, record.py `build_record`:** after the merge both lanes write the columns. A sets
   `condition = _bounded(source.condition, 128)` and `condition_measured = _finite_json(source.condition_measured)`
   from `RecordSource` (its recorder fills them from `identity["condition"]` / `identity["condition_measured"]`);
   B's `bench_identities` provides `condition` + `condition_facts` (no `condition_measured`), and B's block
   `if _HAS_CONDITION_COLUMNS:` then **overwrites** both keys with `condition_outcome(...)`. Result: values are
   B's (correct content), but **A's sanitisers are bypassed** — B's `measured` copies the agent's reported
   `measured` dict, so a NaN/inf there would make PostgreSQL refuse the row (recorder isolates it → lost record).

   `"condition": _bounded(condition.condition, CONDITION_CHARS)` and

   lines that fill them (single source of truth = `condition_outcome`). B's invalid-text fallback bound (64) can
   become `CONDITION_CHARS`. Then update the unit test `test_v09_g4_controller_conditions.py` (~line 320) that
   monkeypatches `_HAS_CONDITION_COLUMNS` / `COLUMN_NAMES`.
