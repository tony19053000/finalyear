## 0. The honest starting point

Most of what the roadmap calls "V0.14" already exists in some form, because V0.6 and V0.10 built a real cost-based
planner rather than a stub. V0.14 is therefore **not** a rewrite. It turns a planner that *predicts* into one that
*knows how wrong it is and gets measurably better* — and proves it with regret numbers, which V0.15 (ML) then has
to beat. The single most important new thing is **replay** (D292): without it, criteria 1 and 2 cannot be measured
honestly, and V0.15 has nothing to train or evaluate against.

## 2. Design decisions (Lead proposals)

| # | Decision | Why |
|---|---|---|
| D290 | **Scope = Local + Mode 1 + Mode 3** (ADR-0012). The candidate generator has a `RequestKind` switch; `AcceleratorRequest` returns "not supported in this build" with a typed reject, so V0.11+ plug in without touching callers. | Re-expansion stays cheap; nothing deferred is half-built. |
| D291 | **0.14.1 unified candidates** = one function `candidates(request, snapshot) -> list[Candidate]` replacing the two current paths (whole-job in `plan.py`, split in `split_plan.py`). `Candidate` = `{mode, node_set (ordered), plan_params}`; Local/Mode 1 have one node; "don't split" for a split job stays the one-lane Mode 3 path (D269) but is labelled `mode1`. Decisions and records keep their stored values. | One generator is what "unified planner" means; keeps D269 identical-code guarantee. |
| D292 | **Replayable decisions.** Every `plan_decision` stores a **versioned, bounded replay snapshot**: the `PlanRequest` and the planner-relevant parts of `ClusterSnapshot` (per node: scores, slots, free RAM/disk, cache holdings of the job's trees + env hash, fresh links used, history medians/rates the estimator read, reliability inputs) — JSON, `replay_version` 1, capped (e.g. 64 KiB; over-cap → `replay: null`, counted). `plan(replay.request, replay.snapshot, policy', now=replay.now)` is then pure and repeatable. Migration **0030**. | Regret of *other* policies needs what the planner saw, not what the cluster looks like today. Without it the evaluator would silently compare against a different world. |
| D293 | **Calibration (0.14.3)** = per-term multiplicative factors fitted from history: for each term `t` ∈ {transfer, env, compute, output, split overhead} and key (node, workload family when known, else node only, else global), factor = **median(actual / predicted)** over the last N matched (decision, outcome) pairs, **shrunk** toward 1 by `n / (n + k)` (k = 5), clamped to [0.2, 5]. Fitted by a pure function, stored as a versioned `planner_calibration` row (migration 0030), refreshed by a controller task (default every 30 min and on demand `compute planner calibrate`). Terms whose source is `measured` (e.g. queue 0, cached env 0) are not scaled. The decision stores the calibration version; explain shows `compute 12.0 s × 1.3 (calibrated, n=14)`. | Simple, robust to outliers, explainable at evaluation; a proper statistical model is V0.15's job. Shrinkage stops one odd run from swinging the planner. |
| D294 | **Pruning (0.14.2).** Keep fastest-first prefix sets (already O(N)); add: a node **dominated** on every term by an already-included node with free capacity is not a set extender; a link below `min_useful_bw` for the job's bytes makes the candidate infeasible (`link_infeasible`) before costing. **Budget:** decision latency p99 < 100 ms for 4 nodes and < 500 ms for 16 nodes (synthetic snapshots, measured in a benchmark test; criterion 3). | The roadmap's "set enumeration" is 2^N; prefix sets are the right approximation and already proven in V0.10. |
| D295 | **Objectives (0.14.5)** = `min_time` (default), `min_network` (minimise bytes moved; time breaks ties; still margin-tested), `prefer_local` (Local wins unless another candidate is faster by `prefer_local_margin` 0.25 risk-adjusted). Selected like policies: `POST placement.objective` > manifest `objective:` > `[controller.planner] default_objective`. The objective is a **ranking rule over the same estimates**, not a new estimator. | Objectives the user can understand; no weights to tune. |
| D296 | **Risk penalty (0.14.4).** Per node `p_fail` = Beta-smoothed rate of node-caused attempt ends (LOST, owner pre-emption, node-side infra failure — **not** job code failures) over the last 7 days, prior Beta(1, 19) (≈ 5 %). Mode 1/Local penalty = `p_fail × (T + retry_overhead)`; Mode 3 lane loss only re-runs leased chunks (D267), so penalty = `Σ_n p_fail(n) × (chunk_time_n + lease_release_s)`. Shown as its own `risk` term with source `history`/`assumed`. | Models what actually happens on failure in each mode; never blames a node for a user's crashing script. |
| D297 | **Offline evaluator (0.14.7)** `meshforge.planner_eval` (controller-side, pure core + Parquet/DB loader): input = campaign run records + labels + replay snapshots; for each **labelled group** and each policy (all rule policies, `cost_model` uncalibrated, `cost_model` calibrated, each objective) replay the decision and look up the measured median `total_ms` of the configuration it picks. **Regret** = picked median − best median (0 when the pick is in a `tie` set); groups labelled `insufficient` / `pending` are excluded and counted. A pick with no measured configuration (the policy chose something the campaign did not run) is **`unmeasured`**, reported, never counted as 0. Output: JSON + Markdown report (per family, per policy, mean regret with bootstrap 95 % CI, "% within 15 % of oracle"). CLI `compute planner eval --campaign … [--holdout family]`. | Exactly the criteria 1 and 2 numbers, computed the same way every time; honest about what was not measured. |
| D298 | **`oracle` policy** = evaluation only, never selectable for real jobs (API rejects it): picks the configuration with the best measured median for the group. It exists so reports have an explicit reference row. | ADR-0007 lists it; making it un-selectable keeps it from leaking into production. |
| D299 | **Held-out evaluation.** Calibration is fitted on campaigns/families **not** in the evaluation set (leave-one-family-out by default) — the evaluator refuses to report criterion 1 on data the calibration saw (flag `--allow-leak` for debugging, printed in the report). | Otherwise criterion 1 is measured on training data; V0.15 inherits the same discipline. |
| D300 | **Decision page (0.14.6).** Job detail "Plan" tab grows into: candidate table (mode, node set, each term predicted × factor, risk, total, rank, rejection reason), objective + policy + calibration version, **predicted vs actual** per term after the job ends, and the margin-test sentence ("split 3 nodes: 41 s vs best single 52 s, needs ≤ 46.8 s → split"). A new **Planner** page: latest evaluator report per campaign, calibration factors per node/term with n, regret per policy chart. `compute explain` prints the same fields. | Criterion 4: every decision explainable in UI and CLI — the same data in both. |
| D301 | **Calibration safety.** A new calibration version is only activated if, replayed on its own held-out slice, it does not raise mean regret by more than 5 % vs the active one; otherwise kept as `rejected` with the reason. Operators can pin a version or disable calibration (`[controller.planner] calibration = "auto" \| "off" \| <version>`). | A bad fit must never silently make the live planner worse. |
| D302 | **Limits & config** (`[controller.planner]`): `default_objective` min_time, `prefer_local_margin` 0.25, `calibration` auto, `calibration_window_runs` 200, `calibration_shrink_k` 5, `calibration_clamp` [0.2, 5], `calibration_refresh_s` 1800, `risk_window_days` 7, `risk_prior` [1, 19], `replay_max_bytes` 65 536, `decision_latency_budget_ms` 100. Validated in settings; documented in OPERATIONS. | Configuration over constants. |
| D303 | **New dependencies: none.** Bootstrap CIs and medians in-house (`meshforge.bench.stats` already has them). | Small footprint; V0.15 brings scikit-learn. |

## 4. Standing checklist (front-load every implementer brief)

Same as V0.10 §4, plus: the planner package stays pure (AST import test); every new number in explain carries its
source; a missing/unknown input is never held against a node; replay of a stored decision with the same
policy/objective/calibration must reproduce the stored choice **exactly** (property test over recorded decisions);
evaluator results are deterministic for the same inputs (byte-identical report).

## 5. Success criteria (calibrated proposal — roadmap's are marked *calibrate*)

1. On held-out families (D299), calibrated `cost_model` picks a configuration within **15 %** of the oracle's measured
   median in **≥ 80 %** of labelled groups. Groups `insufficient`/`unmeasured` reported, not counted.
2. Calibrated `cost_model` mean regret **lower than every rule policy**, with non-overlapping bootstrap 95 % CIs vs the
   best rule policy (or the report says "not separable" — no PASS on overlap).
3. Decision latency p99 **< 100 ms** for 4 nodes (and < 500 ms at 16 synthetic nodes).
4. Every decision explainable in the UI and `compute explain` with identical fields (contract test).

## 5a. Brief for **G1 — replay snapshot + unified candidate generator** (0.14.1, D290–D292; worktree)

**Goal:** every stored decision can be re-run purely and gives the same answer; one generator produces all candidates.

1. `planner/candidates.py`: `candidates(request, snapshot) -> list[Candidate]` (`Candidate` frozen: `mode` ∈
   local/mode1/mode3, ordered `node_set`, `plan_params`). Replace the separate whole-job path in `plan.py` and the
   singles/sets generation in `split_plan.py` with calls to it; costing, margin test and policies unchanged.
   `RequestKind.ACCELERATOR` → no candidates + typed reject `not_supported_in_build`. Stored candidate JSON, reject codes
   and decision fields must stay **byte-identical** for existing cases (golden tests over the current planner suites).
2. `planner/replay.py` (pure): `to_replay(request, snapshot, now) -> dict` and `from_replay(dict) -> (request, snapshot,
   now)`, `REPLAY_VERSION = 1`. Contains only what `plan()` reads (audit `plan.py`, `feasibility.py`, `estimator.py`,
   `split.py`, `split_plan.py`, `policies.py`; round-robin cursor and random seed included). Canonical JSON (sorted keys,
   finite floats, no NaN). Over `[controller.planner] replay_max_bytes` (65 536) → `None` + a counter/log; never fails
   a dispatch.
3. Migration **0030**: `plan_decision.replay JSONB NULL`, `replay_version SMALLINT NULL`, `objective TEXT NULL`,
   `calibration_version BIGINT NULL` (last two written as NULL / `"min_time"` for now — G2/G3 fill them). Written in the
   same savepoint as the row (D131 rule: a refused row is dropped alone).
4. `DispatchPlanner` (`jobs/planning.py`) and the bench shadow plan store the replay.
5. **Property test (the key acceptance):** for recorded decisions from the existing planner/component suites and seeded
   random snapshots (Local/M1/M3, pinned, waiting, failed, split too small, stale links), `plan(*from_replay(to_replay(..)),
   policy)` equals the original `Decision` field for field, for **every** policy. Plus a component test through a real
   dispatch tick: read the row back, replay, same chosen candidate.
6. Decision latency benchmark scaffold (`tests/unit/planner/test_v014_latency.py`, marked `perf`): 4 and 16 synthetic
   nodes, split and whole jobs, p99 printed; assertion < 100 ms (4 nodes) only.

Out of scope: calibration, risk, objectives ranking, evaluator, UI. Gates: ruff, format, `mypy src`, AST purity test,
`pytest_exit_guard.py -m unit`, planner + jobs component suites, migration test. Progress note
`docs/briefs/progress/V0.14-G1.md` with exit gates + Hand-off.

## 5b. Brief for **G2 — calibration fit + store + refresh task + safety** (0.14.3, D293, D301, D305–D308; worktree)

**Goal:** the planner's per-term predictions are multiplied by factors learned from what really happened, the factors are
versioned and explainable, and a bad fit can never go live.

1. **Matching (pure, `planner/calibration.py`).** Input: (stored decision → chosen candidate's predicted terms, with
   source) joined to the attempt's measured `attempt_phase` rows (non-`skipped` only) and its outcome. First audit and
   **document in the module docstring** the term → phase mapping (e.g. `transfer` ↔ staging, `env` ↔ env build,
   `compute` ↔ `run`, `output` ↔ upload, Mode 3 `chunk_overhead`/`combine` ↔ lane/combine data); a term with no honest
   phase is **not calibrated** (factor 1, reason `no_phase`). Only successful attempts whose decision chose the node
   that ran them; forced/pinned runs count (they measured something real); `measured`-source terms and terms with
   predicted < 0.05 s are skipped (D293).
2. **Fit (pure).** `fit(pairs, config) -> Calibration`: per term, per key with fallback **node+family → node → global**
   (family = workload fingerprint family when known); factor = median(actual/predicted) over the last
   `calibration_window_runs` (200) pairs of that key, shrunk `1 + (m − 1)·n/(n + k)` (k = 5), clamped [0.2, 5]. A key
   is used only when n ≥ 1; the fallback chain is recorded per factor (`key_level`). Deterministic: same pairs → same
   bytes (canonical JSON).
3. **Apply (pure, inside `plan()`).** `plan(..., calibration: Calibration | None = None)`. Each non-`measured` term's
   seconds × its factor (after the 1e9 cap rule, still capped); `EstimateTerm.detail` gains `calibration: {factor, n,
   key_level, version}`; the term's `source` is unchanged. `None` / `calibration = "off"` ⇒ bit-identical to today
   (the G1 golden corpus must stay byte-identical with no calibration). Margin test, policies and ranking see
   calibrated totals.
4. **Store (migration 0031).** `planner_calibration(version BIGSERIAL PK, created_at, status ∈
   active/rejected/superseded/pinned, factors JSONB, fit_inputs JSONB {pairs, window, k, clamp, held_out},
   holdout_error_new, holdout_error_active, reason TEXT NULL)`; at most one `active` (partial unique index). The
   dispatcher loads the active version once per tick (cached by version), passes it to `plan()`, and writes
   `plan_decision.calibration_version` (column from 0030) + the replay `calibration` block (D307).
5. **Safety (D301 via D306).** Activation rule exactly as D306; a rejected version is stored with `reason`. Config
   `[controller.planner] calibration = "auto" | "off" | <version>` (pin): `off` ⇒ None; a pinned version that does not
   exist ⇒ settings/startup error, never a silent fallback.
6. **Refresh.** Controller task every `calibration_refresh_s` (1800) + on demand: `compute planner calibrate` (fits,
   gates, prints the new/rejected version and the per-term table) and `compute planner calibration [--version N]`
   (shows factors with n and key level). Task failure logs and keeps the active version; never blocks dispatch. Auth
   follows the existing admin-CLI rules.
7. **Config (D302 subset):** `calibration`, `calibration_window_runs`, `calibration_shrink_k`, `calibration_clamp`,
   `calibration_refresh_s` — validated (clamp low < 1 < high, k > 0, window ≥ 1), documented in OPERATIONS.
8. **Tests.** Unit: fit on hand-built pairs (median, shrink, clamp, fallback chain, outliers, empty, all-measured),
   determinism, apply identity at factor 1 and with `None` (golden corpus byte-identical), replay with calibration
   reproduces the decision (extend G1's property test to random calibrations), safety accept/reject boundary (exactly
   ×1.05). Component (real PostgreSQL): migration 0031 up/down/up + `alembic check`, one-active invariant under two
   concurrent refreshes, a dispatch tick with an active calibration writes `calibration_version` and its replay
   reproduces; refresh task with too few pairs creates nothing (or an all-1 version — choose and document).

Out of scope: risk, objectives, pruning, evaluator/regret gate (G4), UI beyond the CLI. Gates: ruff, format, `mypy src`,
AST purity, `pytest_exit_guard.py -m unit`, planner + jobs + migration component suites, `tests/cluster/test_v010_mode3.py`.
Progress note `docs/briefs/progress/V0.14-G2.md` with exit gates + Hand-off.

## 5c. Brief for **G3 — risk term + objectives + `link_infeasible` + pruning + latency** (0.14.2, 0.14.4, 0.14.5, D294–D296, D305–D308; worktree)

**Goal:** the planner prices the chance a node fails, ranks by the user's objective, never costs hopeless links,
prunes dominated set extenders, and decides within the latency budget.

0. **G1 reviewer non-blocking items (do first, small):**
   - **N1** the dispatcher builds the replay every tick for every queued job — build it **only when the decision row is
     actually written**, and log the over-cap event once per (job, reason), not every tick.
   - **N2** `from_replay` must type-check int-or-None fields (and bool vs int) and raise `ReplayError` on a mismatch.
   - **N4** `to_replay` asserts `now` is timezone-aware (`ReplayError`/`ValueError`, never a naive timestamp stored).
1. **Reliability inputs (D296).** `NodeSnapshot.reliability: Reliability | None` = counts of node-caused attempt ends
   and total attempt ends in the last `risk_window_days` (7). **Node-caused** = `LOST`, `node_lost`,
   `gpu_session_lost`, `owner_preempted`, and infrastructure failures attributable to the node (`disk_full`,
   `env_error` from the node's builder, `transfer_error` where this node was the receiver) — **never** workload
   failures (crash, `oom` of the job's own limit, `timeout`, `cancelled`, `fenced`). Put the classification in one
   table with a test per error code (every `ErrorCode` member classified explicitly, so a new code fails the test).
   Snapshot builder fills it in one query per tick (no N+1); replay carries it (D307).
2. **Risk term (`planner/risk.py`, pure).** `p_fail = (a + failures)/(a + b + total)` with prior `risk_prior` [1, 19].
   Local/Mode 1: `risk = p_fail × (T + retry_overhead)` where T = the candidate's un-risked total and retry_overhead =
   queue+transfer+env of the best other feasible single (or T if none). Mode 3: `Σ_lanes p_fail(n) × (chunk_time_n +
   lease_release_s)` (D267). Added as `extra["risk"]` with source `history` (n > 0) or `assumed` (prior only) and
   `detail {p_fail, failures, total, window_days}`. Margin test uses risk-adjusted totals. Replays without a
   reliability block ⇒ no risk term (D307).
3. **Objectives (`planner/objectives.py`, D295).** `min_time` (default; today's ranking), `min_network` (rank by
   predicted bytes moved = trees not cached + items fetch + outputs; time breaks ties; split still needs the margin
   test), `prefer_local` (Local wins unless another candidate's risk-adjusted total ≤ Local × (1 − 0.25)). Resolution
   `POST placement.objective` > manifest `objective:` > `[controller.planner] default_objective`; unknown → 422 /
   manifest validation error. Written to `plan_decision.objective` and the replay; `reason_key` names the objective when
   it changed the pick. Only `cost_model` reads it; rule policies ignore it (documented).
4. **`link_infeasible` (D294).** New `RejectCode.LINK_INFEASIBLE` (dynamic, not static): a candidate whose required
   transfer uses a **fresh** measured link below `min_useful_bw` (new config, default 1 MB/s) for > `min_useful_bytes`
   (default 64 MiB) is rejected **before** costing. Stale or unmeasured links never reject (a missing input is never
   held against a node). Explain shows the link, bw and bytes.
5. **Pruning (0.14.2).** In `candidates.py`: a node that is **dominated** (every term ≥ and at least one > an
   already-included node with free capacity) is not a set extender; record pruned nodes in the decision (`pruned:
   [{node, by}]`) so explain can say why. Existing goldens: a decision may change only where pruning removed a
   strictly dominated set — list every changed golden in the hand-off with the reason.
