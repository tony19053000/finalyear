## 2. Design decisions the Lead must settle before spawning (write down, then brief)

| # | Decision | Recommendation | Record as |
|---|---|---|---|
| D1 | **Node identity material** (0.3.2): keypair type and file format, so V0.7 mTLS can reuse it | **Decided — [ADR-0013](../adr/0013-node-identity-storage.md) (Proposed).** ECDSA **P-256** (not Ed25519: grpcio's BoringSSL does not verify Ed25519 certificates by default, and the key must survive into V0.7 mTLS unchanged), PKCS#8 PEM via `cryptography`; `node_id` = ULID minted once, stored in `node.json` beside `node.key` with `session_epoch` and a key fingerprint cross-check; `0700/0600` on POSIX, `icacls` SID-restricted on Windows, partial identity is a fatal `IdentityError`; `meshforge-agent identity show|reset` | done: ADR-0013 · ARCHITECTURE §16 · ADR-0008 Updates |
| D2 | **Session epoch + fencing of stale streams** (carry-over from 0.1.5; `TODO(V0.3)` in `agent.proto`) | `Hello.session_epoch: uint64` (agent-monotonic, persisted with identity, +1 per process start) and `AgentMessage.session_id` in envelope field 3; controller keeps one live session per `node_id`, a `Hello` with a newer epoch **closes the older stream** (it was a zombie), an older epoch is rejected `FAILED_PRECONDITION`. Commands carry `session_id`; the agent drops commands for a session it no longer owns | **Decided — ADR-0002 Updates 2026-09-20** |
| D3 | **Liveness owner and clock** (0.3.7) | Controller-side lease timer per session using `loop.time()` (monotonic); heartbeat every `2 s`, `SUSPECT` after 1 missed (`> 2 s + jitter allowance 0.5 s`), `OFFLINE` at `3 × 2 s = 6 s` of silence. Both intervals are settings, defaults meet criterion 2 (≤ 8 s) with margin. gRPC keepalive **also** on (`grpc.keepalive_time_ms=10000`) so a dead TCP path is torn down without waiting on the app-level lease. State transitions are one pure function `next_state(state, event, now)` → unit-testable, matches §12.3 exactly (ENROLLING → ONLINE → SUSPECT ⇄ ONLINE → OFFLINE → ONLINE; DRAINING/REVOKED present as states, transitions stubbed with typed `NotImplemented` failure until V0.7) | comment in code + roadmap concept row; no ADR |
| D4 | **Reconnect policy** (0.3.8) | Full-jitter exponential backoff: `sleep = random(0, min(cap, base·2^n))`, `base 0.5 s`, `cap 15 s` (criterion 3: ≤ 15 s after controller restart — cap must not exceed it). Reset `n` after a stream that lived ≥ 30 s. Agent buffers un-acked reports (bounded ring, drop-oldest with a counter) and replays after `Reconcile`; `Reconcile.replay_from_sequence` fills the second `TODO(V0.3)` | **Decided — ADR-0002 Updates 2026-09-20** (adds gRPC keepalive 10 s / 5 s, replay ring 10 000, heartbeats never buffered) |
| D5 | **Resource snapshot storage** (0.3.11) | Live ring in memory per node (last 5 min at 2 s); `resource_snapshot` table receives a **1-min downsample** (mean/max per metric) written by the controller, not the agent. Retention setting, default 7 days; a periodic delete, not a partitioned table (Postgres partitions are premature at 4 nodes). `ResourceUpdate` is **change-threshold** + heartbeat piggyback: send when any metric moves > 5 % abs or ≥ 10 s elapsed | ADR-0014 if the team wants the retention/downsample policy to be a decision; otherwise ARCHITECTURE §19 sentence already covers it |
| D6 | **One process hosting FastAPI + gRPC** (0.3.6) | Yes, per ARCHITECTURE §3: one asyncio loop, `grpc.aio.server` + `uvicorn.Server(config).serve()` as two tasks under one supervisor with a shared `Fabric` object; graceful shutdown drains both. Ports: gRPC `47100`, REST `47110` (unassigned range, distinct from spike ports 472xx–473xx); both settings | code + `docs/ARCHITECTURE.md` §23 port table |
| D7 | **Where the controller's own agent runs** | The controller host is "also a normal node" (§3): run a normal `meshforge-agent` process there; the controller never embeds an agent | no doc change needed |
| D8 | **Windows service mechanism for 0.3.13** | Document **Task Scheduler** (`schtasks /create ... /sc onlogon`) first — no third-party binary; NSSM as the alternative if the task-scheduler run cannot survive logoff. ADR-0009 already commits to a native Windows agent | `docs/OPERATIONS.md` (new) or `lab/README.md` |

Also carry into the code from the 0.1.7 review row: `command_timeout` in `DatabaseSettings`; every `CheckConstraint(name=...)`; `updated_at` maintained by SQLAlchemy `onupdate` (rule "all writes via SQLAlchemy"); log `store.migrations.failed` with the revision.

## 4. Standing checklist to front-load into **every** V0.3 brief

Paste verbatim into each implementer prompt (this is what got S6 through review first time):

```
No confidently-wrong output. Before handing off, check each and say which apply:
1. Every failure path has a typed failure_type / exception and a test that triggers it for real
   (kill the process, close the socket, stop the container) — not a mock that raises.
2. Nothing is asserted from this machine's state (hostname, GPU present, driver version, IPs).
   Tests pass on a CPU-only Windows laptop after a plain `uv sync`.
3. Time: only loop.time()/monotonic for leases and backoff; wall clock only for timestamps.
   Unit tests inject the clock; no sleep() longer than 50 ms in unit tests.
4. Idempotency: every message handler tolerates duplicates and reordering across a reconnect
   (message_id dedupe, sequence gaps, stale session_id) — with a test for each.
5. Concurrency: one asyncio task owns each stream; shared state is behind one lock or a
   single-writer task; no "fire and forget" create_task without a reference and an exception
   handler.
6. Boundaries: controller/agent never import each other; src/ never imports lab/; proto changes
   regenerate deterministically (`uv run python scripts/gen_protos.py --check`).
7. Logs: structlog events carry node_id/session_id; no secrets, no key material, no full paths
   of user dirs.
8. Docs: settings documented where they are defined; any new port/dir added to ARCHITECTURE §23.
9. Report exact commands and exact pass counts; say explicitly what you did NOT run.
10. Do not start the next group's tasks; list what you noticed under Follow-ups.
```
