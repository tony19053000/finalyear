## 2. Design decisions (Lead proposals — team approves before G1)

| # | Decision | Why |
|---|---|---|
| D169 | **Repo + build.** `frontend/` = Vite + React 18 + TypeScript (strict), npm with committed `package-lock.json`, Node 22 LTS. `npm run build` writes to `src/meshforge/controller/web/dist/` (git-ignored; included in the wheel at packaging). Controller serves it with SPA fallback (any non-`/v1`, non-`/healthz` GET → `index.html`); if not built, `/` shows a plain "dashboard not built — run `make web`" page, never a 500. Dev: Vite dev server proxies `/v1` to a local controller. **Node is a build-time tool only**; nothing JS runs on the controller. | One process to deploy (CLAUDE.md §7: no premature services); the frontend cannot weaken the backend (brief §24). |
| D170 | **Browser auth.** `POST /v1/session` (name + password, same scrypt + D159 backoff) sets a **`HttpOnly; Secure; SameSite=Strict; Path=/v1` cookie** holding a new token kind `browser_session` (256-bit, stored hashed, 12 h idle / 7 d absolute, listed and revocable with the user's API tokens). Mutating requests with a cookie also need header `X-MeshForge-CSRF` equal to a non-HttpOnly companion cookie (double submit). API tokens never enter the browser. Logout deletes server-side. Open WebSockets re-check through the D157 path. | No token in `localStorage` (XSS → theft); SameSite + CSRF header closes cross-site writes; reuses ADR-0016 machinery. |
| D171 | **Typed client from OpenAPI.** `openapi-typescript` generates `frontend/src/api/schema.d.ts` from `/v1/openapi.json` (exported by a Python script, no running server needed); thin `fetch` wrapper + TanStack Query hooks by hand. A test fails if the committed schema differs from the exported one (drift gate). Every route gets explicit response models + error model in OpenAPI. | Backend change that breaks the UI fails CI, not at evaluation. |
| D172 | **One event stream.** `GET /v1/events/ws` (cookie or bearer) carries typed JSON events from an in-controller **event bus**: `node.status`, `node.metrics` (≤ 1 Hz per node), `job.state`, `attempt.state`, `alert`. Each event has a monotonic `seq`; on reconnect the client sends `since=seq`; if the bus ring (last 10 000 events) no longer has it, server says `resync` and the client refetches. The client **patches/invalidates TanStack Query caches**, never keeps a second store. Bounded per-client queue; slow client is dropped with close code, not allowed to grow memory. | One socket instead of N polls; resume-or-resync is simple and honest; ≤ 2 s (criterion 2) is measured end to end. |
| D173 | **Live metrics, no persistence.** Controller keeps a per-node in-memory ring of heartbeat samples (5 min) → `GET /v1/nodes/{id}/metrics?window=` for sparklines. Nothing written to PostgreSQL in V0.8; durable telemetry is V0.9's. | Avoids building telemetry twice; V0.9 replaces the source, not the UI. |
| D174 | **Lists scale.** Jobs list: server-side keyset paging (`created_at,id`), filters (state, owner, node, time), default 50. Criterion 2 tested at 4 nodes × 100 jobs **and** at 10 000 jobs for headroom; table rows virtualised over 200. | "100 jobs" is small; the design must not fall over at the next order of magnitude. |
| D175 | **Design system.** Tailwind with tokens as CSS variables (dark default; light theme from the same tokens — cheap, Q5), Radix primitives, own small component set (Button, Table, Badge/StatusDot, Card, Dialog, Tabs, Toast, CodeBlock/LogView, Sparkline). Fonts **self-hosted** (Inter, JetBrains Mono) — the fabric runs on an offline LAN, no CDN. Recharts for charts. One accent; status colours: online/ok, busy, degraded, offline/failed, unknown. Brief §24 "avoid" list is a review checklist item. | Infra-console look; works with no internet. |
| D176 | **"Every Mode 1 operation" (criterion 1) — the list.** Nodes: list, detail, revoke. Jobs: list, detail, **submit**, cancel, follow logs, download artifacts, view attempts, **plan explanation** (decision table from `explain`). Data: list/pin/delete. Secrets: list/set/delete (value write-only). Fabric: invites create (with **QR**)/list/revoke, API tokens, users (admin), whoami. Owner policy is **agent-local** (D142) → read-only in node detail. A parity test lists every CLI command and maps it to a UI route or an explicit "CLI-only" reason. | Makes criterion 1 checkable, not a feeling. |
| D177 | **Submit from the browser.** Folder picker (`webkitdirectory`) or zip → files hashed in a Web Worker → the **existing resumable CAS upload API** (`/v1/blobs`, `/have`) → same job submit endpoint the CLI uses. Same size/ignore rules as the CLI (`.meshforgeignore`), shared via one spec file + tests on both sides. | No second upload path; see Q2 if the team prefers CLI-only submit in V0.8. |
| D178 | **CLI polish (0.8.8).** Audit every command: one renderer; `--json` on every read command with a documented, versioned schema (snapshot tests); exit codes table (0 ok, 1 job failed, 2 usage, 3 auth, 4 not found, 5 unavailable); errors say *what / why / what to do*; `compute --install-completion` (typer) checked in bash/zsh/PowerShell; `NO_COLOR` and non-TTY respected. | Scripts and the team both depend on it. |
| D179 | **e2e = Playwright for Python (`pytest-playwright`).** Reuses the Python cluster harness fixtures directly (real controller + agents); Chromium in CI, Firefox in the 🧑 review. Every test fails on any console error or unhandled rejection; axe-core check on each page; keyboard-only flows for login, submit, cancel, revoke. | The harness is Python; a TS runner would need a second fixture layer. |
| D180 | **D168 N3 lands here.** `WRONG_NODE` (and other security refusals already audited) become `alert` events on the bus + an Alerts panel on Overview; the `audit` row stays the source of truth. | The dashboard is the operator's surface; V0.9 adds history/graphs. |
