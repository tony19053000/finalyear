## 0. The honest starting point

V0.14 gave us three things V0.15 cannot work without: **replay snapshots** on every decision (what the planner saw),
**calibration** (per-term median-ratio factors, the baseline ML must beat) and the **offline evaluator** (regret vs
oracle with bootstrap CIs, held-out families, the D306/D319 gates). So V0.15 is not "add a model". It is: learn
*where the analytical model is wrong*, prove it on held-out workloads, and never let a model make the live planner
worse.

Three hard truths shape this brief:

1. **Data volume is the real risk, not the algorithms.** The roadmap says "≥ several thousand runs across
   families". Today we have harness data only (≈ 130 records per 10-minute run on one machine); no lab campaign has
   run yet (0.9.10, 0.10.10, 0.14.8 are open). A 4-laptop overnight run of the V0.9 unattended runner (0.9.7) gives
   on the order of 1–3 thousand records. So: **build and test everything on harness data, judge the criteria only on
   lab data**, and make data collection an explicit 🧑 step (§6), not an assumption.
2. **With tens of labelled groups, "beats analytical with non-overlapping CIs" may simply not be provable.** The
   evaluator already says `not_separable` honestly. The brief keeps that honesty: a `not_separable` result is a
   reported outcome, not a pass, and prediction error (MAPE) is reported alongside so the report still says what ML
   achieved.
3. **The model must never be the planner.** ML corrects cost *terms*; the planner still enumerates, checks
   feasibility, applies the margin test and ranks. If the model is missing, uncertain or out of distribution, the term
   falls back to calibrated analytical — per term, per candidate, recorded.

## 2. Design decisions (Lead proposals)

| # | Decision | Why |
|---|---|---|
| D333 | **Dataset (0.15.1).** One row per matched (dispatched decision, `done` attempt) and per learnable term: Local/Mode 1 whole-job terms `transfer`↔`stage`, `env`↔`env`, `compute`↔`run`, `output`↔`collect`; Mode 3 per-lane `stage`/`env` and per-lane **chunk rate** (items/s per node from chunk records) and the job's `combine`. Built by a pure function from DB rows + replay; exported as a versioned Parquet dataset with a content digest. **Group key = workload fingerprint, family label = run record family** (null family = its own group). Rows whose replay is missing or unreadable are skipped and counted, never imputed. | The same matching V0.14 calibration uses, so ML and calibration are judged on identical pairs. |
| D334 | **Features (0.15.2) come from the replay snapshot, not from today's DB.** Per (candidate node, job): node hardware scores (CPU, memory bandwidth, GPU TFLOPS, VRAM — measured, not model names), live load (CPU %, free RAM, running attempts), cache state (missing bytes, env cached), link bandwidth/RTT used, job size features (input bytes, item count, declared resources), family one-hot only as an *optional* ablation feature, and the **analytical raw prediction and its `source`**. Feature schema is versioned (`feature_version`); unknown values stay missing (NaN), never 0. | Training on exactly what the planner saw at decision time removes train/serve skew — the most common way ML schedulers quietly fail. Hardware scores let the model generalise to a laptop it has not seen. |
| D335 | **Target = residual, not absolute time (0.15.3).** For each term, `y = ln(actual / analytical_raw)`. The ML-corrected prediction is `analytical_raw × exp(ŷ)`. A model that predicts 0 *is* the uncalibrated analytical model; calibration is the special case "ŷ = constant per key". Failure probability: **keep the D296 Beta risk term**; a failure classifier is trained only if the data holds ≥ 50 node-caused failures (otherwise reported as "not enough events"). | Residual learning needs far less data than predicting seconds from scratch, extrapolates safely (physics stays in the analytical part), and makes the fallback exact. Failures are rare on a healthy lab; pretending to learn them from a handful of events would be decoration. |
| D336 | **Planner integration (0.15.6).** The planner takes an optional `predictor: TermPredictor` (a pure protocol: batch of feature rows → `ŷ` + interval + `ood` flag). Implementation lives in `controller/ml/` (outside the AST-pinned planner package); the dispatcher builds it once per model version and passes it in. Precedence per term: **ML (in-distribution, interval narrow enough) → calibration factor → raw analytical**. Each term records `detail.ml {model_version, y_hat, interval, used: true/false, reason}` and keeps its `source`; `plan_decision` stores `ml_model_version`; the replay key gains `ml {version}` (optional, absent = no ML). Batch prediction for all candidates in one call; inside the 100 ms decision budget (criterion 3 of V0.14 stays enforced). | Keeps the planner pure and replayable; the fallback is per term, so one OOD node does not throw away the model for the rest. |
| D337 | **Model comparison (0.15.4).** Per term: ridge (on standardised features + missing indicators), decision tree, random forest, **LightGBM**, **XGBoost**, kNN; plus the two baselines **raw analytical** (ŷ = 0) and **V0.14 calibration**. Selection by **leave-one-family-out CV** (grouped by family, then fingerprint) on mean absolute log error (≈ symmetric MAPE); ties → simpler model. Fixed seeds, `deterministic=True`, fixed thread count → byte-identical model for the same dataset digest. Hyper-parameters from a small fixed grid (no unbounded search). | Compared, not assumed (ARCHITECTURE §18 table). Log error matches the residual target and does not explode on tiny times. |
| D338 | **Uncertainty + OOD (0.15.5).** Uncertainty = **split-conformal intervals** on the CV residuals (model-agnostic, distribution-free 90 % coverage); LightGBM quantile models are compared as an alternative in the report. OOD = feature outside the training range by > 10 % for any of the hardware/size features, **or** kNN distance in standardised space above the 99th percentile of training distances. ML is used for a term only if in-distribution **and** the interval width ≤ `ml_max_interval_log` (default ln 2 ≈ ×2). Coverage is checked on the held-out family (reported; < 80 % → model rejected). | Conformal intervals are honest without assuming normal errors and are cheap; a two-part OOD test catches both "new laptop" and "new job size". |
| D339 | **Registry + retraining (0.15.7).** Table `ml_model` (migration **0034**): `version` (content digest), `term`, `algorithm`, `feature_version`, `dataset_digest`, `params`, `metrics` (CV + held-out), `status` active/rejected/superseded/pinned, `reason`, `created_at`, artefact in the CAS blob store. **No pickle**: LightGBM text, XGBoost JSON, sklearn via a parameter dump re-built at load (ridge/kNN/tree/forest serialised as arrays). Scheduled retrain (`ml_retrain_s`, default daily, and `compute planner ml train`) runs in a worker process; **activation gate** = D306/D319 style on the D329 stratified slice: held-out log error ≤ active (or calibration) × 1.05 **and** regret check not worse **and** no family worse than fallback beyond tolerance (criterion 2). Config `[controller.planner] ml = "auto" | "off" | <version>`. | The calibration store pattern already works and is reviewed; reuse it. Loading pickled models from a DB is remote code execution by another name (CLAUDE.md §9). |
| D340 | **Dependencies:** controller extra `ml` = `scikit-learn`, `lightgbm`, `xgboost` (pinned, wheels on Linux + Windows). Agents never import them. The controller without the extra runs exactly as V0.14 (`ml` reported `unavailable`). | Small agent footprint; ML is a controller concern. |
| D341 | **Evaluation report (0.15.8).** The evaluator gains rows `cost_model:ml` (per objective) next to calibrated/uncalibrated; criterion 1 uses a **paired bootstrap CI of the regret difference** (ML − calibrated analytical) on held-out groups (PASS iff the CI upper < 0; `not_separable` if it spans 0; FAIL if lower > 0). Criterion 2: per family, ML mean regret ≤ fallback + `ml_family_tolerance` (5 percentage points). Plus per-term MAPE / log error, interval coverage, fallback rate (by reason), **ablations** (drop each feature group; ML vs calibration vs raw) and **permutation feature importance**. Deterministic, byte-identical for the same inputs. | Criterion 1 as a paired test is the statistically right comparison (same groups, two policies) and more powerful than comparing two independent CIs. |
| D342 | **Dashboard (0.15.9).** Planner page gains "Models": active version per term, status history with reasons, CV/held-out metrics, predicted-vs-actual scatter (log axes) per term, fallback rate. Plan tab shows the ML correction per term (`compute 12.0 s → 9.4 s (ML v3a1, ±18 %)` / `ML not used: out of distribution`). `compute explain` shows identical fields (contract fixture). | Explainability (V0.14 criterion 4) must survive ML. |
| D343 | **0.15.10 experiment (report only).** A direct classifier (features of the job + snapshot → which configuration wins) trained on the same labelled groups, evaluated with the same regret metric. Never wired into the planner. | Answers the obvious evaluation question "why not just classify?" with numbers. |
| D344 | **Roadmap change:** add 🧑 **0.15.11 lab data collection + validation**: an overnight unattended campaign on 4 laptops (all Mode 1 + Mode 3 families, ≥ 2 000 records), then train → evaluate with held-out families, criteria pasted. Criteria are judged only on this data. | The roadmap's V0.15 had no lab task, yet all 3 criteria need real data. |
| D345 | *(Lead, 2026-10-22, G1 open question 1.)* **ML learnability is not the calibration's `measured` rule.** A term is excluded as not learnable only if its prediction is **exact by construction** - a structural 0 s, not a time derived from a rate or history: `transfer` / `lane_stage` with `detail.missing_bytes == 0` (nothing moves) and `env` / `lane_env` with `detail.env_cached` true (`queue` is never a dataset term). Skip reason `exact_by_construction` (`ml/targets.exact_by_construction`, by term + detail, never by `source` alone). A transfer over a fresh probed link (`source = measured`: measured bandwidth, predicted time) **is learnable**; `source` stays a one-hot feature. The calibration's behaviour is unchanged. | On a probed LAN almost every real transfer is `measured`; excluding them threw away the transfer data the model most needs, and a measured input does not make the predicted time exact. |
| D346 | *(Lead, 2026-10-22, G1 open question 2.)* **The `combine` actual covers exactly what the combine term models.** `planner/split.py::_combine` = `t_o` (`chunk_overhead`: attempt start, stage, upload) + the other lanes' parts moved to the combine node (`parts_bytes / bw`, fetched in the combine's `stage` phase) -> actual = the combine attempt's **`stage + env + run`** (skipped = 0 s); its `collect` is the set's `output` term and is not counted. Not `split_combine_ms` (run phase only; misses the parts fetch). | Target and prediction must measure the same work, or the residual learns a definition mismatch instead of a modelling error. |
| D347 | *(Lead, 2026-10-22, G2 brief — approved, Q11–Q16.)* **Nested, grouped evaluation.** *Outer* loop = leave-one-family-out (G1 `splits.leave_one_family_out`): gives the honest held-out numbers per family and is **never** used to choose anything. *Inner* loop = `group_kfold(k=5)` by fingerprint on the outer training rows only: chooses the algorithm + hyper-parameters (D337) and gives the out-of-fold residuals for the conformal interval (D338). The shipped candidate per term = the selected config refit on **all** rows, its conformal quantile from all-row grouped out-of-fold residuals. | Choosing the model on the same families that report its score is the classic optimistic leak; with ~10–20 families it could turn a useless model into a "win". |
| D348 | **One model per term, with a data floor.** A term is trained only with ≥ `ml_min_rows` (default 200) rows **and** ≥ `ml_min_families` (default 3) families; otherwise the report says `insufficient_data` for that term and the planner keeps calibration (fallback). Term is not a feature of a shared model. | Terms have different physics (bytes/bandwidth vs items/rate); a shared model lets the big terms drown the small ones. The floor stops "trained" models on 12 rows. |
| D349 | **Missing values + preprocessing.** LightGBM/XGBoost take NaN natively. Ridge / kNN / sklearn tree / forest go through one shared, explicit preprocessing step fitted on the training fold only: median imputation + one missing-indicator column per feature that had any NaN + standardisation (ridge/kNN only). Implemented as plain numpy arrays (not a pickled sklearn `Pipeline`) so G3 can serialise it as arrays (D339). | Uniform, leak-free, and serialisable without pickle. |
| D350 | **Baselines inside the same folds.** `raw` = ŷ 0. `calibration` = the V0.14 factor refit **on the training fold only** with the calibration's own pure `fit` key ladder (global → node → node+family) and `CalibrationConfig` (factor = median ratio, same minimum counts) — reuse `planner/calibration.py`, never re-implement; if `fit` only takes `MatchedRun`, add a small shared helper that both call. A model counts as better only against **calibration**, not raw. | The live fallback is calibration; beating raw alone would be a hollow claim. |
| D351 | **Metrics (all on held-out rows, per term, per family + pooled):** MALE = mean |ŷ − y| (log error, primary), MAPE on seconds (`raw·e^ŷ` vs actual), median APE, conformal coverage at 90 % and median interval width, OOD rate, usable rate (in-distribution **and** width ≤ `ml_max_interval_log`). **Paired family bootstrap** of ΔMALE = model − calibration (resample families, 2 000 resamples, fixed seed; reuse the planner_eval bootstrap helper): verdict `better` (CI upper < 0) / `not_separable` / `worse` (CI lower > 0). Per-term **would-reject** flags: held-out coverage < 80 % (D338), any family MALE worse than calibration by > `ml_family_tolerance_log` (default 0.05). | These are prediction-error numbers; planner regret on decisions is G5 (D341). Reporting both keeps the report honest when regret is `not_separable`. |
| D352 | **Determinism.** Fixed seeds everywhere, `n_jobs = 1` / `num_threads = 1` / `nthread = 1`, LightGBM `deterministic=True, force_row_wise=True`, XGBoost `tree_method="hist"`, sorted inputs. Same dataset digest + same library versions → **byte-identical report** (JSON canonical: sorted keys, floats rounded to 6 significant digits). Library versions are written into the report. | Criterion 3 and reproducible experiments (CLAUDE.md §7). |
| D353 | **Where G2 runs.** G2 is an offline library + CLI over a Parquet file: `compute planner ml compare --dataset FILE [--terms …] [--algorithms …] [--out DIR]` (input from `compute planner ml dataset --out`), in-process, needs the `ml` extra on that machine (clear error + exit code 2 without it). No server-side training in G2 — the controller worker process and registry are G3. | Keeps G2 testable without a server; G3 reuses the same library. |
| D354 | **Failure events (D335/Q3).** G2 adds `node_failures` to the dataset counts (attempts `failed` for a node-caused reason — reuse the D296 risk-term failure query, never a new definition) and the report prints "failure classifier: not trained, N < 50 events" or "eligible". The classifier itself is built **only when a real dataset reaches 50** (new roadmap tech-debt item, not code written now). | Building and testing a classifier that real data cannot feed would be decoration; the count keeps the question answerable. |
| D355 | **Dataset route cache (G1 carry).** `GET /v1/planner/ml/dataset` caches the last built Parquet keyed by a cheap watermark (newest outcome `(finished_at, decision_id)` + matched-run count + `FEATURE_VERSION` + config cap) and builds under an `asyncio.Lock` (single flight); a second request during a build waits, then reuses. | The G1 route rebuilt the whole dataset per request — an easy admin-only DoS and slow. |
| D356 | *(Lead, 2026-10-22, G2 implementer open questions.)* (1) **CLI runs the comparison in a child process** (`python -m meshforge.controller.ml.train compare`) — accepted: the CLI import contract forbids importing the controller; still offline, no server. (2) **Coverage reject stays pooled** for the D338 < 80 % rule, and *(amended after tester r1 T1-D2)* **any family with ≥ 20 held-out rows and coverage < 70 % also sets `would_reject`** (per-family coverage always reported). (3) **One fixed LightGBM quantile config is enough** — it is a reported comparison, not what ships. (4) D355 cache key widened to every ended attempt's count + newest end — accepted (narrow key proven stale, mutation M11). | Lead answers so G2 can close without a team round; none changes an approved criterion. |
| D357 | *(Lead, 2026-10-22, G2 tester r1 T1-D1.)* **`better` needs a real, learned, practically meaningful win.** Verdict `better` only if **all** hold: (a) a learned algorithm (not raw/calibration) was selected in ≥ half of the outer folds and for the shipped all-rows candidate; (b) paired family-bootstrap CI upper of ΔMALE < −`ml_min_effect_log` (default 0.02 ≈ 2 %); (c) ≥ 5 families (fewer → `not_separable`, reason `too_few_families`). If no learned model ships the verdict is `no_learned_model`. Verdict reasons recorded. | Tester showed 15/48 pure-noise runs called `better` when `raw` was selected and 3–4 families made the bootstrap thin. A claim the report cannot defend must not be printed. |
| D358 | *(Lead, 2026-10-22, G3 draft — Q17.)* Models ship as an **`ml_model_set`** per training run (members per term, `algorithm = none` for terms with no learned model); one active set; pin/rollback by set version. | One version to pin, replay and roll back. |
| D359 | *(G3 draft — Q19.)* Serving needs numpy only (+ lightgbm/xgboost for those algorithms); tree/forest served by our numpy evaluator over exported node arrays; never sklearn, never unpickle. | Security baseline; smaller serve surface. |
| D360 | *(G3 draft — Q18.)* G3 gate = log error ≤ active × 1.05, coverage (D338/D356), per-family tolerance; the D339 regret part is wired in G5 through `TermPredictor` (`regret: pending_g4` until then). | Lets G3 ∥ G4. |

## 4. Standing checklist (front-load every implementer brief)

Same as V0.14 §4, plus: no pickle/joblib loading anywhere (grep test); every ML number carries its model version;
a missing feature is NaN, never 0; training is deterministic for a dataset digest (byte-identical artefact test);
the planner package still imports no ML library (AST test); controller without the `ml` extra passes the whole V0.14
suite unchanged; no evaluation row may use a model trained on its own held-out family (leak test, as D299/D316).

## 5. Success criteria (calibrated proposal)

1. On held-out families, `cost_model:ml` mean regret is **lower than calibrated analytical v2**: paired bootstrap 95 %
   CI of the difference entirely below 0 (`not_separable` reported honestly, not a pass). MAPE per term reported.
2. On **every** benchmark family, ML mean regret ≤ fallback (calibrated analytical) + **5 percentage points**.
3. Retraining automated (scheduled + CLI) and reproducible: the same dataset digest gives a byte-identical model
   version; a gate rejection is recorded with its reason.
4. (Kept from V0.14) decision latency p99 < 100 ms with ML on, 4 live nodes.

## 5a. Brief for **G1 — dataset builder + features + targets + export** (0.15.1–0.15.3, D333–D335; worktree; no migration)

**Goal:** a pure, deterministic, tested function that turns the fabric's recorded decisions and outcomes into a
versioned training dataset — the only input G2 will train on.

**Build:**
1. **Package `controller/ml/`** (new). Pure modules (stdlib + `numpy`/`pyarrow` only; **no** sklearn/lightgbm/xgboost in
   G1) + one I/O module. AST test pins the pure modules' imports (as `planner_eval`).
2. **`ml/schema.py`** — `FEATURE_VERSION = 1`, `DATASET_VERSION = 1`; the ordered feature list with type, unit, group
   (`hardware`, `load`, `cache`, `network`, `job_size`, `analytical`, `family`) — the groups are what G5 ablates. The
   term list (D333): whole-job `transfer|env|compute|output`; Mode 3 lane `stage|env`; Mode 3 `chunk_rate` (per lane,
   items/s) and `combine`. Each term's target phase mapping reuses `planner/calibration.py`'s term→phase map (import
   it; never copy).
3. **`ml/features.py`** (pure) — `features(replay, candidate_node, term) -> dict[str, float]` from the **replay
   snapshot** (D334): node hardware scores, load (CPU %, free RAM, running attempts), cache (missing bytes, env cached),
   link bw/RTT the estimator used, job size (input bytes, items, declared CPUs/RAM/GPU), the analytical **raw** term
   prediction and its `source` (one-hot), family (kept but flagged `family` group). Missing → `NaN`, never 0. Works on
   replay v1 and v2.
4. **`ml/targets.py`** (pure) — `y = ln(actual / raw)` per (run, term). Exclusions, each **counted by reason**:
   raw or actual ≤ 0 / non-finite, term `measured` (not learnable), raw < `MIN_PREDICTED_S` (calibration's 0.05 s),
   skipped phase, missing replay, unreadable replay. `chunk_rate`: actual = items / summed run time of that lane's
   chunks (from `chunk_record`), predicted = the planner's lane rate.
5. **`ml/dataset.py`** (pure) — `build(rows) -> Dataset` (rows sorted by `(finished_at, decision_id, attempt_id,
   term, node)`; columns: ids, `group` = fingerprint, `family`, `term`, features…, `y`, `raw_s`, `actual_s`); content
   **digest** = SHA-256 of the canonical Parquet bytes; `counts` (rows per term/family, skipped by reason).
   **Group split helpers** for G2: `leave_one_family_out(dataset)` and `group_kfold(dataset, k, seed)` that never put
   one fingerprint on both sides (property test).
6. **`ml/loader.py`** (I/O) — reads matched runs **through the same matching as calibration**
   (`CalibrationStore.matched_runs` or the shared query it uses — refactor to share, don't duplicate), their decisions'
   replays and `chunk_record` rows, bounded and streamed (no unbounded `fetchall`; cap configurable,
   `[controller.planner] ml_dataset_max_runs` default 50 000).
7. **Export + CLI:** `ml/export.py` writes the dataset as Parquet (one pyarrow version → byte-identical, as D222) +
   a JSON sidecar (`dataset_version`, `feature_version`, digest, counts, schema). Admin REST
   `GET /v1/planner/ml/dataset` (streams the Parquet; `?format=summary` → JSON sidecar only) and
   `compute planner ml dataset [--out PATH] [--summary]`. OpenAPI + frontend schema regenerated if the API changes the
   contract (no UI in G1).
8. **Docs:** ARCHITECTURE §18 amendment (dataset, features, targets as built), OPERATIONS short section, CLI.md.

**Tests (all required):** unit — every feature on replay v1/v2 fixtures and the golden replay corpus; NaN-not-0 for
each missing input; each exclusion reason; `chunk_rate` arithmetic; deterministic digest (same rows in any input order →
same bytes); group-split property test (no fingerprint leak; LOFO holds out exactly one family); AST purity. Component
(real PG) — real dispatches through the planner → `done` attempts → dataset rows equal hand-computed `y` for each term,
incl. one Mode 3 job (lane + chunk_rate + combine); a decision without replay is skipped and counted; API == CLI ==
function output. **Mutation checks** (≥ 6, listed in the progress note): NaN→0, ln ratio inverted, a skip reason
dropped, group leak in the splitter, unsorted rows, measured term not excluded.

**Gates:** ruff check + format --check, `mypy src`, `pytest_exit_guard.py` on `tests/unit/ml` + `tests/unit/planner`
+ `tests/unit/controller`, component: new files + every `test_v014_*`; frontend typecheck/lint/check:api if the API
changed. The Lead runs full unit, cluster and the rest.

**Out of scope:** training, models, registry, planner changes (G2–G4). Progress note
`docs/briefs/progress/V0.15-G1.md`, commit after every step (`wip:` allowed). Hand-off: what changed, deviations,
gate results with exit codes.

## 5b. Brief for **G2 — training/comparison library + conformal + OOD + offline report** (0.15.4, 0.15.5, D337, D338, D340, D347–D355; worktree; no migration)

> **Status: APPROVED 2026-10-22** (Q11–Q16 as recommended).

**Goal:** given a G1 dataset file, decide **per term** whether any learned model predicts the residual better than
the V0.14 calibration on families it has never seen — with honest intervals and an OOD test — and write a
deterministic report. Nothing here touches the live planner (G4) or stores models (G3).

**Build:**
0. **G1 carry items first:** (a) D355 dataset route cache + single-flight lock (+ test: two concurrent requests → one
   build; a new matched run → rebuild); (b) D354 `node_failures` in dataset counts + sidecar.
1. **Dependencies (D340, Q16):** new extra `ml` = `numpy`, `scikit-learn`, `lightgbm`, `xgboost` (or `xgboost-cpu`),
   pinned with upper bounds; `uv lock`; record wheel sizes + the Linux/Windows wheel check in the progress note;
   mypy overrides for untyped libs. **Agent and plain controller installs unchanged** (test: import
   `meshforge.controller` and run the V0.14 planner tests in an env without the extra — or a monkeypatched import
   failure if a second env is too costly; say which). import-linter contract: `sklearn|lightgbm|xgboost` importable
   only from `meshforge.controller.ml.train` (new subpackage); the planner AST purity test still passes.
2. **`ml/train/prep.py`** — D349 preprocessing as arrays (fit on train → `Prep{medians, indicator_cols, mean, std}`
   → `transform`). Feature columns = `schema` order; `family` group **excluded by default** (`--with-family` ablation
   flag only).
3. **`ml/train/algorithms.py`** — one small adapter per algorithm (`ridge`, `tree`, `forest`, `knn`, `lightgbm`,
   `xgboost`) with a **fixed grid of ≤ 4 configs each** (listed in the module, e.g. ridge α ∈ {0.1, 1, 10};
   LightGBM leaves ∈ {7, 15}, n_estimators ∈ {200, 400}, lr 0.05, min_child_samples 20) + `raw` and `calibration`
   baselines (D350) behind the same `fit(X, y, rows) / predict(X, rows)` protocol. Simplicity order for ties:
   raw < calibration < ridge < knn < tree < forest < lightgbm < xgboost. D352 determinism settings.
4. **`ml/train/select.py`** — inner grouped 5-fold per (term, outer fold): mean MALE ± SE per config; pick by
   the **one-standard-error rule** (simplest config within 1 SE of the best). If the pick is `raw`/`calibration`,
   the term has "no learned model" — a valid, reported outcome.
5. **`ml/train/conformal.py`** — split-conformal: q = the ⌈(n+1)(1−α)⌉-th smallest |out-of-fold residual|, α 0.1;
   interval ŷ ± q (log space). Plus LightGBM quantile (0.05/0.95) as the compared alternative — coverage and width
   reported side by side; conformal is what ships (D338).
6. **`ml/train/ood.py`** — D338 two-part test fitted on training rows: (a) range test on the `hardware` and
   `job_size` feature groups (outside [min − 10 % span, max + 10 % span]); (b) kNN (k = 5) mean distance in the
   standardised space > 99th percentile of training leave-one-out distances. NaN features are ignored by (a) and
   imputed by (b). Returns `ood: bool, reason`.
7. **`ml/train/compare.py`** — the D347 nested loop per term (with the D348 floor) → `TermResult` (selected config,
   inner scores, outer per-family + pooled D351 metrics, paired bootstrap verdict vs calibration, would-reject
   flags, quantile-vs-conformal, top-10 permutation importances of the selected model on held-out rows — full
   ablations are G5). Report = canonical JSON + a short Markdown summary; header = dataset digest,
   `dataset_version`, `feature_version`, seeds, library versions, wall time **excluded** from the JSON bytes.
8. **CLI (D353):** `compute planner ml compare --dataset FILE [--terms a,b] [--algorithms …] [--with-family]
   [--out DIR]` → `report.json`, `report.md`; prints the per-term table (term, rows, families, selected, held-out
   MALE model vs calibration, verdict, coverage, usable %). Exit 2 without the `ml` extra or on a dataset whose
   `dataset_version`/`feature_version` this code does not know.
9. **Docs:** ARCHITECTURE §18 (training/selection/conformal/OOD as built), OPERATIONS (how to run a comparison,
   install the extra), CLI.md, roadmap tech-debt line for the failure classifier (D354).

**Tests (all required):**
- **Synthetic truth datasets** (fixture builder writing real G1-schema Parquet):
  (i) residual = a known function of load + hardware features + noise → a learned model must be selected and
  `better` than calibration on held-out families;
  (ii) residual = pure noise around a per-node constant → selection must pick `calibration` (or a learned model
  must be `not_separable`), **never** `better`;
  (iii) a held-out family whose job sizes lie far outside training → OOD rate high, usable rate low.
- Leakage: the outer test family never appears in any inner fold, prep fit, conformal residuals, OOD fit or
  calibration-baseline fit (instrumented property test over random datasets).
- Conformal coverage on (i) within 90 % ± 5 on a large synthetic set; quantile alternative reported.
- D348 floor → `insufficient_data`; empty dataset; one family; all-NaN feature column; constant `y`.
- Determinism: the same file twice → byte-identical `report.json`; rows shuffled before writing → identical.
- No pickle/joblib anywhere under `ml/` (grep test, §4); planner AST purity unchanged; import contract.
- CLI: missing extra (monkeypatched) → exit 2 with a clear message; unknown dataset version → exit 2.
- Component: real PG → G1 dataset build → compare runs end to end on harness-shaped data (small, fast); route cache
  single-flight with two concurrent clients.
- **Mutation checks (≥ 6, in the progress note):** outer family leaks into inner folds; conformal uses in-sample
  residuals; calibration baseline fit on all rows; 1-SE rule replaced by argmin; NaN imputed with 0; OOD range
  margin ignored.

**Performance bound:** compare on a 20 000-row synthetic dataset (8 terms, 15 families) finishes in < 15 min single
thread on Laptop 1; a harness-sized dataset in < 2 min. Record actual times. `--terms/--algorithms` exist to cut it.

**Gates:** ruff check + format --check, `mypy src`, lint-imports, `pytest_exit_guard.py` on `tests/unit/ml` +
`tests/unit/planner` + `tests/unit/cli`, component: new files + `test_v015_g1_*`; frontend check:api if the route's
OpenAPI changed. The Lead runs full unit + cluster.

**Out of scope:** model registry/artefact storage, scheduled retrain, activation gate (G3); planner use of models
(G4); regret rows, ablations, dashboard (G5); failure classifier (D354). Progress note
`docs/briefs/progress/V0.15-G2.md`, commit after every step (`wip:` allowed). Hand-off: what changed, deviations,
gate results with exit codes, timings, wheel sizes.


## 5c. Brief for **G3 — model registry + artefacts + scheduled retrain + activation gate** (0.15.7, D339, D358–D361; worktree; migration **0034**) ∥ G4

> **Status: APPROVED 2026-10-22** (Q17–Q20 as recommended).

**Goal:** turn a G2 comparison into a **stored, versioned, reproducible model per term** that the controller can load
without pickle, retrain on a schedule, and activate only through a gate. Nothing here changes a plan (G4 does).

**Build:**
0. **G2 tech-debt carry (STATUS):** `compute planner ml compare` gets `--timeout S` (default 3600; timeout → exit 1,
   one-line message, child killed); conformal rank in integer-safe form (`ceil((n+1)(1-α) - 1e-9)`) + test at
   α ∈ {0.05, 0.1, 0.2}, n ∈ [1, 2000]; D355 watermark gains `max(run_record.updated_at)` (or the label table's
   count + max) so a relabel rebuilds — test; report.md states "baseline folds count as Δ = 0" and importance shows
   the number of folds it came from.
1. **Migration 0034 `ml_model`** (D339 columns) + `ml_model_set` (**D358**): one row per *training run* = the set of
   per-term models that ship together (`set_version` = digest of the sorted member versions + feature_version),
   status `active | rejected | superseded | pinned`, `reason`, `gate` JSON, `dataset_digest`, `created_at`. At most one
   `active` set (partial unique index). Terms whose selection was `raw`/`calibration` are recorded as members with
   `algorithm = "none"` (no artefact) so the set says *why* a term has no model. Store models in
   `controller/store/models.py` style of `planner_calibration`.
2. **`ml/artefact.py` — no-pickle formats (D339, §4):** LightGBM `model_to_string()`, XGBoost `save_raw("json")`,
   ridge = coef + intercept arrays, tree/forest = sklearn `tree_` node arrays (`children_left/right`, `feature`,
   `threshold`, `value`) evaluated by **our own numpy predictor** (no sklearn needed at serve time), kNN = the
   standardised training matrix + y. Plus the D349 `Prep` arrays, the conformal `q`, the OOD fit (ranges, kNN
   reference matrix, threshold), `feature_version`, column order. Container = canonical JSON + raw arrays as
   little-endian `.npy`-free base64 blocks (no `np.load(allow_pickle)`), in the CAS blob store keyed by sha256;
   `version` = that digest. **Determinism test:** same dataset file → byte-identical artefact + same version
   (in a fresh process, `PYTHONHASHSEED` varied).
3. **`ml/serve.py` — `LoadedModel`** (**D359**): loads an artefact into a predictor that needs **numpy only** for
   ridge/tree/forest/kNN and `lightgbm`/`xgboost` only for those two (import-linter: serving may import
   `lightgbm`/`xgboost` from `ml.serve` only; never `sklearn`). Round-trip test: for every algorithm, the loaded
   model's predictions equal the in-memory trained model's to 1e-9 on a held-out matrix. A corrupt / truncated /
   wrong-`feature_version` artefact → typed `ArtefactError`, never a crash (fuzz test).
4. **`ml/train/fit.py` — `train_set(dataset) → TrainResult`**: reuses G2 `select` on all rows per term (the
   shipped-candidate path of D347, unchanged), fits conformal + OOD, builds artefacts. No new statistics.
5. **Activation gate (D339 + D360):** a new set is activated only if, on the D329 stratified held-out slice of the
   *current* dataset (models refit on the remaining rows): per term, held-out MALE ≤ active-set MALE × 1.05 (or ≤
   calibration MALE when nothing is active); coverage ≥ 80 % pooled and the D356 per-family rule; **no family
   worse than calibration by > `ml_family_tolerance`** (criterion 2, log-error proxy). The **regret part** of the
   D339 gate needs the G4 predictor inside the planner → **D360 (Q18): G3 records `regret: "pending_g4"` in the
   gate JSON; G5 wires the D319 regret check through `TermPredictor`** once both groups are merged. Rejections
   stored with reason; `--force` is never offered (pin is the override).
6. **Retrain task (D361):** `controller/ml_retrain_task.py` modelled on `planner_calibration_task.py` — interval
   `[controller.planner] ml_retrain_s` (default 86 400), skips when the D355 watermark is unchanged since the last
   set (`no_new_runs`), runs training in a **child process** (`python -m meshforge.controller.ml.train fit`, the G2
   pattern) with a timeout and `nice`, single-flight (advisory lock), never on the event loop. Controller without
   the `ml` extra: task logs one `ml_unavailable` line at start and never runs.
7. **Config + CLI:** `[controller.planner] ml = "auto" | "off" | "<set_version>"` (parse like calibration
   `parse_mode`; a pinned *rejected* set refused at startup like D306). CLI: `compute planner ml train [--wait]`
   (triggers the task via API), `compute planner ml models [--json]` (sets, members, status, reason, metrics),
   `compute planner ml pin|unpin <set_version>` (admin). API routes under `/api/v1/planner/ml/…`, OpenAPI
   regenerated, `check:api` green; UI parity entries (G5 builds the page — mark `CliOnly` with reason for now).
8. **Docs:** ARCHITECTURE §18 (registry, formats, gate, retrain), OPERATIONS (retrain, pin, rollback), CLI.md,
   THREAT_MODEL (why no pickle; artefact integrity = CAS digest).

**Tests:** migration up/down; one-active invariant under two concurrent activations (PG); gate accept / reject per
rule (synthetic datasets from G2 fixtures: better → active; noise → rejected `not_better`; one bad family → rejected
`family_tolerance`); retrain skip on unchanged watermark; pin of rejected set refused; restart keeps the active set;
grep test: no `pickle|joblib|allow_pickle=True|torch.load` under `src/`; serve imports no sklearn (import contract +
subprocess import check); controller without `ml` extra boots and runs the V0.14 planner suites unchanged.
**Mutation checks (≥ 5):** gate compares against itself; artefact omits Prep; version not content-derived; watermark
ignored; rejected set loadable.

**Out of scope:** using the model in plans (G4); regret part of the gate (G5, D360); Models page (G5).

## 5d. Brief for **G4 — planner integration: `TermPredictor`, precedence, decision/replay fields, latency** (0.15.6, D336, D362–D365; worktree; no migration unless Q21) ∥ G3

> **Status: APPROVED 2026-10-22** (Q21–Q23 as recommended; Q21 = JSON, no migration).

**Goal:** when a model is available, the planner uses it per term with the D336 precedence, records exactly what it
did, stays pure and replayable, and stays inside the 100 ms budget. G4 builds against a **stub predictor** and the
G2 in-memory models, so it does not wait for G3's registry; the two meet in G5.

**Build:**
0. **G1 carry (D362):** `features()` takes the **pre-calibration** analytical term (`raw_s` before
   `calibrate_estimate`) — training rows already use pre-calibration `raw_s` (G1 targets); assert it. **Replay-vs-live
   parity test:** plan live with a snapshot, store the replay, rebuild features with `features_from_replay` → equal
   bit for bit (NaN-aware) for every candidate and term, Mode 1 and Mode 3 (lane + combine terms).
1. **`planner/predictor.py` — the protocol (pure, no numpy in the planner):** `TermPredictor.predict(rows:
   Sequence[TermQuery]) -> Sequence[TermPrediction]`, where `TermQuery = (term, node_id, features: tuple[float, …])`
   and `TermPrediction = (y_hat, lo, hi, ood: bool, reason: str | None, model_version: str)`; plus
   `predictor_version`. The planner never imports `controller.ml` (AST test unchanged); feature building is done by
   a callable injected with the predictor (`FeatureFn`), so `planner` stays pure.
2. **Precedence (D336), per term, per candidate:** ML used iff a model exists for the term **and** not OOD **and**
   `hi − lo ≤ ml_max_interval_log` → term = `raw_s · e^ŷ`, `source` unchanged, `detail.ml = {model_version, y_hat,
   lo, hi, used: true}`; else calibration factor (V0.14) else raw, with `detail.ml.used = false, reason ∈
   {no_model, ood, interval_too_wide, exact_by_construction, predictor_error}`. `exact_by_construction` terms (D345)
   never call the model. **D363:** a predictor exception or timeout (> `ml_predict_budget_ms`, default 20) → whole
   decision falls back to calibration with reason `predictor_error`, logged once per minute; the plan never fails
   because of ML.
3. **Batching:** one `predict` call per decision covering all feasible candidates × terms (Mode 1) and all lane /
   combine terms (Mode 3 `split.py` / `split_plan.py`). Split planning that sizes chunks from term costs uses the
   ML-corrected costs (same precedence) — test that a model that halves `lane_compute` on node B moves chunk share to
   B.
4. **Records:** `plan_decision.ml_model_version` (**Q21:** new nullable column → migration 0035 after G3's 0034, or
   store it inside the existing decision JSON + replay only — Lead recommends the JSON, no migration); replay key gains
   `ml: {version}` (absent = no ML; `REPLAY_VERSION` stays 2, field optional — **D364**). Replay with ML re-runs
   with the **same** model version if loadable, else reports `ml_model_unavailable` (never silently re-plans with
   calibration and claims a match). `compute explain` / decision JSON show the per-term ML line (contract fixture
   updated; UI rendering is G5).
5. **Wiring:** `server.py` builds a `ModelSource` (G3's loader when merged; in G4 an `InMemoryPredictor` from a G2
   `train_set` result or a test stub) and passes `predictor=` to the dispatcher like `calibration=`. `ml = "off"` →
   predictor `None` → identical decisions to V0.14 (byte-identical decision JSON test on the V0.14 fixtures).
6. **Latency (criterion 4, D365):** decision p99 < 100 ms with ML on, 4 live nodes, Mode 1 and Mode 3, LightGBM
   400 trees + kNN OOD on 20 000 reference rows (worst realistic); measured in the V0.14 latency test harness;
   record numbers. If kNN OOD is the bottleneck, cap the reference set (deterministic sample, documented).

**Tests:** precedence table (every reason path); OOD node gets calibration while in-distribution nodes use ML in
the same decision; `ml=off` byte-identical to V0.14; predictor exception/timeout → `predictor_error` fallback;
replay with ML reproduces; replay with missing model → `ml_model_unavailable`; parity test (step 0); split share
moves with an ML correction; AST purity; latency. **Mutation checks (≥ 5):** calibrated raw_s fed to features;
OOD ignored; width check ignored; exact-by-construction term predicted; fallback skips calibration straight to raw.

**Out of scope:** registry/retrain (G3); regret evaluation rows, Models page, UI (G5).
