## 2. Design decisions (settled by the Lead before spawning)

| # | Decision | Why |
|---|---|---|
| D79 | **CAS stores whole files** named `sha256:<hex>` at `cas/sha256/<aa>/<bb>/<hex>`, written `*.part` → fsync → rename, files made read-only. One module `common/cas.py` used by controller and agent (no imports of each other). | Whole-file blobs keep dedupe/materialisation trivial; chunking is a *transfer* concern (D80), not a storage one. |
| D80 | **Chunks are transfer units, not stored objects:** files > `chunk_size` (default 8 MiB, setting) carry a list of per-chunk SHA-256 in the tree manifest. Transfers use HTTP `Range` per chunk, verify each chunk, assemble into `*.part`, verify the whole digest, rename. Resume = keep a sidecar `*.part.chunks` bitmap. | Resumable + parallel with verification per chunk and no second object namespace. |
| D81 | **Tree manifest** = canonical JSON `{"v":1,"entries":[{"path","sha256","size","exec","chunks"?}]}`, entries sorted by POSIX path bytes, no timestamps/owners. `tree_id = sha256(canonical bytes)`; the manifest itself is stored as a blob. Built with the bundle module's ignore rules and path checks (shared helper, not copied). Max entries / max path length / max total size are settings with tests (max and max+1). | Deterministic id across OSes; 0 bytes on resubmit (criterion 1). |
| D82 | **Have/need upload:** `POST /v1/blobs/have` `{digests:[…]}` → `{missing:[…]}` (bounded list); client uploads only missing files; large files upload in parts (`PUT /v1/blobs/{digest}/parts/{i}` then `POST …/complete`) so an interrupted upload resumes. Then the job is submitted with `tree_id`. Existing bundle path kept only for outputs. | Criterion 1 and 3 on the upload side. |
| D83 | **Job spec references `tree_id`** (migration `0009`: `job.tree_id`, nullable `bundle_digest` kept for old rows). `ExecutionSpec` gains `string tree_id = 15` and `repeated BlobSource sources = 16` (G1 adds `BlobSource{url, token, node_id}`; in wave 1 only the controller is listed). | One proto edit, in one lane, numbers fixed here. |
| D84 | **Agent materialisation:** fetch missing blobs into the agent CAS, then **copy** (reflink where the FS supports it, never hardlink) into the workdir, hashing while copying. | A hardlink would let a job poison the cache; copying is cheap next to the transfer and gives verify-on-read for free. |
| D85 | **Env hash** = `sha256(canonical{runtime_kind, base image digest or interpreter version, python version, normalized requirements bytes, platform tag})`. Requirements normalisation: strip comments/blank lines, sort, no network resolution (V0.5 hashes *what the user wrote*; a lockfile, if present, is hashed as is). | Same input → same env everywhere; reproducible and cheap to compute. |
| D86 | **Environment builder (agent):** Docker → `docker build`-free path: run the existing setup container with `uv pip install --target /env` then `docker commit` to image `meshforge-env:<hash>` labelled; **venv runtime** → `uv venv` + `uv pip install` into `envs/<hash>/` built in `envs/<hash>.building/` then renamed; read-only to jobs. One build per hash per node at a time (file lock); a failed build leaves nothing behind and is `env_error`. | Warm start ≤ 3 s (criterion 5); never build twice. |
| D87 | **Base images** `python-cpu` and `cuda-pytorch` pinned **by digest** in one settings table; the agent refuses an unpinned base. `meshforge-agent prepare` (local, wave 1) pre-pulls them and builds nothing else; `compute node prepare` (controller-driven) is wave 2. | Lab laptops can be prepared offline-friendly before a run. |
| D88 | **Peer blob server (wave 2):** a small HTTP server in the agent serving its CAS (GET + Range only, read-only), bound to the LAN interface on a configured port. Tokens: the controller generates an **Ed25519 signing key** at first start (private file, 0600), sends the public key in `HelloAck`; tokens are signed `{tree_id or digests, requester node_id, holder node_id, exp}` (≤ 10 min). V0.7 mTLS layers on top without changing the token. | Peers verify without calling the controller; forward-compatible with ADR-0008. |
| D89 | **Source choice (wave 2):** the controller lists every ONLINE holder + itself; the agent downloads chunks **work-stealing across all sources in parallel** (bounded per source), so faster sources take more chunks; failed/slow sources are dropped for that transfer. | Criterion 6 falls out of the mechanism instead of a guessed ranking. |
| D90 | **Cache reports (wave 2):** `CacheReport` = delta `{added, removed}` of blob digests + env hashes + image ids, bounded per message; a full snapshot is sent after Hello (paged). Controller table `cache_location(node_id, kind, key, size, last_seen)`. | Planner input for V0.6 `cache_affinity`. |
| D91 | **GC (wave 2):** per-node quotas (CAS bytes, envs bytes); LRU by last-use recorded in a small SQLite index (stdlib `sqlite3`) next to the CAS; items in use by a running attempt and pinned items (base images, registered datasets) are never evicted. Controller CAS gets the same policy with blobs referenced by non-terminal jobs pinned. | Bounded disk on personal laptops. |
| D92 | **Named inputs (wave 2):** `compute data push <name> <dir>` → tree; `named_input(name, version, tree_id, pinned)`; manifest `inputs: [{ref: name@version-or-hash, mount: path}]` materialised read-only under the workdir. | Datasets/models registered once. |
| D93 | **Transfer telemetry (wave 2):** per attempt and per blob: bytes, source node, duration, cache hit/miss — sent with AttemptStatus phase timings, persisted in `transfer_event`. | Feeds V0.9 telemetry and V0.15 ML features. |
| D94 | **V0.4 debt carried here (G3):** UPLOADING backstop (bounded upload deadline → `output_error`), log-file GC for terminal jobs (retention setting), log gaps persisted across a controller restart. | Tracked in D78 / STATUS. |
| D95 | **Fetch tokens across a controller restart (stabilisation, 2026-10-01; Lead decision).** Tokens stay in memory only (never persisted). On Reconcile the controller sends `RefreshFetchToken` (ControllerMessage payload 18: new download-only token, same scope, current `blob_url`/`blob_port`) for each held `ASSIGNED`/`STAGING` attempt with no live token in this process; the agent retries a staging fetch that met a refused token (waits for the refresh) or an unreachable controller (backoff), resuming verified tree chunks, until `[agent.execution] staging_retry_s` (60 s) → `transfer_error`. Upload grants are not refreshed (uploads across a restart stay `output_error`). | A controller restart while an attempt stages failed the job `transfer_error` (found by `test_g4_tester_r1_controller_restart` under load); job-level retries only arrive in V0.6. |
| D96 | **Wave 2 regrouping (Lead, 2026-10-04).** 0.5.5 (cache reports + location index) moves **into G4** and 0.5.10 (transfer telemetry) moves **to G5**. | Peer fetch (0.5.3) cannot list holders without the location index, so G4 needs 0.5.5. Telemetry only ships numbers the G4 fetcher already counts per source (`FetchStats.sources`), so it fits the G5 reporting/persistence work. |
| D97 | **Peer blob server = asyncio streams + `h11`** (no new framework; `h11` made explicit in the `agent` extra by the Lead). `GET`/`HEAD` on `/v1/blobs/{hex}` only, single `Range: bytes=a-b`; anything else → 405/416/400. Bounds: header bytes 16 KiB, idle/read timeout, max concurrent connections and per-connection requests (settings). Response head **and** body written with one coalesced write per buffer (`TCP_NODELAY` on), and the body comes from `loop.sendfile` where available. Binds `[agent.peer] bind` (default: off until set; refuses a wildcard bind unless `allow_any_bind`), default port **47120**. | uvicorn/fastapi is a controller-only dependency; a GET+Range-only surface is small enough to own, and owning the writes fixes the ~40 ms delayed-ACK stall measured on the controller path. |
| D98 | **Peer tokens (implements D88).** The controller keeps an Ed25519 key `<data dir>/controller/peer_signing.key` (0600, created at first start, refuses loose perms like `fabric.token`); public key in `HelloAck.peer_token_key = 8` (raw 32 bytes). Token = `base64url(canonical JSON {v:1, tree, req, hold, att, exp}) + "." + base64url(sig)`; `exp` ≤ 600 s after issue (wall clock, 30 s skew allowance). The holder checks the signature with the key from its *current* session, `hold == its node_id`, `exp`, and that the digest is `tree` itself or a member of the tree it holds (the manifest blob is read from its own CAS; no manifest → 404). Not persisted, never logged. Tokens are refreshed exactly like D95 (the refresh carries the new peer sources too). | Peers verify without calling the controller; the key persists, so a controller restart does not invalidate peer tokens. |
| D99 | **Where a peer is.** `Hello.peer_endpoint = 10` (`host:port` the agent serves on, empty = no peer server). The controller accepts it only if the host equals the address it sees the session coming from (or the setting `[controller] trust_peer_endpoints = true` for NAT'd lab setups) and the port is 1–65535. Shown in REST node detail. | Stops a node advertising another host's address as its own. |
| D100 | **Which peers are listed (implements D89/D90).** Cache reports carry kinds `blob`, `tree`, `env`, `image`; an agent reports `tree <tree_id>` only once **every** member blob and the manifest are in its CAS (after a successful materialisation or a later full check), and withdraws it as soon as any member is evicted. At dispatch the controller lists the controller + up to `[controller.jobs] max_peer_sources` (4) ONLINE nodes holding `tree <tree_id>` with a peer endpoint, never the target node itself, ordered by most recent `last_seen`. | Bounded query (one row per holder), no per-blob joins; a holder that lost a blob just 404s and is dropped for that blob. |
| D101 | **Cache report protocol.** `CacheReport{ uint64 seq = 1; bool snapshot = 2; bool snapshot_last = 3; repeated CacheItem added = 4; repeated CacheItem removed = 5; }`, `CacheItem{ Kind kind = 1; string key = 2; uint64 size = 3; }`, ≤ 1024 items per message. After every accepted Hello the agent sends a paged snapshot (`snapshot=true`, last page `snapshot_last`), then deltas; the controller replaces the node's rows on the first snapshot page of a new session and applies deltas only after `snapshot_last` (earlier deltas are buffered or dropped → resnapshot). Uses the reliable report path (acked, replayed). Migration **`0011`** `cache_location(node_id, kind, key, size, last_seen, PK(node_id, kind, key))` + index on `(kind, key)`; rows of a node deleted when it is removed. | Idempotent across reconnects (D-list checklist 4); a lost delta heals at the next Hello. |
