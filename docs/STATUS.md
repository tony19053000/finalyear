Until it lands, **anything reading liveness must use `connected` / `sample_age_s`, never `state` alone** — including V0.14's planner and any V0.15 label.

## Known Bugs
- 🔴 **`pytest -m unit` exits 139 (SIGSEGV) after a fully green summary** (found 2026-09-24, pre-existing — reproduced with *and* without that session's changes). `3214 passed, 2 skipped, 2 xfailed`, then `Fatal Python error: Segmentation fault` in a native thread with `<no Python frame>`: a C-level crash at interpreter shutdown. Each of `tests/unit/{cli,common,agent,controller}` exits **0** alone; only the whole `tests/unit` set crashes, and the top-level files are the ones importing grpc/protobuf — **prime suspect `grpcio`'s C core**, not yet proven. **This will make the first GitHub Actions `unit` job red no matter how many tests pass, so it blocks closing V0.1 (0.1.4, 0.1.10).** Raised as its own task. Lesson for every future round: **a green summary is not a green run — check the exit code**; `pytest-timeout` cannot see this and neither did three agent rounds.
- ⚠️ **A test that logs a large exception can wedge the whole suite.** structlog's *default* processor chain renders a rich traceback at a cost superlinear in the message length (~1.9 s at 20 K chars, minutes at 200 K) and the spin **holds the GIL**, so `--timeout` never fires and it looks like a stall with no failing test. Fixed structurally on 2026-09-24: `tests/conftest.py` now has a **function-scoped** autouse fixture applying `configure_logging` (function-scoped because `tests/unit/common/test_common_logging*.py` legitimately call `structlog.reset_defaults()`, which repairs away a session-scoped call). Do not make it session-scoped again.
- No bugs open in the lab suites (S2's two red tests from 2026-09-19 were fixed in the S2 rounds). DEFECT-0.1.8-01 (test Postgres container leaked on Ctrl-C) fixed: layered cleanup (atexit + finally, SIGINT-deferring shield, labelled containers, namespace-safe stale sweep, Ryuk).
- Fixed 2026-09-20: `test_udp_flood_of_garbage_is_dropped_not_amplified` flaked once under full-suite load — a single 540-datagram burst (~1 KiB skb `truesize` each) can overflow the server's 212 KiB default UDP receive buffer while its thread is descheduled, so the kernel dropped datagrams before the server counted them. The test now sends paced bursts of ≤ 50, each acknowledged by the `udp_dropped` counter, and still asserts the exact count and that nothing is echoed.
- Watch: `test_sigkill_during_pg_settings_leaks_no_container` failed once (1 of 8 runs, right after a heavy run) — likely the 20 s Ryuk reap window under load; not reproduced in 7 further runs. If it recurs in CI, widen the deadline or rely on the next-run sweep assertion.
